## 运行

需要 Node 22+ 和 pnpm。只有删除测试视频后重新生成时才需要 PATH 上可用的 `bash` 和 `ffmpeg`。

```bash
cd prototypes/frontend-v1
pnpm install --frozen-lockfile
pnpm dev          # http://localhost:6120（监听 0.0.0.0，局域网可访问）
```

`pnpm build` 会先做类型检查再打包。测试视频 `src/media/test-clip.mp4` 是用 ffmpeg 生成的 60 秒测试图（H.264 + AAC，faststart），与简中、简英、繁中、繁英四条字幕 VTT 一起提交（繁体由简体经 OpenCC 转出，双语是中文行下接英文行）；同一时间线的 1080p/720p/480p 清晰度档位 `test-clip.<档位>.mp4` 也一起提交。任一文件缺失时 `pnpm dev`/`pnpm build` 会先调用 `pnpm gen:media` 全部重新生成。所有单集和电影都播放同一段测试片段。

剧集与电影资料已缓存进 `src/data/tmdb.json`，随仓库提交、开箱即用。要重新从 TMDB 拉取（例如新增作品或更新资料）时，先在环境变量里设置 `TMDB_API_KEY`（key 只留在本机，不提交进仓库），再运行 `node scripts/fetch-tmdb.mjs`。

## 非播放页单集剧照

`/title/:slug` 的按季选集列表使用 TMDB 季页面中的单集剧照，按作品 TMDB ID、季号、集号与 `public/assets/stills/star-trek/manifest.json` 匹配。`Episode.still` 可为空；缺图或加载失败都保留相同尺寸的中性占位，不用作品或季海报代替。播放页及其选集列表保持不变，播放器时间轴预览图仍在需求范围外。

- 图片放在原有虚线边框内、标题左侧，手机 80×45，`sm` 起 112×63。标题和简介继续截断，观看状态与进度在窄屏换行，标记已看按钮始终独立可用。
- 本地图片统一为 240×135 WebP、质量 55；输入取 TMDB 未裁切的 `w300` 图片，等比缩放并补边，4:3 画面不拉伸、不裁切。浏览器只加载本地 WebP，不向 TMDB 发图片请求。
- 图片是辅助辨认的装饰，使用空 `alt`、`loading="lazy"`、`decoding="async"`；固定尺寸在加载前后不变。素材来源与每集来源页保存在 manifest 中，详细说明见 [`../../public/assets/stills/star-trek/README.md`](../../public/assets/stills/star-trek/README.md)。

已生成的图片随仓库提供，启动原型无需采集。重建素材需 `curl.exe`、支持 `libwebp` 的 FFmpeg，以及已连接的 Kimi WebBridge 浏览器扩展；在同一 `WEBBRIDGE_SESSION` 会话中先打开任意 TMDB 页面，不需要 TMDB API key。在原型目录运行：

```bash
node scripts/fetch-episode-stills.mjs --all       # 采集来源、下载、压缩并写 manifest
node scripts/fetch-episode-stills.mjs --collect   # 只采集来源，写本地缓存
node scripts/fetch-episode-stills.mjs --compress  # 使用来源缓存下载、压缩并写 manifest
```

原图与 `sources.json` 只保存在 Git 忽略的 `assets-raw/episode-stills/`。采集连接可用 `WEBBRIDGE_URL`、`WEBBRIDGE_SESSION` 指定，详情见素材 README。剧照仅延续原型素材展示用途，不代表取得了再分发许可。

`pnpm test` 运行 Node 测试，验证逐集索引、来源记录、本地 WebP 文件与尺寸、目录匹配和空图回退、装饰图片与占位的渲染，以及采集脚本缓存复用的边界行为。它不启动 HTTP 服务，也不连接 TMDB。已通过 Kimi WebBridge 验证 1440×1000 桌面和 360×800 手机布局、切季、已看状态切换及图片加载失败占位；截图见 [桌面](screenshots/episode-stills-desktop.png)、[手机](screenshots/episode-stills-mobile.png)、[手机观看进度](screenshots/va-tng-s3-mobile.png)。

- 切换身份场景：访客、新成员（空数据）、成员 `picard_fan`（有观看记录、收藏、片单）、管理员 `station_keeper`。
- 直接跳到各个页面和状态，例如过期邀请码、缺中文简介的电影、播放页评论区。
- 切换访客首页和星图的候选方案（会先切到访客场景）。线上构建在访客身份下打开 `/?landing=…`、`/?chart=…` 切换，同样在本标签页内保留。

数据全部在内存里，刷新就重置（只有所选场景会保留在 sessionStorage）。人物都是虚构的。

- 整条打破内容列的深色舞台，顶栏在舞台上方变透明；用当前作品的海报模糊成背景光。

  - 当前这一部：海报装进四角加亮的线框，旁边是作品、这一集、简介、直角进度条和继续播放。手机上海报缩小、和标题并排，不再隐藏，因为刻度尺上没有缩略图。

## 访客页（登录前）

要回答的问题：没登录的人打开站点，除了登录框还应该看到什么，同时不泄露片库。访客页一律不放海报，不列作品，不显示片库统计；访客也打不开搜索（搜索会列出全部作品）。

> 已确认的 v1 范围：访客首页 `/`、关于页 `/about` 及登录、注册、恢复入口公开；片库、搜索、成员记录、媒体和讨论仍仅向成员开放。正式版须按需求文档第 6.5 节在服务端校验权限，不能以原型的模拟身份代替。

`/` 对访客显示落地页，对成员显示原来的影院首页。比较过星图、登舰指南、站长来信三个方案后选定星图，另两个方案连同底部的切换条已经删掉：

- 整页是一张线稿图纸，跟随站点主题，默认浅色。顶部斜纹带下面是图头（Stellar cartography / Fig. 01），然后是占满整列宽的星图和一条很薄的标题栏，再往下是和其他候选相同的说明（加入三步、成员可以做什么、守则、常见问题）。星图用和全站一样的细 hairline 画 4×2 的星区网格，次级网格是点线，四条边框上是向内的刻度尺（次级网格线处长刻度，其间短刻度）；星点按印刷星图的星等画成 4 种大小，最亮的带圈；中立区画成一条和全站分隔带相同的斜纹带，Nimbus III 在带内、Romulus 在带外；星云画成测绘图式的点线等高线。正中是 Sol，瞄准样式照电影星图：一对红色 LCARS 方括号，括号竖边嵌着青色块，外侧各有一根青色立柱；网格的两条中线换成青色横线和绿色竖线的十字准线，在瞄准框外断开；Sol 在四条边框刻度尺上的位置用红色短条标出。星系 5 个，都避开了文字、编号、准线和刻度，位置只是装饰，不是考据。标题栏分三格，分隔线接着星图的竖线：站名加一句介绍和关于页链接、成员登录（通行密钥按钮和密码登录链接）、邀请码注册（输入框，提交后带着码进入注册页）。LCARS 风格只用在星图内部：Antonio 窄体（OFL）标注、黄色括号的星系标记和红青两色的瞄准框；星图外面一律用站点原有的 Noto Sans SC 和 Geist Mono，只在标题栏编号上留了一点 LCARS 配色。

## 公开看板（待确认）

> 需求文档尚未包含公开看板。版式已选定仪表盘；是否公开、公开哪些数字待开发者确认。已定的约束：数据全部来自 Cloudflare API，不在自己的数据库里记录统计，所以只展示 31 天以内的数据，也没有人工维护的事件记录。所有数字都是虚构的：每小时的数据由该小时的时间戳生成，刷新后历史不变；每分钟速率在相邻两个小时的均值之间插值再加波动，同样由分钟时间戳生成。

`/status` 成员和访客都能打开，没有导航入口。页面只用站点自己的组件和颜色：面板、斜纹分隔带、Geist Mono 数字、ToggleGroup 分段切换和直角进度条；曲线是单色细线，系列之间靠粗细和虚线区分；绘图区不画网格线，改铺一层点阵（16px 间距，站点 `dot-grid` 的两倍，避免看起来像一层灰色底纹），向四边淡出，坐标标签所在的边距不铺。

数据写法偏工程化，中英文按职责取舍：指标名和面板名用中文（“R2 下行流量”“调用结果”），解释性的句子和标签不上页面（分区标题不带副标题，占比列表每行只有名称、占比条和百分比），原因记在本节；技术记号保留英文，包括单位、小写分位 `p50/p95/p99`、时间窗 `24h` / `1m`、聚合方式 `sum / 1h`、时区 `UTC+8`、产品与 API 原名（Workers、`clientDisconnected`、`GetObject`、Class A/B）。数量保留 3 位有效数字，用 K / M（`185K`、`1.03M`）。

版式用宽列。24h / 7d / 30d 切换驱动所有序列，24 小时按小时汇总，7 天和 30 天按北京时间自然日汇总（当天不完整）。顶部 8 个数字只显示读数：R2 下行流量、每分钟下行速率、下行峰值（范围内每小时平均速率的最大值）、请求数、错误率、接口延迟 P95、CPU 时间 P99、D1 查询；上行只在媒体同步时才有量，放在 R2 面板的传输量里。下面是 R2 下行流量、最近 1 小时的每分钟下行速率、接口延迟 P50/P95/P99；再按产品分面板：Workers（每时段请求、CPU 时间、调用结果）、R2（操作类型、传输量）、D1（读写查询、查询耗时、读写行数、数据库大小），然后是最近 5 次部署和边缘节点、状态码。图表在宽屏加高（下行流量 320px、半宽图 240px），手机上保持 240px 和 192px，避免接近方形。

图表用 [bklit](https://bklit.com/)（shadcn 注册表 `@bklit`，见 `components.json`），源码装在 `src/components/charts/`，依赖 visx 和 motion。它的 `--chart-*` 变量在 `globals.css` 里映射到站点的 foreground / muted / border 等令牌，所以保持单色并跟随主题，不另设 `.dark` 值。系统开启“减少动态效果”时，图表入场动画、每分钟刷新时的曲线过渡和状态点闪烁都会关掉。

bklit 的部分文件按站点约定改过，重新执行 `shadcn add` 会覆盖：`chart-formatters.ts`（北京时间、`MM-DD` / `HH:mm`）、`chart-loading-label.tsx`（改为引用 `@/components/ui/shimmering-text`）。CLI 每次 `add` 还会往 `globals.css` 注入一组英文默认色和写错的 `var(----chart-*)`，需要删掉。

数据对应的 Cloudflare GraphQL Analytics 数据集：

| 看板数据 | 数据集与字段 | 状态 |
| --- | --- | --- |
| 请求数、错误数、调用结果、CPU 时间 P50/P99 | `workersInvocationsAdaptive`：`sum.requests/errors`、`quantiles.cpuTimeP50/P99`、维度 `status` | 文档已核对 |
| 接口延迟（墙钟时间）分位 | 同上，墙钟时间分位的字段名 | 未核对，接入时需 introspection |
| R2 下行 / 上行流量 | `r2BandwidthUsageAdaptiveGroups`：`bytesDownload`、`bytesUpload`，最细按分钟分组，不计 100 KiB 以下的传输 | 文档已核对 |
| R2 操作类型、A/B 类 | `r2OperationsAdaptiveGroups`：按 `actionType` 汇总 `requests` | 文档已核对 |
| D1 读写查询、行数、查询耗时 | `d1AnalyticsAdaptiveGroups`：`readQueries`、`writeQueries`、行数、`queryBatchTimeMs` 分位 | 文档已核对 |
| 数据库大小 | `d1StorageAdaptiveGroups`：`databaseSizeBytes` | 文档已核对 |
| 部署记录 | Workers 版本与部署 API | 未核对 |
| 边缘节点、状态码 | zone 级 HTTP 请求分析 | 未核对 |

以上数据集按账户查询，所有套餐至少保留 31 天；每 5 分钟最多 300 次查询，最近几分钟有汇总延迟。单次查询能覆盖的时长按数据集而定，账户的实际保留期和单次时长用 GraphQL 的 `settings` 节点（`notOlderThan`、`maxDuration`）查，超出单次时长时后端分段查询。公开页面不能每次访问都调用 API，服务端需要一层短时响应缓存（Workers Cache API），过期即丢弃，不算存储统计。

每分钟下行速率：用 `r2BandwidthUsageAdaptiveGroups` 按 `datetimeMinute` 取最近 1 小时的 `bytesDownload`，舍掉最近 3 分钟（汇总未完成），缺失的分钟补 0，换算成 Mbps。这一组单独缓存约 60 秒；页面每分钟拉一次，标签页隐藏时暂停，回到前台立即刷新，标出“数据截至 HH:mm UTC+8”。它不是逐秒实时值，比真实情况晚约 3 分钟。Worker 经绑定读取 R2 的流量是否计入这个数据集还未核对；若不计入，这个速率和 R2 下行流量都要改用其他来源（例如 zone 级 HTTP 分析的响应字节，同样未核对）。

刻意不展示：R2 存储量和对象数（`r2StorageAdaptiveGroups` 可读，但会透露片库规模，访客也能打开这个页面）、对象名和存储桶名。

已知问题：bklit 图表的数值只能用指针悬停查看，没有键盘逐点浏览。原型打包成单个约 2.4 MB 的脚本，正式迁移时应按路由拆分。

迁移到正式工程时的差异和适配要点见 [docs/prototype-diff-20261018.md](../../docs/prototype-diff-20261018.md)。

## 维护模式、欢迎页与片库报表（待确认）

> 需求文档尚未包含这三项，是否采用待开发者确认；采用前先在需求文档补充行为与验收。数据均为虚构。

- **维护模式**：站长在 `/admin/backups` 顶部的“维护模式”面板开启，可填预计恢复时间（北京时间，可留空）和给成员的说明，开启前二次确认。开启后，站长以外的所有人（成员、其他管理员、访客）访问任何路由都只看到维护页：顶栏只留站标和主题切换，正文是“503 · 维护中”、说明、开始与预计恢复时间和刷新按钮。只有 `/login` 保持可用，站长退出或会话过期后仍能登回来结束维护；其他人登录后照样只看到维护页，注册、找回密码等其余登录类页面也被替换。原型的登录总是以成员身份进入，站长身份用控制台切换。站长每页顶部有提醒横幅，链接回备份页结束维护。原型把开关存在 sessionStorage，切换身份场景后仍保留，便于以其他身份查看；原型控制台也有开关。正式版应在 Worker 入口统一拦截页面、接口和媒体凭证签发，返回 503 与 `Retry-After`；登录页和登录接口除外，但只有站长的会话能越过拦截。
- **新成员欢迎页** `/welcome`：注册后一次性展示。添加通行密钥、开启二步验证（复用账号页的二步验证对话框）都可跳过，完成后显示“已完成”；成员守则与关于页共用一份；三部推荐起点与首页 hero 共用一份数据；“进入档案馆”回首页。原型没有“只显示一次”的记录，用控制台入口打开。
- **片库完整性** `/admin/library`：只有站长可见，只读。顶部是可播放单元、缺视频、缺中文字幕（没有简中或繁中）、缺双语字幕（没有简英或繁英）四个数，下方注明最近一次导入时间和未通过格式检查的文件数（只给数量，详情看导入工具日志）。按作品列出视频、中文字幕、双语字幕和多档清晰度的覆盖数，缺失项标红，并按集号列出缺失单元（超过 6 个只列前 6 个）；默认只看有缺失的作品，可切到全部。页面只用集号定位，不显示 R2 对象键、存储桶或路径；补齐走离线导入工具，页面不提供操作。缺失数据由固定种子生成，每次打开相同。

## 取舍和待定

- 原型技术栈为 Vite + React Router 7（库模式）+ Tailwind 4 + Base UI，UI 组件从 chanhdai.com（MIT）的 shadcn `base-nova` 组件复制过来。正式版另建 React Router 框架模式 + Workers 工程，审查后迁移已有展示组件、布局、样式和已定稿交互；按需适配 loader / action、运行环境和真实数据，不全面重写前端，也不直接 import 本目录。
- 版式按参考站逐页对齐，内容列分两档，顶栏、页脚和页面始终同宽：
  - 宽列 72rem（1152px）：首页、剧集、电影、作品页、播放页、片库、片单。参考站的 3xl 列是为博客正文设计的，海报和播放器放进去太局促；主导航之间切换时宽度不变，顶栏不会跳。海报网格从 md 起 4/5/6 列，首页货架只显示整行；播放器按视口高度封顶，保证控制条在首屏内。
  - 窄列 48rem（768px，即 3xl）：账号、邀请、管理后台、404、登录类页面，以表单和文字为主，保持适合阅读的行宽。页面用 `<Page narrow>` 声明。
  - 两档之间切换时列宽用 320ms 平滑过渡：宽度是布局根节点上注册过的 CSS 变量 `--content-width`，顶栏、页脚和刚挂载的新页面读同一个插值，细线全程对齐；系统开启“减少动态效果”时直接切换。手机上两档都是满宽，没有区别。

  列表页用 PageHeading（小标签 + 4xl 标题），作品页和播放页用博客详情页的“← 返回 + 前后切换 + 4xl 标题”，访客页用 login-01 的居中 Card，404 用等宽大号数字。
- 页脚下方是一条和底部淡出层等高的满宽带子，放纯装饰的线稿，不承载信息：它总在淡出和模糊之下，只露出上半部分；线稿自身也向下渐隐，没有淡出层的登录类页面也不露硬边。线稿是透视网格：由代码按带子宽度生成的格子平面，退向页面下方的消失点，远处几行沉入淡出层。消失方向在内容列中线上，顶边格宽约 96px、取整到列宽一半的整数分之一，所以有两条射线正好从内容列左右边框线的末端出发；边框位置按设备像素取整后量取，任何宽度和列宽切换动画中都接得上。行距按同一透视关系排列，每格都是同一个正方形退向远处。
- 字体统一用 Noto Sans SC（可变字重，自托管 `@fontsource-variable/noto-sans-sc`），正文和标题都用它；等宽角色（集号、时长、邀请码、TOTP、小号大写标签）继续用 Geist Mono，其中的中文字符回落到 Noto Sans SC。字重照参考站：正文 400，标题、导航、标签 500，不用粗体；大标题保留参考站的收紧字距，但减半到 `-0.0125em`，避免中文挤在一起。
- 可交互控件按参考站做成方块：按钮、输入框、菜单项是 8px 圆角的小方块；分段切换（字幕、管理后台标签页）是一个带边框的方框，用 1px 竖线分成格子，当前项灰底；季选择条和分类条一样，是贴着横线的格子；进度条是直角平条。小标签（已开启、管理员等）沿用参考站 Tag 的胶囊形。
- 海报保留圆角，圆角随海报宽度变化：取宽度的 7%，最小 4px、最大 12px。大海报约 12px，和参考站博客卡片的比例一致；小缩略图收到 4px，避免圆得像 App 图标。圆角由 `Poster` 组件统一计算（`rounded-poster`），调用处不要再单独加 `rounded-*`；叠在海报上的遮罩层也用 `rounded-poster`。
- 海报在桌面端默认灰度、悬停恢复彩色，照搬参考站的博客卡片；触屏设备始终显示彩色。

  - Copy Button：邀请链接、二步验证备用码。
  - Status Button：生成邀请码、修改密码、添加通行密钥、登录。
  - Scroll Fade：季选择条、成员表格、搜索列表。
  - Swipe Actions：片单条目，左滑移除、右滑排序。
  - Line Nav：账号页右侧，宽屏才显示。
  - Shimmering Text：播放页签发 token 时的占位。
  - Chevrons Up Down：“加入片单”下拉。
  - Timescale：剧集和电影浏览页的“时间轴”视图，按首映年份排列。

  新增依赖 `motion` 和 `@ncdai/react-swipe-actions`。参考站复制按钮的音效和震动反馈没有引入。
- 触屏设备上片单的上移、下移按钮隐藏，改用右滑；移除按钮始终保留，给键盘和读屏用户用。
