# 前端高保真原型 v1

> 原型代码，随时可以丢弃。不要被正式代码引用，也不要在这上面继续开发成正式功能。

## 要验证的问题

1. chanhdai.com 的视觉语言（居中带边框的内容列、贯穿全屏的细线、斜纹分隔带、zinc 单色、等宽小注释、“图纸标题栏”式页脚）能不能撑起一个以海报为主的观看站，而不只是个人主页。
2. `docs/requirements.md` 的 v1 用户故事能不能落到一套完整、不打架的页面和导航结构里。
3. ArtPlayer 在这套风格里的样子，以及中英字幕切换、续播、下一集提示、键盘操作的交互细节。

## 运行

需要 Node 22+、pnpm，以及 PATH 上可用的 `bash` 和 `ffmpeg`（首次启动时生成测试视频）。

```bash
cd prototypes/frontend-v1
pnpm install
pnpm dev          # http://localhost:6120（监听 0.0.0.0，局域网可访问）
```

`pnpm build` 会先做类型检查再打包。测试视频 `src/media/test-clip.mp4` 是用 ffmpeg 生成的 60 秒测试图（H.264 + AAC，faststart），不提交到 git；字幕 VTT 已提交。所有单集和电影都播放同一段测试片段。

剧集与电影资料已缓存进 `src/data/tmdb.json`，随仓库提交、开箱即用。要重新从 TMDB 拉取（例如新增作品或更新资料）时，先在环境变量里设置 `TMDB_API_KEY`（key 只留在本机，不提交进仓库），再运行 `node scripts/fetch-tmdb.mjs`。

## 怎么用

左上角琥珀色的 **PROTO** 按钮是原型控制台，只在开发模式出现，样式故意和站点不同。它可以：

- 切换身份场景：访客、新成员（空数据）、成员 `picard_fan`（有观看记录、收藏、片单）、管理员 `station_keeper`。
- 直接跳到各个页面和状态，例如三个访客首页方案、过期邀请码、缺中文简介的电影、重置链接。

数据全部在内存里，刷新就重置（只有所选场景会保留在 sessionStorage）。人物都是虚构的。

演示用的输入：

| 场景 | 输入 |
| --- | --- |
| 登录密码 | `engage`，输错 3 次会出现人机验证占位 |
| 二步验证码 | `123456` |
| 有效邀请码 | `Q-CONT-INUM-01` |
| 已用 / 作废 / 过期邀请码 | `MAKEIT-SO9-3HDR` / `WARP-F8TZ-11NB` / `BORG-X0X0-7777` |
| 恢复码 | 任意 `xxxxx-xxxx` 格式 |

快捷键：`⌘K` / `Ctrl+K` 或 `/` 打开搜索，`D` 切换深浅色。播放页：空格、方向键、`F` 全屏、`M` 静音、`C` 切换字幕。

## 首页 hero

要回答的问题：首页最上面一屏应该长什么样。原来照搬了参考站个人主页的头部（头像位、Logo 配图、用户名），回答的是“我是谁”；首页真正要回答的是“现在看什么”。比较过档案卡、影院、航行日志三个方案后选定影院，原来的头部、快捷操作和概览已经删掉。

- 整条打破内容列的深色舞台，顶栏在舞台上方变透明；用当前作品的海报模糊成背景光。
- 舞台只讲当前这一部：作品、这一集、进度、继续播放。底部缩略图条就是需求里的“继续观看”，每张带代号，点一下切换舞台，再点已选中的（带播放标记的那张）直接播放。
- 手机上不显示大海报，只留底部缩略图，标题占满整行；只有一部在看、没有缩略图条时保留大海报。
- 新成员没有观看记录，缩略图条换成三个推荐起点。这三个是写死的示例文案，正式版由谁来挑选还没定。

验收时切换身份场景看两遍：`picard_fan`（有记录）和新成员（无记录）。

## 访客页（登录前，方案比较中）

要回答的问题：没登录的人打开站点，除了登录框还应该看到什么，同时不泄露片库。访客页一律不放海报，不列作品，不显示片库统计；访客也打不开搜索（搜索会列出全部作品）。

> 和需求冲突：`docs/requirements.md` 用户故事 1 写的是“访客只看到登录页和注册页”，第 7 节的访问控制测试也按这个写。这里的 `/` 和 `/about` 对访客公开，定稿前需要站长确认并修改需求文档。

`/` 对访客显示落地页，对成员显示原来的影院首页。落地页有三个方案，用 `?variant=a|b|c` 切换；底部琥珀色的切换条和 `←` `→` 键也能切换（只在开发模式出现）：

| 方案 | 结构 | 主操作 | 透露多少 |
| --- | --- | --- | --- |
| A 星图 `?variant=a` | 宽度 768px 及以上，整页是一张线稿图纸，跟随站点主题，默认浅色。顶部斜纹带下面是图头（Sector 001 · Stellar cartography / Fig. 01），然后是占满整列宽的星图，最下面是一条很薄的标题栏。星图用和全站一样的细 hairline 画 4×2 的星区网格，次级网格是点线，四条边框上是向内的刻度尺（次级网格线处长刻度，其间短刻度）；星点按印刷星图的星等画成 4 种大小，最亮的带圈；中立区画成一条和全站分隔带相同的斜纹带，Nimbus III 在带内、Romulus 在带外；星云画成测绘图式的点线等高线。正中是 Sol，瞄准样式照电影星图：一对红色 LCARS 方括号，括号竖边嵌着青色块，外侧各有一根青色立柱；网格的两条中线换成青色横线和绿色竖线的十字准线，在瞄准框外断开；Sol 在四条边框刻度尺上的位置用红色短条标出。星系 5 个，都避开了文字、编号、准线和刻度，位置只是装饰，不是考据。标题栏分三格，分隔线接着星图的竖线：站名加一句介绍和关于页链接、成员登录（通行密钥按钮和密码登录链接）、邀请码注册（输入框，提交后带着码进入注册页）。LCARS 风格只用在星图内部：Antonio 窄体（OFL）标注、黄色括号的星系标记和红青两色的瞄准框；星图外面一律用站点原有的 Noto Sans SC 和 Geist Mono，只在标题栏编号上留了一点 LCARS 配色。1024px 及以上，星图高度随屏幕变化，保证标题栏在第一屏、不被底部渐隐遮住。宽度低于 768px 时星图太小、标注挤在一起，改为直接显示方案 B 的整页（和方案 B 共用同一个组件，内容完全相同） | 通行密钥登录 / 输入邀请码；窄屏同方案 B，只有邀请码输入框，登录走链接 | 宽屏最少：站名和一句话，其余放在关于页；窄屏同方案 B，讲加入方式、功能、守则和常见问题 |
| B 登舰指南 `?variant=b` | 宽列长页面：邀请码输入框加一张随输入变化的登舰证，下面是加入三步、成员可以做什么、守则、常见问题 | 直接输入邀请码，带着码进入注册页 | 讲功能，不讲片库 |
| C 站长来信 `?variant=c` | 窄列，一封署名短信说明这是什么、规矩是什么，下面是带日期的航行日志 | 读完再去注册或登录 | 语气最亲近；信和日志都是占位文案，需要站长自己写、持续更新 |

`/about` 只有一版，成员和访客都能打开：这是什么、怎么加入、成员守则、隐私与数据、找回账号、版权说明、技术说明。宽屏右侧有本页导航。“版权方联系方式”留了待定占位。

访客顶栏是“首页 · 关于 · 登录”，Logo 一律回到 `/`。直接打开受保护页面（例如 `/series`）仍然跳到 `/login?next=…`，不经过落地页，方便老成员登录后回到原页面。

## 取舍和待定

- 技术栈用 Vite + React Router 7（库模式）+ Tailwind 4 + Base UI，UI 组件从 chanhdai.com（MIT）的 shadcn `base-nova` 组件复制过来。正式版用 React Router 框架模式跑在 Workers 上，届时重写，不直接搬这里的代码。
- 版式按参考站逐页对齐，内容列分两档，顶栏、页脚和页面始终同宽：
  - 宽列 72rem（1152px）：首页、剧集、电影、作品页、播放页、片库、片单。参考站的 3xl 列是为博客正文设计的，海报和播放器放进去太局促；主导航之间切换时宽度不变，顶栏不会跳。海报网格从 md 起 4/5/6 列，首页货架只显示整行；播放器按视口高度封顶，保证控制条在首屏内。
  - 窄列 48rem（768px，即 3xl）：账号、邀请、管理后台、404、登录类页面，以表单和文字为主，保持适合阅读的行宽。页面用 `<Page narrow>` 声明。
  - 两档之间切换时列宽用 320ms 平滑过渡：宽度是布局根节点上注册过的 CSS 变量 `--content-width`，顶栏、页脚和刚挂载的新页面读同一个插值，细线全程对齐；系统开启“减少动态效果”时直接切换。手机上两档都是满宽，没有区别。

  列表页用 PageHeading（小标签 + 4xl 标题），作品页和播放页用博客详情页的“← 返回 + 前后切换 + 4xl 标题”，访客页用 login-01 的居中 Card，404 用等宽大号数字。
- 字体统一用 Noto Sans SC（可变字重，自托管 `@fontsource-variable/noto-sans-sc`），正文和标题都用它；等宽角色（集号、时长、邀请码、TOTP、小号大写标签）继续用 Geist Mono，其中的中文字符回落到 Noto Sans SC。字重照参考站：正文 400，标题、导航、标签 500，不用粗体；大标题保留参考站的收紧字距，但减半到 `-0.0125em`，避免中文挤在一起。
- 可交互控件按参考站做成方块：按钮、输入框、菜单项是 8px 圆角的小方块；分段切换（字幕、管理后台标签页）是一个带边框的方框，用 1px 竖线分成格子，当前项灰底；季选择条和分类条一样，是贴着横线的格子；进度条是直角平条。小标签（已开启、管理员等）沿用参考站 Tag 的胶囊形。
- 海报保留圆角，圆角随海报宽度变化：取宽度的 7%，最小 4px、最大 12px。大海报约 12px，和参考站博客卡片的比例一致；小缩略图收到 4px，避免圆得像 App 图标。圆角由 `Poster` 组件统一计算（`rounded-poster`），调用处不要再单独加 `rounded-*`；叠在海报上的遮罩层也用 `rounded-poster`。
- 海报在桌面端默认灰度、悬停恢复彩色，照搬参考站的博客卡片；触屏设备始终显示彩色。
- 从参考站的 [组件库](https://chanhdai.com/components) 引入了 10 个组件，只用在已有功能上：
  - Copy Button：邀请链接、重置链接、恢复码。
  - Status Button：生成邀请码、修改密码、添加通行密钥、登录。
  - Scroll Fade：季选择条、成员表格、搜索列表。
  - Middle Truncation：重置链接。
  - Theme Switcher：页脚，三档“跟随系统、浅色、深色”。
  - Swipe Actions：片单条目，左滑移除、右滑排序。
  - Line Nav：账号页右侧，宽屏才显示。
  - Shimmering Text：播放页签发 token 时的占位。
  - Chevrons Up Down：“加入片单”下拉。
  - Timescale：剧集和电影浏览页的“时间轴”视图，按首映年份排列。

  新增依赖 `motion` 和 `@ncdai/react-swipe-actions`。参考站复制按钮的音效和震动反馈没有引入。
- 触屏设备上片单的上移、下移按钮隐藏，改用右滑；移除按钮始终保留，给键盘和读屏用户用。
- 时间轴视图不在需求文档里，是站长要求试做、看效果的。观看热力图同样不在需求里，站长决定不做。
- 异步操作（生成邀请码、添加通行密钥等）在原型里人为延迟约 0.7 秒，好让加载状态看得见。
- 手机底部悬浮胶囊是“搜索 + 菜单”，菜单弹出页面列表；右下角有回到顶部按钮。原型控制台因此挪到了左上角。
- 播放 token、限流、Turnstile、WebAuthn 都只是界面占位，没有真实逻辑。
- 进度上报间隔 15 秒、看完阈值 90%、邀请额度 2、恢复码 10 个，都用需求文档里的默认值。
- 单集标题、简介、时长、集数与播出日期来自 TMDB（`zh-CN`，缺失回退 `en-US`），由 `scripts/fetch-tmdb.mjs` 以 manifest 中的 TMDB ID 拉取并缓存到 `src/data/tmdb.json`（14 部电影、13 部剧集、52 季、960 集）。海报和作品中文标题来自 `public/assets/posters/star-trek/manifest.json`（作品中文标题沿用国内流媒体惯用译名，优先于 TMDB）。
