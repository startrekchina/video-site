# 前端高保真原型 v1

> 原型代码，随时可以丢弃。不要被正式代码引用，也不要在这上面继续开发成正式功能。

## 要验证的问题

1. chanhdai.com 的视觉语言（居中带边框的内容列、贯穿全屏的细线、斜纹分隔带、zinc 单色、等宽小注释、“图纸标题栏”式页脚）能不能撑起一个以海报为主的观看站，而不只是个人主页。
2. `docs/requirements.md` 的 v1 用户故事能不能落到一套完整、不打架的页面和导航结构里。
3. ArtPlayer 在这套风格里的样子，以及中英字幕切换、续播、下一集提示、键盘操作的交互细节。
4. 播放页评论区的定稿形态（需求外，站长要求试做），见下文“播放页评论区”。

## 运行

需要 Node 22+、pnpm，以及 PATH 上可用的 `bash` 和 `ffmpeg`（首次启动时生成测试视频）。

```bash
cd prototypes/frontend-v1
pnpm install
pnpm dev          # http://localhost:6120（监听 0.0.0.0，局域网可访问）
```

`pnpm build` 会先做类型检查再打包。测试视频 `src/media/test-clip.mp4` 是用 ffmpeg 生成的 60 秒测试图（H.264 + AAC，faststart），不提交到 git；字幕 VTT 已提交。所有单集和电影都播放同一段测试片段。

剧集与电影资料已缓存进 `src/data/tmdb.json`，随仓库提交、开箱即用。要重新从 TMDB 拉取（例如新增作品或更新资料）时，先在环境变量里设置 `TMDB_API_KEY`（key 只留在本机，不提交进仓库），再运行 `node scripts/fetch-tmdb.mjs`。

## 怎么用

左上角琥珀色的 **PROTO** 按钮是原型控制台，只在开发模式出现，样式故意和站点不同。它可以：

- 切换身份场景：访客、新成员（空数据）、成员 `picard_fan`（有观看记录、收藏、片单）、管理员 `station_keeper`。
- 直接跳到各个页面和状态，例如过期邀请码、缺中文简介的电影、重置链接。

数据全部在内存里，刷新就重置（只有所选场景会保留在 sessionStorage）。人物都是虚构的。

演示用的输入：

| 场景 | 输入 |
| --- | --- |
| 登录密码 | `engage`，输错 3 次会出现人机验证占位 |
| 二步验证码 | `123456` |
| 有效邀请码 | `Q-CONT-INUM-01` |
| 已用 / 作废 / 过期邀请码 | `MAKEIT-SO9-3HDR` / `WARP-F8TZ-11NB` / `BORG-X0X0-7777` |
| 恢复码 | 任意 `xxxxx-xxxx` 格式 |

快捷键：`⌘K` / `Ctrl+K` 或 `/` 打开搜索，`D` 切换深浅色。播放页：空格、方向键、`F` 全屏、`M` 静音、`C` 切换字幕。

## 首页 hero

要回答的问题：首页最上面一屏应该长什么样。原来照搬了参考站个人主页的头部（头像位、Logo 配图、用户名），回答的是“我是谁”；首页真正要回答的是“现在看什么”。比较过档案卡、影院、航行日志三个方案后选定影院，原来的头部、快捷操作和概览已经删掉。

- 整条打破内容列的深色舞台，顶栏在舞台上方变透明；用当前作品的海报模糊成背景光。
- 舞台上半部是当前这一部，下半部是刻度尺。比较过图框、幕布、放映单、刻度四版线稿方案后选定刻度，另三版连同 `/hero-studies` 比较页已经删掉。
  - 当前这一部：海报装进四角加亮的线框，旁边是作品、这一集、简介、直角进度条和继续播放。手机上海报缩小、和标题并排，不再隐藏，因为刻度尺上没有缩略图。
  - 刻度尺就是需求里的“继续观看”，上方是“继续观看 · 5”小标签。尺子是内容列里的一条细线（不贯穿全屏），每 12px 一个短刻度；每部占一段，段首是长刻度，下面是序号、上次观看时间（或“下一集”）、作品名和集号。看了多少就沿尺填多少，当前项的长刻度和填充最亮、序号前带播放标记。点一下切换舞台，再点已选中的直接播放；放不下时横向滑动，右侧渐隐。只有一部在看时也保留刻度尺，舞台结构和高度不随数量变化。
- 新成员没有观看记录，刻度尺换成三个推荐起点。这三个是写死的示例文案，正式版由谁来挑选还没定。

验收时切换身份场景看两遍：`picard_fan`（有记录）和新成员（无记录）。

## 访客页（登录前）

要回答的问题：没登录的人打开站点，除了登录框还应该看到什么，同时不泄露片库。访客页一律不放海报，不列作品，不显示片库统计；访客也打不开搜索（搜索会列出全部作品）。

> 和需求冲突：`docs/requirements.md` 用户故事 1 写的是“访客只看到登录页和注册页”，第 7 节的访问控制测试也按这个写。这里的 `/` 和 `/about` 对访客公开，定稿前需要站长确认并修改需求文档。

`/` 对访客显示落地页，对成员显示原来的影院首页。比较过星图、登舰指南、站长来信三个方案后选定星图，另两个方案连同底部的切换条已经删掉：

- 整页是一张线稿图纸，跟随站点主题，默认浅色。顶部斜纹带下面是图头（Sector 001 · Stellar cartography / Fig. 01），然后是占满整列宽的星图，最下面是一条很薄的标题栏。星图用和全站一样的细 hairline 画 4×2 的星区网格，次级网格是点线，四条边框上是向内的刻度尺（次级网格线处长刻度，其间短刻度）；星点按印刷星图的星等画成 4 种大小，最亮的带圈；中立区画成一条和全站分隔带相同的斜纹带，Nimbus III 在带内、Romulus 在带外；星云画成测绘图式的点线等高线。正中是 Sol，瞄准样式照电影星图：一对红色 LCARS 方括号，括号竖边嵌着青色块，外侧各有一根青色立柱；网格的两条中线换成青色横线和绿色竖线的十字准线，在瞄准框外断开；Sol 在四条边框刻度尺上的位置用红色短条标出。星系 5 个，都避开了文字、编号、准线和刻度，位置只是装饰，不是考据。标题栏分三格，分隔线接着星图的竖线：站名加一句介绍和关于页链接、成员登录（通行密钥按钮和密码登录链接）、邀请码注册（输入框，提交后带着码进入注册页）。LCARS 风格只用在星图内部：Antonio 窄体（OFL）标注、黄色括号的星系标记和红青两色的瞄准框；星图外面一律用站点原有的 Noto Sans SC 和 Geist Mono，只在标题栏编号上留了一点 LCARS 配色。
- 1024px 及以上，星图高度随屏幕变化，保证标题栏在第一屏、不被底部渐隐遮住。
- 宽度低于 768px 时星图太小、标注挤在一起，改用原来登舰指南方案的整页：欢迎语、邀请码输入框（旁边随输入变化的登舰证只在 768px 及以上显示）、加入三步、成员可以做什么、守则、常见问题。

`/about` 只有一版，成员和访客都能打开：这是什么、怎么加入、成员守则、隐私与数据、找回账号、版权说明、技术说明。宽屏右侧有本页导航。“版权方联系方式”留了待定占位。

访客顶栏是“首页 · 关于 · 登录”，Logo 一律回到 `/`。直接打开受保护页面（例如 `/series`）仍然跳到 `/login?next=…`，不经过落地页，方便老成员登录后回到原页面。

## 播放页评论区

要回答的问题：评论区最终长什么样。以 `proto/comments-ui` 的 Fig. B「双栏对话」为基础，并入 `proto/comments-studies` 的输入框、放置位置（选集列表下方）和时间格式，再补一轮细节。两个分支里的其他方案和方案切换条都没有带过来。

> 和需求冲突：`docs/requirements.md` 第 8 节把评论列为范围外。要进 v1，需要先改需求文档，并补上管理员删评、举报和封禁联动等审核工具（原型里都没有）。

从原型控制台的“播放页评论区”进入，或者直接打开 `/watch/tng-s03e26#comments`（46 条评论，第一条有 23 条回复）。`/watch/tng-s03e24#comments` 没有评论，用来看空状态；`/watch/movie-star-trek-ii-the-wrath-of-khan#comments` 是电影。截图在 [`src/pages/watch-comments/screenshots/`](src/pages/watch-comments/screenshots/)（1440×1000 浅色、吸顶后回复、深色，390×844 列表、内联对话，空状态）。

- **位置**：单集在选集列表下面，电影在简介下面。一块标准面板，标题是“本集讨论 / 本片讨论 + 总数”，右侧是排序。
- **1024px 及以上分两栏**：左栏顶部是发评论的输入框，下面是评论列表；右栏 28rem 是当前评论的对话，从上到下是原评论、全部回复和停靠在底部的回复框。默认打开本页第一条，点评论的空白处或“N 条回复”切换。当前评论灰底，两栏分隔线上对应位置压一条黑色竖条，表示它和右栏是一起的。
- **右栏吸顶**：右栏从自己的位置一直填到底部渐隐区上方，一进来就能看到回复框；往下滚时贴在顶栏下面，内部单独滚动；滚到列表末尾时右栏跟着变矮，标题和回复框始终露在外面。
- **1024px 以下单栏**：点“N 条回复”在评论下面就地展开，左侧一条竖线，回复框在最后，再点收起。
- **输入框**（来自 comments-studies）：Markdown 工具栏、表情、Markdown 速查、预览、字数，`⌘↵` / `Ctrl+↵` 发送。回复框是精简版：一行起步、随内容长高，发送键只有图标；手机上和发评论的输入框一样，工具栏只留粗体、斜体、引用、链接、表情和 `MD`。回复某条回复时框顶显示“回复 @x”，点 ×，或在空框里按 `Esc`，改回回复评论作者。
- **时间**（来自 comments-studies）：全英文、Geist Mono；7 天内用相对时间（`just now`、`5m ago`、`3h ago`、`2d ago`），更早用绝对日期（`Sep 12`，跨年为 `Aug 3, 2025`），悬停显示完整时间。

和两个原方案相比改了这些：

- 发评论的输入框常开，收在左栏顶部，不横跨两栏：写字的宽度和评论正文一致，右栏能从标题栏下面开始，首屏同时看得到列表、对话和回复框。
- 右栏的回复框常驻底部，不用先点“回复这段对话”；点评论的空白处也能打开对话（链接、按钮和选中文字时除外）。
- 每页从 3 条改为 10 条评论（comments-studies 的数值），回复每批显示 10 条。
- 发新评论后不再切到“最新”排序，而是把自己刚发的评论置顶并闪一下，右栏正在看的对话也不会被换掉。新回复会展开到最后，并滚到看得见的地方。
- 发送键和 `⌘↵` 走同一条路径，都会显示转圈和“已发送”。发送中输入框只读，工具栏、表情和预览也锁住，避免重复提交或改了却没发出去。发送途中切到别的对话也没关系：回复照样发到原来的对话，切回来时输入框仍然锁着。发送结果用 `role=status` 播报给读屏。
- 每个对话的草稿分开保存，切换对话或在宽窄屏之间切换都不会丢。
- 点“回复”时在同一次点击里聚焦输入框（iOS 只有这样才会弹出键盘）；输入框不在可视区时滚到屏幕中间，避开顶栏、底部渐隐和手机底部的导航胶囊。
- 回复里，评论作者带“作者”标签。
- 系统开启“减少动态效果”时，平滑滚动、淡入和高亮都跳过。

其他规则沿用 comments-studies：管理员和自己带小标签；赞显示数量，踩不显示、只参与排序，再点取消；“智能”排序只在切换时算一次，点赞不会让列表跳动，回复始终按时间正序；正文太长时折叠（列表和回复约 5 行，右栏的原评论约 7 行），可以展开全文；评论最长 1000 字；Markdown 只开放粗体、斜体、删除线、代码、引用、列表、链接和分隔线，回车即换行，不支持图片、表格和 HTML，站外链接新窗口打开并带 `nofollow ugc`（`//host` 也算站外，`javascript:` 之类的链接只留文字）；发送人为延迟约 0.5 秒；示例评论和用户都是虚构的，由固定种子生成，刷新后不变（电影的示例评论不提“这集”“这季”）。

新增依赖 `react-markdown`、`remark-gfm`、`remark-breaks`，版本和 comments-studies 相同。没做、留给定稿时讨论的：剧透遮罩语法、评论里的时间码跳转、编辑和删除自己的评论、举报。

## 取舍和待定

- 技术栈用 Vite + React Router 7（库模式）+ Tailwind 4 + Base UI，UI 组件从 chanhdai.com（MIT）的 shadcn `base-nova` 组件复制过来。正式版用 React Router 框架模式跑在 Workers 上，届时重写，不直接搬这里的代码。
- 版式按参考站逐页对齐，内容列分两档，顶栏、页脚和页面始终同宽：
  - 宽列 72rem（1152px）：首页、剧集、电影、作品页、播放页、片库、片单。参考站的 3xl 列是为博客正文设计的，海报和播放器放进去太局促；主导航之间切换时宽度不变，顶栏不会跳。海报网格从 md 起 4/5/6 列，首页货架只显示整行；播放器按视口高度封顶，保证控制条在首屏内。
  - 窄列 48rem（768px，即 3xl）：账号、邀请、管理后台、404、登录类页面，以表单和文字为主，保持适合阅读的行宽。页面用 `<Page narrow>` 声明。
  - 两档之间切换时列宽用 320ms 平滑过渡：宽度是布局根节点上注册过的 CSS 变量 `--content-width`，顶栏、页脚和刚挂载的新页面读同一个插值，细线全程对齐；系统开启“减少动态效果”时直接切换。手机上两档都是满宽，没有区别。

  列表页用 PageHeading（小标签 + 4xl 标题），作品页和播放页用博客详情页的“← 返回 + 前后切换 + 4xl 标题”，访客页用 login-01 的居中 Card，404 用等宽大号数字。
- 字体统一用 Noto Sans SC（可变字重，自托管 `@fontsource-variable/noto-sans-sc`），正文和标题都用它；等宽角色（集号、时长、邀请码、TOTP、小号大写标签）继续用 Geist Mono，其中的中文字符回落到 Noto Sans SC。字重照参考站：正文 400，标题、导航、标签 500，不用粗体；大标题保留参考站的收紧字距，但减半到 `-0.0125em`，避免中文挤在一起。
- 可交互控件按参考站做成方块：按钮、输入框、菜单项是 8px 圆角的小方块；分段切换（字幕、管理后台标签页）是一个带边框的方框，用 1px 竖线分成格子，当前项灰底；季选择条和分类条一样，是贴着横线的格子；进度条是直角平条。小标签（已开启、管理员等）沿用参考站 Tag 的胶囊形。
- 海报保留圆角，圆角随海报宽度变化：取宽度的 7%，最小 4px、最大 12px。大海报约 12px，和参考站博客卡片的比例一致；小缩略图收到 4px，避免圆得像 App 图标。圆角由 `Poster` 组件统一计算（`rounded-poster`），调用处不要再单独加 `rounded-*`；叠在海报上的遮罩层也用 `rounded-poster`。
- 海报在桌面端默认灰度、悬停恢复彩色，照搬参考站的博客卡片；触屏设备始终显示彩色。
- 从参考站的 [组件库](https://chanhdai.com/components) 引入了 10 个组件，只用在已有功能上：
  - Copy Button：邀请链接、重置链接、恢复码。
  - Status Button：生成邀请码、修改密码、添加通行密钥、登录。
  - Scroll Fade：季选择条、成员表格、搜索列表。
  - Middle Truncation：重置链接。
  - Theme Switcher：页脚，三档“跟随系统、浅色、深色”。
  - Swipe Actions：片单条目，左滑移除、右滑排序。
  - Line Nav：账号页右侧，宽屏才显示。
  - Shimmering Text：播放页签发 token 时的占位。
  - Chevrons Up Down：“加入片单”下拉。
