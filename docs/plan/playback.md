#### 6.6.1 会话授权与撤销边界

- 视频与字幕入口先由 Better Auth 识别请求 Cookie 中的会话（`identity.session()`，同一请求内只解析一次），再用一条主库 SQL 按 `liveMemberSql` 核对会话行未过期、成员注册完成、邮箱已验证且未封禁，并在同一语句中按 ID 与格式取出资源行。会话或成员不满足返回 `401`，资源不存在或版本未验证返回 `404`，都在读取 R2 之前判定，不暴露元数据。
- `liveMemberSql` 是页面身份（`memberForSession`）与媒体入口共用的唯一成员规则；媒体入口不再先调用 `memberForSession` 再重复核对同一条件。
- 每个新请求都从主库判定，不缓存鉴权结果。退出、撤销会话、邮箱密码重置、改密换会话或封禁（触发器同时删除会话）后，下一个媒体请求即被拒绝。已建立的响应不主动截断：R2 正文直接交给响应，客户端断开时由运行时取消上游读取。
- 媒体地址固定为 `/media/:mediaFileId`、`/subtitles/:subtitleTrackId`，不含凭证；旧页面残留的 query 参数被忽略，不参与授权。会话 Cookie 为 `SameSite=Lax`，跨站嵌入的子资源请求不携带它，因而返回 `401`。

#### 6.6.2 R2 与 HTTP Range 契约

鉴权先于 HEAD、Range 判断、条件响应和任何 R2 读取。Worker 使用私有 R2 binding，将资源 ID 映射到 D1 中的对象键，不重定向到 R2，也不返回可绕过 Worker 的预签名地址。

视频和字幕请求要求数据库保存的已验证 `r2_etag` 非空且与 R2 当前版本一致，否则返回脱敏 `404`。历史未记录版本的引用须经扫描验证格式、校验和及长度后补齐版本，不能仅凭长度相同放行。

GET 与 Range 只做一次 R2 读取：`get()` 带 `onlyIf: { etagMatches: r2_etag }`，范围按 D1 记录的 `byte_length` 换算为 `{ offset, length }` 传入。前置条件不符（读取时对象已被替换）、对象缺失或返回大小与记录不符时取消正文并返回 `404`。HEAD，以及返回 `416` 前确认对象仍在，各使用一次 `head()`。`head()` / `get()` 在响应开始前抛错时返回 `MEDIA_UNAVAILABLE` 与脱敏 `503`。

| 请求 | 外部行为 |
| --- | --- |
| `GET` 无 Range | `200 OK`，流式返回整文件，`Content-Length` 为对象总字节数，不带 `Content-Range`。 |
| `GET` 单个有效字节范围 | 支持 `bytes=start-end`、`bytes=start-`、`bytes=-suffix`，按已验证长度换算后由 R2 只读取该段，不先取全文件再切片；返回 `206`。end 超出尾部时截断到文件末尾。 |
| 范围无法满足 | start 超出文件、反向范围或零长度 suffix 返回 `416 Range Not Satisfiable`，`Content-Range: bytes */total`，无媒体 body；总大小仅在授权通过后可见。 |
| 非法 Range / 未支持的范围形式 | 格式不合法返回 `400`；非 bytes 单位和有效的多范围请求在 v1 忽略 Range，按无 Range 返回 `200`，不声称支持 multipart，也不拼成错误的单段 206。 |
| `HEAD` | 经过相同授权，忽略 Range，`200` 返回完整 GET 的元数据和总长度，没有 body；用 R2 `head()`，不为了 HEAD 拉取视频内容。 |
| `If-Range` | 只按强 ETag 匹配：与当前 ETag 相同才保留 Range；不匹配或日期形式一律忽略 Range，返回完整 `200`。任何条件响应都不能绕过鉴权。 |
| 文件缺失 / 方法不支持 | 缺失返回脱敏 `404`，记录资源 ID 供排查；其他方法返回 `405` 及 `Allow: GET, HEAD`，不开放浏览器上传。 |

- 成功响应设 `Accept-Ranges: bytes`；206 的 `Content-Range` 为 `bytes start-end/total`，`Content-Length = end - start + 1`；`ETag`、`Last-Modified` 取自本次读取的对象。
- MP4 使用 `video/mp4`，字幕使用 `text/vtt; charset=utf-8`；字幕接受同样的鉴权和 GET/HEAD 规则。不复制上传时的 R2 HTTP 元数据，不能让其中的 `cacheControl` 变成公开缓存。
- R2 `body` 以流交给响应，不整体 `arrayBuffer()` 或缓存进内存；媒体不压缩、不改写字节，Content-Length 与 Range 语义保持一致。
- v1 不将授权媒体响应放进共享 CDN/Cache API；200、206、416 和错误均为 `private, no-store`。地址不含凭证；应用日志只记路由族、状态与资源 ID，不记 URL 或 query，平台的 query 脱敏与 invocation log 关闭照常保留。

## 播放器与媒体接口

| 入口与方法 | 权限 | 请求 / 响应 |
| --- | --- | --- |
| `/watch/:unitId` loader | 正常成员 | 与片库查询并行读取该单元已验证的原画与档位 MP4 及已验证 VTT 字幕轨（`playbackSource`），返回 `source: { url, qualities: [{ label, url }], tracks: [{ id, language, displayName, url }] } | null`，`url` 为原画，原画未验证时为 `null`；不访问 R2，不写入任何计数。 |
| `GET/HEAD /media/:mediaFileId`、`/subtitles/:subtitleTrackId` | 当前 Cookie 会话的正常成员 | 按 6.6.1 鉴权、6.6.2 返回字节流或脱敏错误；资源 ID 只在服务端映射 R2，不接受客户端对象路径。 |

ArtPlayer 在浏览器懒加载，同源 MP4/VTT；切单元重建并读取目标起点。媒体地址固定且不按时间续期，成员选择另一清晰度时切换到对应档位地址。

字幕由播放器先以同源 `fetch` 读取并检查状态，再以本地 blob 地址交给 ArtPlayer；ArtPlayer 会把任何响应正文当作 VTT 解析，自身发现不了失败。`404` 时把该轨移出菜单与页面按钮并切到关闭；`401`/`403` 提示重新登录；其他失败提示重新选择字幕并保留选项，再次选择成功后清除该提示。字幕切换串行执行，旧响应不能覆盖最新选择。

播放器关闭 ArtPlayer 自带的自动重连（`RECONNECT_TIME_MAX = 0`）：它从 0 秒重试，浏览器缓存了开头数据时会先触发 `canplay` 再请求缺失区段，形成持续请求的循环。每次故障播放器只向同一地址发一次 HEAD，按状态提示登录失效（`401`/`403`）、片源暂时无法播放（`404`）或连接中断；登录失效提供“重新登录”（带回当前页的 `next`），其余提供“重新连接”。点击后原地重设地址，在下一次可播时回到故障前最后播放到的位置并恢复播放或暂停状态，浏览器拒绝自动播放时提示手动播放；重连再失败会重新分类并再次提供重连，不自动重试。字幕失败只提示重新选择字幕，不显示重新连接；视频故障未经重连期间，字幕或自动播放受阻提示不会覆盖视频的出错提示与重连按钮。

播放页维护当前字幕选项；播放器移出字幕轨时通过 `onTracksChange` 同步页面按钮，选择由页面状态与 `onSubtitleChange` 同步，同一单元不因字幕清单变化重建播放器。
