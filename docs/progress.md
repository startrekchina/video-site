## 3. 尚未完成与已知限制

- 后端审查修复尚未在 staging 复验；浏览器夹具使用虚构 API 响应，不能替代真实外部服务或平台验证。回复游标、发信索引与 TOTP 唯一索引迁移只在隔离测试库验证，云端尚未应用；TOTP 迁移遇到已有重复配置会中止并保留凭证，须先核查归属，不能自动删除。
- 恢复工具的单次 TOTP 处理上限为 1000 条（B25）；超过时明确停止，尚未实现分批恢复收尾。
- 当前、历史密钥的独立副本尚未准备，这是上线阻塞。媒体/字幕冷备由你在项目之外完成，项目不再跟踪。
- 性能慢样本多数耗时在代理/TLS 建连，但仍有两次后续等待偏高，历史尾延迟未完全归因；浏览器插件连接不稳定且没有性能 trace，手机冷缓存 LCP、真正冷启动及完整成本矩阵未完成。
- 控制台 24 小时内存 P99 约 25.19 MB，内存超限为 0；它不是单次备份峰值，WebDAV 直接回读服务也仍缺实测。
- 同名替换不保留旧文件：格式合法的错误文件也会替换已验证片源，只能凭扫描日志和你自己的冷备找回。
- 直接在存储里删除已关联的视频或字幕后，数据库记录仍保留；恢复备份时工具要求每条记录的文件都在，所以凡含该记录的备份（包括删除前做的）都会在恢复校验时失败，只能补回文件。这是本次功能之前就有的行为。
- PR #42 的密钥指纹可被弱口令字典匹配；现有高熵 Secret 要求不能由长度检查保证。处置方案待确认，未更换格式或轮换密钥；其余未复核的静态发现不算已确认缺陷。
- 按旧 1,700 GB 总媒体假设，官方单价计算的 R2 存储加 Workers 基础费约 30.35 美元/月；全部清晰度合计容量、CPU/操作、邮件及异地备份费用未核定。账单接口返回 403，不能宣称总预算已验收。

## 4. 待确认事项与体验反馈

恢复登录与播放验收、临时 Token 撤销均已收到你的确认，无需重复操作。接下来需要准备当前、历史密钥独立副本，并核定所有清晰度的实际总容量及外部服务费用；密钥不用发送到聊天。

可读页面地址已发布到 staging 并通过验证，“队列条测试”片单已换成 8 位新地址，旧链接失效；待你在 staging 验收。正式站前端同步待你复核。字幕四类标记、首播日期、片单队列条与页脚已在 staging 验证，待你验收；测试片单“队列条测试”留在你的账号下供查看，验收后可删除。同名替换在 staging 只验证了字幕；原画与档位替换需要你授权向 staging R2 写入测试视频后实测，或确认缩小验证范围。本机映射文件若仍有 `displayName` 字段需删除。

删除已关联媒体的处理方式需要你决定。一种是恢复校验遇到缺失文件时不再中止，像版本不符一样标为待验证并单独计数，删除前后的备份都能恢复，缺的片源恢复后不可播；另一种是扫描在文件删除后一并删除记录，只对之后的备份有效。

密钥指纹风险需要确认是否另立备份格式/弱密钥策略调整；当前仍要求独立的高熵随机 Secret，不把给 SHA-256 加盐视为弱密钥问题已解决。
