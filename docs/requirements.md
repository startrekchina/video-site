# 星际迷航私人观看站 · 需求文档

- 状态：需求已确认（2026-09-30），尚未开始开发
- 适用范围：第一版（v1）。后续版本的内容见“范围外”一节

## 1. 问题陈述

一个小圈子的《星际迷航》粉丝希望在同一个地方观看全部剧集和电影，按自己的节奏记录看到了哪里，并整理和分享片单。现有的观看渠道很分散，中文字幕和中文剧集资料不全，也没有只属于这个圈子的空间。

站长只能用业余时间维护，希望运维工作尽量少、每月花费可控，整套系统放在 Cloudflare 上。

## 2. 解决方案

建一个邀请制的私人观看站，只对受邀成员开放：

- 成员必须持邀请码注册，之后用用户名和密码登录，可以加上通行密钥和 TOTP 二步验证。
- 登录后可以浏览全部作品，在线播放 MP4 视频，并切换中文或英文字幕。
- 站点自动记录观看进度，首页显示“继续观看”。成员可以收藏作品，也可以建立片单。
- 管理员负责发放邀请码、封禁成员、重置账号。
- 站长在本地用离线命令行工具把视频、字幕和剧集资料导入系统。网站本身不提供内容上传或编辑功能。

### 2.1 法律风险声明

《星际迷航》系列的版权归 Paramount 所有。本站的片源是站长自己持有的拷贝，但提供给其他人观看，在法律上仍然属于未授权分发。“非营利”和“粉丝向”都不构成免责理由。

Cloudflare 的可接受使用政策（AUP）禁止托管侵权内容。一旦收到 DMCA 投诉，可能导致内容下架、账号被封，以及 R2 中的数据丢失。站长已知晓并自行承担这一风险。

本项目不设计任何规避 DMCA 或检测的机制。访问控制只用于限定谁是成员。

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| 作品 | 一部电影或一部剧集（系列），和 manifest 中的一条主海报一一对应 |
| 季 | 剧集下的一季，有自己的季海报 |
| 集 | 某一季下的一集 |
| 可播放单元 | 可以直接播放的东西：一集，或一部电影 |
| 媒体文件 | 存在 R2 中、属于某个可播放单元的视频文件（v1 只有 MP4） |
| 字幕轨 | 挂在可播放单元上的一条外挂字幕（v1 为 VTT，分中文和英文） |
| 成员 | 已注册的普通用户 |
| 管理员 | 能管理成员和邀请码的用户 |
| 邀请码 | 一次性的注册凭证，记录是谁发出的 |
| 邀请链 | 成员之间“谁邀请了谁”的关系，出问题时用来追溯和连带处理 |
| 播放 token | Worker 签发的短期凭证，只对一个媒体文件有效，并绑定到具体成员 |
| 恢复码 | 成员自己保存的一次性码，用于找回账号 |
| 重置链接 | 管理员为成员生成的一次性账号重置入口 |
| 片单 | 成员自己整理的有序作品或剧集清单 |

## 5. 用户故事

### 5.1 访客与注册

1. 作为访客，我希望只看到登录页和注册页，这样站点内容不会暴露给非成员。
2. 作为访客，我希望用邀请码注册账号，这样只有受邀的人才能加入。
3. 作为访客，我希望邀请码无效、过期或已被使用时能看到明确的提示，这样我知道该去找邀请人重新要一个。
4. 作为访客，我希望注册时自己设置用户名和密码，这样不需要提供邮箱也能加入。
5. 作为新成员，我希望注册完成后立刻拿到一组恢复码并被提醒妥善保存，这样以后忘记密码也能自己找回账号。
6. 作为搜索引擎的爬虫，我不应该收录本站的任何页面。

### 5.2 登录与账号安全

7. 作为成员，我希望用用户名和密码登录。
8. 作为成员，我希望绑定通行密钥，这样可以不输密码直接登录。
9. 作为成员，我希望开启 TOTP 二步验证，这样即使密码泄露，账号也不会被盗。
10. 作为成员，我希望连续输错密码时系统会限流或弹出人机验证，这样我的账号不容易被暴力破解。
11. 作为成员，我希望能查看自己有哪些登录会话，并退出不认识的会话。
12. 作为成员，我希望能修改密码、重新生成恢复码、解绑通行密钥或二步验证设备。
13. 作为成员，我希望忘记密码时可以用恢复码重设，不需要找管理员。
14. 作为成员，我希望恢复码也丢了的时候，管理员能给我一个一次性的重置链接。

### 5.3 浏览片库

15. 作为成员，我希望在首页看到“继续观看”，以及按剧集和电影分类的全部作品。
16. 作为成员，我希望在作品页看到中文标题、简介、年份和海报；中文资料缺失时显示英文。
17. 作为成员，我希望在剧集页按季浏览，每一集都显示标题、简介、时长和我的观看状态。
18. 作为成员，我希望按作品名（中文或英文）搜索作品。
19. 作为成员，我希望在一部作品的季和集之间顺畅地切换。

### 5.4 播放

20. 作为成员，我希望点击一集或一部电影就能在网页里直接开始播放。
21. 作为成员，我希望可以随意拖动进度条，播放能马上从新位置开始。
22. 作为成员，我希望在中文字幕、英文字幕和关闭字幕之间切换。
23. 作为成员，我希望看完两小时的电影都不会因为凭证过期而中断。
24. 作为成员，我希望用键盘控制播放器（播放、暂停、快进、快退、调节音量、全屏）。
25. 作为成员，我希望一集播完后，页面提示我播放下一集。
26. 作为站长，我希望复制出去的视频地址很快就失效，而且只对原来的成员和这一个文件有效，这样链接被转发出去影响也有限。

### 5.5 观看进度与片单

27. 作为成员，我希望系统自动记住每一集和每部电影看到了哪里，下次打开时从那里继续。
28. 作为成员，我希望看到接近结尾时自动标记为“已看完”，也可以手动标记为已看或未看。
29. 作为成员，我希望在剧集页一眼看出哪几集已经看过。
30. 作为成员，我希望在不同设备上看到同样的观看进度。
31. 作为成员，我希望收藏作品。
32. 作为成员，我希望建立有序的片单（比如“TNG 必看 20 集”），片单里可以放作品，也可以放单集。
33. 作为成员，我希望把片单设为站内公开，让其他成员也能看到。

### 5.6 邀请

34. 作为成员，我希望看到自己还剩多少个邀请码，并能生成邀请码发给朋友。
35. 作为成员，我希望看到自己发出的邀请码是否已被使用，以及是谁用的。
36. 作为成员，我希望能作废还没被使用的邀请码。

### 5.7 管理员

37. 作为管理员，我希望生成邀请码不受数量限制。
38. 作为管理员，我希望调整每位成员的邀请额度。
39. 作为管理员，我希望查看成员列表，以及每个人的邀请人和被邀请人。
40. 作为管理员，我希望封禁一名成员，并可以选择连带封禁他邀请的人。
41. 作为管理员，我希望被封禁的成员立即无法登录，已经在播放的视频最多 30 分钟后停止。
42. 作为管理员，我希望为成员生成一次性重置链接，通过站外渠道发给对方。
43. 作为管理员，我希望把其他成员设为管理员，或取消管理员身份。

### 5.8 站长与运维

44. 作为站长，我希望在本地用一个命令行工具把视频、字幕和剧集资料导入 staging 或 prod 环境。
45. 作为站长，我希望导入工具能重复运行而不出问题：再跑一次只会补上缺少的部分，不会产生重复数据。
46. 作为站长，我希望导入工具在上传前检查视频格式，格式不对时明确提示我去重新转码。
47. 作为站长，我希望剧集标题和简介由导入工具从 TMDB 自动拉取中文和英文版本，不用我手动整理。
48. 作为站长，我希望 staging 和 prod 完全隔离，这样在 staging 上试错不会影响成员。
49. 作为站长，我希望数据库每天自动备份到 R2，同时推送一份加密副本到 Cloudflare 之外的 WebDAV 地址。
50. 作为站长，我希望每月的开销都在预算以内，不用盯着账单。

## 6. 实现决策

### 6.1 总体架构

- 全站使用 React Router v7 框架模式，前后端作为一个 Worker 部署在 Cloudflare Workers 上。页面的登录校验在服务端的 loader 中完成。
- D1 存放所有结构化数据，包括成员、会话、邀请码、剧集资料、观看进度和片单。
- R2 存放媒体文件和字幕文件。R2 存储桶不公开，只通过 Worker 访问。
- 海报留在仓库的 `public/` 目录下，作为 Workers 静态资源公开访问，不需要登录。站长知道这样会让外人看出这是一个星际迷航站，并接受这一点。
- 界面只做中文，不做 i18n。
- 全站返回 `X-Robots-Tag: noindex`，并配置 `robots.txt` 禁止所有爬虫。

### 6.2 数据模型（概念层）

- 作品分为电影和剧集两种。剧集下有季，季下有集。电影和集统一抽象为“可播放单元”，播放、进度、收藏和片单都只和可播放单元或作品打交道，不用区分电影和剧集。
- 作品、季、集都记录 TMDB ID，中英文标题和简介分开存储。展示时优先用中文，中文缺失就回退到英文。
- 一个可播放单元对应一个或多个媒体文件，媒体文件记录格式、码率等属性。v1 每个单元只有一个 MP4，以后加 HLS 或多档码率时只需要增加记录。
- 一个可播放单元可以挂多条字幕轨，每条记录语言、格式和显示名称。v1 只用 VTT，以后接入 ASS 时不需要改表结构。
- 片单里的条目既可以是作品，也可以是可播放单元，并且保留排序。
- 邀请码记录发出人、使用人、状态和有效期。成员表记录邀请人，邀请链由这两者串联出来。

### 6.3 身份认证

- 注册必须提供有效邀请码。邀请码只能使用一次，可以作废，也可以设置过期时间。
- 登录方式是用户名加密码。成员还可以绑定通行密钥（WebAuthn）用于免密码登录，以及开启 TOTP 二步验证。
- 密码哈希使用 `node:crypto` 的 scrypt，参数取 N=2^14、r=8、p=5，每次约占 16 MB 内存，强度和 OWASP 推荐的其他参数组合相当。不使用 argon2，因为 Workers 不支持；也不使用 PBKDF2，因为 Web Crypto 在 workerd 中限制迭代次数不超过 10 万次（这个上限是根据运行时行为观察到的，文档里没有写明，开发时需要实测确认）。
- TOTP 密钥在数据库中加密存储，加密密钥放在 Worker Secrets 里。
- 登录、注册和恢复接口通过 Workers Rate Limiting 限流，连续失败后要求完成 Turnstile 人机验证。
- 会话存在 D1，浏览器端用 HttpOnly、Secure、SameSite 的 Cookie 保存会话标识。
- 认证逻辑可以使用 Better Auth（它的 username、passkey、twoFactor 插件和 D1 适配器正好覆盖这些需求），也可以自己实现，开发时再决定。无论选哪种，认证模块都要能以插件方式接入以后的邮件验证码和 OAuth 登录。

### 6.4 账号恢复

- 第一层：成员注册或开启二步验证时，系统生成一组一次性恢复码（默认 10 个），只保存哈希值。成员可以用任意一个恢复码重设密码。
- 第二层：恢复码全部丢失时，管理员在后台生成一次性重置链接（默认 24 小时有效），通过站外渠道交给成员。
- 通过重置链接恢复账号后，旧会话全部失效。是否同时清除二步验证和通行密钥，开发时再定，默认是清除后让成员重新绑定。

### 6.5 邀请与权限

- 角色只有两种：成员和管理员。
- 管理员生成邀请码不受数量限制。每位成员有一个邀请额度（默认 2 个），管理员可以为每个人单独调整。
- 封禁一名成员时，可以选择只封禁他本人，或者沿邀请链连带封禁他邀请的人。封禁后该成员的所有会话立即失效，已经签发的播放 token 最多 30 分钟后自然失效。

### 6.6 播放与媒体分发

- v1 直接播放 MP4 文件，要求视频为 H.264、音频为 AAC，并做 faststart 处理（元数据放在文件开头，这样不用下载完就能开始播放和拖动）。不做 HLS，也不做在线转码。
- 成员打开播放页时，Worker 签发一个播放 token：
  - 用 HMAC 签名，内容包括成员 ID、媒体文件 ID 和过期时间；
  - 有效期 30 分钟，播放页在过期前自动续期；
  - 每次续期都会检查成员当前状态，所以被封禁的成员最多 30 分钟后就无法继续播放。
- token 放在媒体地址的查询参数里，因为 `<video>` 标签无法自定义请求头。Worker 验证 token 后，把浏览器的 HTTP Range 请求原样转给 R2，并返回 `206 Partial Content`。
- 字幕文件也通过同样的 token 机制访问。
- 播放器使用 ArtPlayer，一方面可以加载外挂 VTT 字幕并切换中英文，另一方面方便以后接入弹幕插件。
- v1 不限制每个账号的同时播放数。以后要加这个功能，入口放在 token 签发和续期这一步，限额由管理员在后台随时调整。

### 6.7 观看进度与片单

- 播放页定期上报播放位置（默认 15 秒一次），暂停和离开页面时也上报一次。进度存在 D1，按“成员 + 可播放单元”保存，所以换设备也能接着看。
- 播放位置达到总时长的 90% 就标记为已看完（默认值，可调）。成员也可以手动标记。
- “继续观看”显示成员最近看过、还没看完的可播放单元。如果一集已经看完，就推荐同一部剧的下一集。
- 收藏只针对作品。片单是有序列表，条目可以是作品或单集，成员可以设为私有或站内公开。

### 6.8 离线导入工具

这是一个在站长本机运行的命令行工具，可以指定导入到 staging 还是 prod。它负责：

- 读取 manifest，建立作品和季的记录；
- 按 TMDB ID 拉取作品、季和集的中英文资料；
- 检查 MP4 的编码和 faststart 是否符合要求，不符合就报错，提示站长先在本地转码；
- 把字幕统一转成 VTT，其中 ASS 字幕会丢失样式；
- 上传媒体文件和字幕文件到 R2，并在 D1 中写入对应记录。

导入可以重复执行而不产生副作用：记录以 TMDB ID 或季号、集号为唯一键，已经存在的文件会跳过。网站本身不提供内容管理后台，TMDB API Key 只放在站长本地。

### 6.9 环境与备份

- staging 和 prod 是两套完全独立的资源，各自有自己的 Worker、D1 和 R2。
- D1 利用 Time Travel 功能，可以恢复到最近 30 天内的任意时间点。
- 一个 Worker 定时任务（Cron Trigger）每天调用 D1 的导出 API，把导出文件存进 R2 的备份目录，再加密后用 HTTP `PUT` 推送到 Cloudflare 之外的一个 WebDAV 地址。导出内容包含密码哈希和 TOTP 密钥，所以必须加密后才能离开 Cloudflare。备份默认保留 30 天。
- WebDAV 地址必须能从公网通过 HTTPS 访问，最好用 443 端口。如果它在家里的 NAS 上，推荐用 Cloudflare Tunnel 暴露出来，不需要在路由器上开端口。
- Cloudflare API Token、WebDAV 账号密码和备份加密密钥都存在 Worker Secrets 里。
- 视频原片只在站长本地冷备份，不存第二份云端副本。

### 6.10 成本估算

| 项目 | 估算 |
| --- | --- |
| Workers Paid | 5 美元/月 |
| R2 存储（单档 1080p MP4，约 1.7 TB） | 约 26 美元/月 |
| R2 出口流量 | 免费 |
| R2 读写操作和 D1 | 在这个规模下基本都在免费额度内 |
| 合计 | 约 31 美元/月，在 50 美元的预算以内 |

以后如果增加 HLS 多档码率，存储会涨到 2.2 至 3 TB，每月约 38 至 50 美元，那时需要重新评估是否保留原始 MP4。

## 7. 测试决策

- 只测试从外部能观察到的行为：请求发进去，看返回的结果和数据库、存储里的变化。不测内部函数的调用方式和实现细节。
- 仓库目前还没有代码，也就没有可以参照的现有测试。下面两个测试边界是根据架构提出的建议，开发开始前需要再确认一次。
- 测试边界一：Worker 的 HTTP 接口。用 Cloudflare 的 Workers Vitest 集成在本地运行真实的 Worker，D1 和 R2 使用本地模拟。覆盖以下场景：
  - 注册：邀请码的各种状态（有效、已用、作废、过期），以及额度用完的情况。
  - 登录：密码、通行密钥、TOTP 分别登录，限流是否生效，Turnstile 何时触发。
  - 恢复：用恢复码重设密码，用重置链接恢复账号，恢复后旧会话是否失效。
  - 封禁：只封本人和连带封禁两种方式，封禁后续期播放 token 是否被拒绝。
  - 播放 token：签名被篡改、已过期、拿去访问别的文件、属于别的成员，这些情况都应该被拒绝。
  - Range 请求：返回 206 状态码，内容范围和字节数正确。
  - 观看进度和片单：增删改查，以及“已看完”的判定逻辑。
  - 访问控制：未登录时访问除登录页、注册页和静态资源以外的任何页面，都会跳转或被拒绝。
- 测试边界二：离线导入工具。用一份精简的样例 manifest、几个很小的样例视频和字幕文件，导入到本地的 D1 和 R2。验证数据是否正确写入、连续导入两次结果是否一致，以及格式不对的视频是否被拒绝。
- 备份定时任务：把 WebDAV 目标换成本地模拟服务，验证上传的内容是加密的，并且解密后能正常还原。

## 8. 范围外（后续版本）

- 限制每个账号的同时播放数。
