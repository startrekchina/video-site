## 1. 问题陈述

一个小圈子的《星际迷航》粉丝希望在同一个地方观看全部剧集和电影，按自己的节奏记录看到了哪里，并整理和分享片单。现有的观看渠道很分散，中文字幕和中文剧集资料不全，也没有只属于这个圈子的空间。

站长只能用业余时间维护，希望运维工作尽量少、每月花费可控，整套系统放在 Cloudflare 上。

## 2. 解决方案

建一个邀请制的私人观看站，片库、播放和成员功能只对受邀成员开放：

- 访客可以查看不展示片库的首页和关于页，以及登录、邀请码注册和账号恢复入口。
- 成员必须持邀请码注册，注册时提供邮箱并通过邮件验证，之后用用户名和密码登录，可以加上通行密钥和 TOTP 二步验证。
- 登录后可以浏览全部作品，按网格或首映年份时间轴查看剧集和电影，在线播放 MP4 视频，并切换中文或英文字幕。
- 站点自动记录观看进度，首页显示“继续观看”。成员可以收藏作品，也可以建立、排序和分享站内片单。
- 成员可以在单集或电影的播放页发表评论、回复和赞踩，讨论只对成员开放。
- 成员可以用邮箱找回密码，也可以修改注册邮箱并完成新邮箱验证，同时会收到封禁等重要安全事件的通知邮件。
- 管理员负责发放邀请码、封禁与解封成员、调整额度和角色，以及删除违规的评论和回复。忘记密码由成员通过邮箱自助重置。
- 站长在本地用离线命令行工具把视频、字幕和剧集资料导入系统。网站本身不提供内容上传或编辑功能。
- 站长可在网站内执行数据库备份，直接下载加密文件或保存到 WebDAV / S3；只有 Worker 环境变量指定邮箱的管理员拥有这项权限。

### 2.1 法律风险声明

《星际迷航》系列的版权归 Paramount 所有。本站的片源是站长自己持有的拷贝，但提供给其他人观看，在法律上仍然属于未授权分发。“非营利”和“粉丝向”都不构成免责理由。

Cloudflare 的可接受使用政策（AUP）禁止托管侵权内容。一旦收到 DMCA 投诉，可能导致内容下架、账号被封，以及 R2 中的数据丢失。站长已知晓并自行承担这一风险。

本项目不设计任何规避 DMCA 或检测的机制。访问控制只用于限定谁是成员。

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| 作品 | 一部电影或一部剧集（系列），和 manifest 中的一条主海报一一对应 |
| 季 | 剧集下的一季，有自己的季海报 |
| 集 | 某一季下的一集 |
| 可播放单元 | 可以直接播放的东西：一集，或一部电影 |
| 媒体文件 | 存在 R2 中、属于某个可播放单元的视频文件（v1 只有 MP4） |
| 字幕轨 | 挂在可播放单元上的一条外挂字幕（v1 为 VTT，分中文和英文） |
| 成员 | 邀请注册已完成、通过邮箱验证且未被封禁的用户 |
| 管理员 | 能管理成员和邀请码的用户 |
| 站长 | 本环境 `OWNER_EMAIL` 指定邮箱的正常管理员；网页备份权限只授予该账号，不增加第三种业务角色 |
| 邀请码 | 一次性的注册凭证，记录是谁发出的 |
| 邀请链 | 成员之间“谁邀请了谁”的关系，出问题时用来追溯和连带处理 |
| 邮箱验证 token | Better Auth 签名的限时邮箱归属证明；注册验证可在到期前重复确认，不承诺一次性消费 |
| 改邮箱待验证 | 已验证成员已提交新邮箱、但新邮箱尚未验证通过的状态；此时旧邮箱及旧邮箱找回仍然可用 |
| 待验证账号 | 已提交注册、但尚未通过邮箱验证的账号，不能登录成员功能 |
| 通知邮件 | 系统主动发出的封禁等安全提醒；不含管理员签发的账号重置链接 |
| 播放 token | Worker 签发的短期凭证，只对一个媒体文件有效，并绑定到具体成员 |
| 二步验证备用码 | Better Auth 的一次性第二因素备用码，需先通过密码阶段；不能用于重设密码，本文不再把它称为密码恢复码 |
| 重置链接 | Better Auth 发往成员邮箱的限时密码重置入口；提交新密码时一次消费，多个未过期链接可并存 |
| 片单 | 成员自己整理的有序作品或剧集清单 |
| 评论 | 成员在一个可播放单元下发表的讨论内容 |
| 对话 | 一条评论及其按时间排列的回复 |
| 赞踩 | 成员对评论或回复的赞同或反对反馈，与作品评分无关 |

## 4. 范围与规模

### 4.1 片库

片库以 `public/assets/posters/star-trek/manifest.json` 为准。v1 不开发“收录新内容”的功能，但数据模型要按通用的作品、季、集结构来设计，以后扩展时不需要改表结构。

- 电影 14 部：1979 年到 2025 年，包括《Section 31》。
- 剧集 13 部，共 52 季，约 950 集（集数为估算）：TOS、TAS、TNG、DS9、VOY、ENT、DIS、Short Treks、LD、PIC、PRO、SNW、Starfleet Academy。

| Workers 套餐 | Paid，已开通 |

### 4.3 前端原型对应的 v1 范围

当前原型提供 v1 的展示与交互参考；认证相关页面按 2026-10-06 确认的 Better Auth 方案调整。恢复码重设密码、管理员签发重置链接和匿名改邮箱不再纳入 v1。下表用于检查覆盖情况，原型旧流程不作为正式规则。

| 页面或能力 | v1 范围 |
| --- | --- |
| 访客首页 `/`、关于 `/about` | 桌面星图、手机登舰指南、邀请码入口、通行密钥和密码登录入口、站点说明与守则 |
| `/login`、`/register`、`/reset-password` | 用户名密码、通行密钥、TOTP 与备用码登录、邀请码注册和邮箱验证；旧 `/recover` 密码恢复页不迁移 |
| 邮箱验证 `GET /verify-email`、待验证提示页 | **原型没有**：验证邮件链接落地页、验证结果反馈、重新发送验证邮件入口 |
| 邮箱找回密码 `GET /forgot-password` | **原型没有**：提交邮箱、统一成功提示、邮件中的重置落地页 |
| 成员修改邮箱 `/account` | **原型没有**：已登录成员通过库原生改邮箱流程验证新邮箱，完成后替换旧邮箱；不提供匿名密码改邮箱 |
| 成员首页 `/` | 影院式推荐或续播舞台、继续观看刻度尺、收藏、剧集和电影分区 |
| `/series`、`/movies`、全站搜索 | 剧集和电影浏览、网格与首映年份时间轴、中文或英文作品名搜索 |
| `/title/:slug` | 作品资料、收藏和加入片单、季切换、带单集剧照和观看状态的选集列表 |
| `/watch/:unitId` | 播放、拖动、字幕、键盘控制、续播和观看状态、下一集提示、加入片单、评论与回复 |
| `/library`、`/playlists`、`/playlists/:id` | 收藏、片单创建和删除、条目增删排序、私有或站内公开、按顺序播放入口 |
| `/invites`、`/account`、`/admin` | 邀请、账号安全和会话、成员及邀请链管理、封禁与解封、额度与管理员身份；无管理员账号重置入口 |
| 跨页面交互 | 跟随系统或浅色/深色主题、响应式布局、手机搜索与菜单、回到顶部、快捷键、复制和操作反馈、404 页面 |

原型中的 PROTO 控制台、身份切换、虚构用户、模拟接口、固定密码和验证码、人为等待时间、自生成测试片段，以及已删除的设计比较方案，不属于正式产品功能。原型已有的加载、空数据、失败和成功反馈需要接入真实数据；已知缺陷不能作为正式版的预期行为。此前已确认但尚未在原型中实现的后端、导入和运维需求仍然保留。

## 5. 用户故事

### 5.1 访客与注册

1. 作为访客，我希望能查看不展示片库的首页、关于页，以及登录、注册和账号恢复页，了解如何加入；作品资料、搜索、媒体、观看记录、片单和讨论只对成员开放。
2. 作为访客，我希望用邀请码注册账号，这样只有受邀的人才能加入。
3. 作为访客，我希望邀请码无效、过期或已被使用时能看到明确的提示，这样我知道该去找邀请人重新要一个。
4. 作为访客，我希望注册时自己设置用户名、密码和邮箱，注册后收到验证邮件，验证通过才能使用成员功能，这样账号一定对应一个真实可联系的人。
5. 作为成员，我希望开启二步验证时取得一组备用码并妥善保存，这样遗失验证器后仍能在输入正确密码后登录。注册时不发放密码恢复码。
6. 作为搜索引擎的爬虫，我不应该收录本站的任何页面。

### 5.2 登录与账号安全

7. 作为成员，我希望用用户名和密码登录。
8. 作为成员，我希望绑定通行密钥，这样可以不输密码直接登录。
9. 作为成员，我希望开启 TOTP 二步验证，这样即使密码泄露，账号也不会被盗。
10. 作为成员，我希望认证入口有限流和人机验证，减少自动化注册、密码猜测和邮件滥用。
11. 作为成员，我希望能查看自己有哪些登录会话，并退出不认识的会话。
12. 作为成员，我希望能修改密码、重新生成二步验证备用码、解绑通行密钥或关闭二步验证，按 Better Auth 的密码确认和新鲜会话规则完成。
13. 作为成员，我希望在忘记密码时通过邮箱重设密码；遗失 TOTP 验证器时可用密码加二步验证备用码登录。
14. 原“管理员生成账号重置链接”故事移出 v1；邮箱、密码、验证器和备用码均不可用时，不承诺网页自助或管理员一键恢复。

### 5.3 浏览片库

15. 作为成员，我希望在首页看到“继续观看”，以及按剧集和电影分类的全部作品。
16. 作为成员，我希望在作品页看到中文标题、简介、年份和海报；中文资料缺失时显示英文。
17. 作为成员，我希望在剧集页按季浏览，每一集都显示标题、简介、时长、我的观看状态和一张小尺寸单集剧照；剧照仅用于非播放页的选集列表，缺失时显示同尺寸占位，不用作品或季海报替代。
18. 作为成员，我希望按作品名（中文或英文）搜索作品。
19. 作为成员，我希望在一部作品的季和集之间顺畅地切换。

### 5.4 播放

20. 作为成员，我希望点击一集或一部电影就能在网页里直接开始播放。
21. 作为成员，我希望可以随意拖动进度条，播放能马上从新位置开始。
22. 作为成员，我希望在中文字幕、英文字幕和关闭字幕之间切换。
23. 作为成员，我希望看完两小时的电影都不会因为凭证过期而中断。
24. 作为成员，我希望用键盘控制播放器（播放、暂停、快进、快退、调节音量、全屏）。
25. 作为成员，我希望一集播完后看到下一集提示，可以立即播放、取消倒计时，或等倒计时结束后继续播放；浏览器不允许自动播放时，应给我明确的手动播放入口。
26. 作为站长，我希望复制出去的视频地址很快就失效，而且只对原来的成员和这一个文件有效，这样链接被转发出去影响也有限。

### 5.5 观看进度与片单

27. 作为成员，我希望系统自动记住每一集和每部电影看到了哪里，下次打开时从那里继续。
28. 作为成员，我希望看到接近结尾时自动标记为“已看完”，也可以手动标记为已看或未看。
29. 作为成员，我希望在剧集页一眼看出哪几集已经看过。
30. 作为成员，我希望在不同设备上看到同样的观看进度。
31. 作为成员，我希望收藏作品。
32. 作为成员，我希望建立有序的片单（比如“TNG 必看 20 集”），片单里可以放作品，也可以放单集。
33. 作为成员，我希望把片单设为站内公开，让其他成员也能看到。

### 5.6 邀请

34. 作为成员，我希望看到自己还剩多少个邀请码，并能生成邀请码发给朋友。
35. 作为成员，我希望看到自己发出的邀请码是否已被使用，以及是谁用的。
36. 作为成员，我希望能作废还没被使用的邀请码。

### 5.7 管理员

37. 作为管理员，我希望生成邀请码不受数量限制。
38. 作为管理员，我希望调整每位成员的邀请额度。
39. 作为管理员，我希望查看成员列表，以及每个人的邀请人和被邀请人。
40. 作为管理员，我希望封禁一名成员，并可以选择连带封禁他邀请的人。
41. 作为管理员，我希望被封禁的成员立即无法登录，已经在播放的视频最多 30 分钟后停止。
42. 原“管理员重置成员账号”故事移出 v1；后台不签发重置链接，也不清除成员的认证设备。
43. 作为管理员，我希望把其他成员设为管理员，或取消管理员身份。

### 5.8 站长与运维

44. 作为站长，我希望在本地用一个命令行工具把视频、字幕和剧集资料导入 staging 或 prod 环境。
45. 作为站长，我希望导入工具能重复运行而不出问题：再跑一次只会补上缺少的部分，不会产生重复数据。
46. 作为站长，我希望导入工具在上传前检查视频格式，格式不对时明确提示我去重新转码。
47. 作为站长，我希望剧集标题和简介由导入工具从 TMDB 自动拉取中文和英文版本，不用我手动整理。
48. 作为站长，我希望 staging 和 prod 完全隔离，这样在 staging 上试错不会影响成员。
49. 作为站长，我希望在网页内备份数据库、查看结果，可以直接下载加密备份，或保存到 WebDAV / S3；其他管理员和成员不能使用这项功能。配置完整的 WebDAV 或 S3 目标后，我才可以设置自动备份的频率与执行时间；仅使用直接下载时不启用定时备份。
50. 作为站长，我希望每月的开销都在预算以内，不用盯着账单。

### 5.9 原型新增与细化的用户故事

以下编号接续原有 1–50，保留已有编号便于追踪。

51. 作为访客，我希望桌面首页展示星图、手机首页展示登舰指南，并能从首页使用通行密钥登录、进入密码登录或填写邀请码注册。
52. 作为访客或成员，我希望在关于页了解本站、加入方式、成员守则、隐私与数据、账号找回、版权说明和技术说明。
53. 作为成员，我希望首页用影院式舞台展示当前续播作品，并通过带进度的刻度尺切换或播放其他继续观看条目；没有记录时能看到推荐起点。
54. 作为成员，我希望在剧集和电影浏览页切换海报网格与首映年份时间轴，并从两种视图进入作品页。
55. 作为成员，我希望在单集或电影的播放页发表评论，用受限的 Markdown、表情和预览表达内容。
56. 作为成员，我希望展开评论的对话、回复评论或其中某位成员，并在切换对话时保留各自未发送的草稿。
57. 作为成员，我希望对评论和回复赞同或反对，再次点击可以取消；赞显示数量，踩仅参与排序、不显示数量。

## 6. 实现决策

本节保留已确认的产品行为，补充后端实现约束和接口草案。表名、字段名、接口路径用于指导迁移和 loader / action 开发，不要求照搬认证库的内部命名。第 6.13、6.16 节原列出的策略已确认；对应模块的实现与验证门槛见 6.16，已确认规则索引见 6.13。

### 6.0 邮箱验证与发信

#### 6.0.1 注册与邮箱验证

- 邀请注册必须填写邮箱，由 Better Auth 校验格式并按其小写化规则保证当前邮箱唯一。账号注册完成且 `emailVerified=true` 后，才能访问成员功能；待验证或注册未完成的账号没有片库、媒体或讨论权限。
- 注册采用 6.2.2 的持久化预留与完成流程。配置 `emailAndPassword.autoSignIn=false`、`requireEmailVerification=true`，并关闭库的 `sendOnSignUp` 自动发信，注册时不自动登录、不生成备用码；邀请码完成消费后才调用发信回调。完成的待验证账号保留用户名、邮箱和邀请码消费记录，不因长期未验证自动返还邀请码。
- 使用 Better Auth 原生签名验证链接，有效期默认 **1 小时**。原生 `GET /api/auth/verify-email?token=...` 可完成验证并跳转结果页，接受邮件预览器可能提前完成验证的行为；验证不承担密码重置或授予成员身份的作用。
- 普通注册验证配置 `autoSignInAfterVerification=false`，验证后由成员正常登录。注册验证重复点击在未过期且邮箱仍匹配时可幂等成功；不再要求数据库哈希凭证、一次消费或重发立即撤销旧链接。新旧未过期链接可并存，过期或签名不合法则失败。
- 邮件发送失败保留注册结果，提示可重发，按 6.0.3 记录发送结果；不得宣称服务商接受请求就代表已经送达。

#### 6.0.2 邮箱作为密码找回通道

- 使用 Better Auth `requestPasswordReset` / `resetPassword`，无论邮箱是否存在都给出同一成功提示。链接默认 **1 小时**有效；多个未过期重置链接可并存，不承诺申请新链接撤销全部旧链接。
- 设置 `revokeSessionsOnPasswordReset=true`。成功后只更新密码并撤销全部旧会话，保留 TOTP、通行密钥与未用二步验证备用码，不自动登录；仍开启 TOTP 的密码登录仍须第二因素。
- GET 检查链接并跳转 `/reset-password?token=...`，不消费重置凭证；POST 设置新密码时消费。D1 故障可能已消费链接但未改密，界面应允许重新申请邮件，不把多次库写入描述为原子事务（6.4.1）。
- 邮箱找回不能关闭二步验证或解除封禁。仅邮箱可用但验证器与备用码均遗失时，不能借密码重置绕过第二因素；已绑定通行密钥仍可用于登录。

#### 6.0.3 发信通道与限流

- 沿用站长已经购买的 Postal 发件服务，以 HTTPS API 和 `fetch` 接入 Better Auth 的验证/重置发信回调及站点封禁通知。API key 使用 Worker Secret `EMAIL_API_KEY`，不使用 SMTP，不重新选型。接口依据：[Postal API 说明](https://docs.postalserver.io/developer/api/)、[发信接口](https://apiv1.postalserver.io/controllers/send/message)。
- 请求实际服务的 `POST /api/v1/send/message`，使用 `Content-Type: application/json` 与 `X-Server-API-Key`；字段映射为 `to`（收件人数组）、`from`、`reply_to`、`subject`、`plain_body` / `html_body`。同时检查 HTTP 状态与 JSON `status`：HTTP 200 不代表业务成功，仅 `status=success` 记为服务已接受；`parameter-error` / `error` 按失败处理。从成功结果只提取必要的 `data.message_id` 作为服务商消息标识，不保存或记录完整回包中的收件人、token 或其他凭证；服务已接受不代表已送达。
- 每次操作最多一次发信请求，传输层单次等待默认 **10 秒**；失败或超时不自动重试，超时/连接中断记录为发送结果未确认。回调捕获并记录脱敏失败，避免注册结果随邮件失败回滚；成员可按配额手动重发。传输层不自动跟随重定向，避免 API key 发往其他地址。
- 验证（注册、重发、改邮箱）共用目标邮箱摘要的配额，密码找回单独计数：至少间隔 **60 秒**，滚动 **60 分钟最多 5 次**。首次、失败和超时发送尝试均计入；不存在邮箱的找回请求同样计数和反馈。此发信业务配额由 D1 条件写入保证，Better Auth 的 IP 限流不能代替它。
- 封禁通知不受站内发信频率上限限制；服务商套餐和 API 限额仍适用。发信失败不回滚封禁，不增加自动排队、主动失败告警或投递 webhook。
- 全部发件地址使用站长确认的统一发件子域，实际域名与地址仅保存在本机/平台配置。站长已提供 API 基础地址、配置 staging API key 并授权代理选择发件/回复地址；staging 使用测试发件人、production 使用正式发件人，Reply-To 指向同一收信地址。退信路径与收信记录已由站长配置，域名与 SPF/DKIM/DMARC 仍由站长维护；production Secret 尚未配置，配置声明不代替实际投递验证。真实地址与凭证不写入公开仓库。
- 仅邮件正文包含必要的限时链接；日志记录邮箱不可逆摘要、用途、请求 ID、结果及脱敏错误，不记录正文、完整 URL 或 token。必要异步发送纳入 Worker 请求生命周期，不使用未等待的后台 Promise。

#### 6.0.4 修改注册邮箱

- 仅已验证、注册已完成且正常的成员在登录后使用 Better Auth `changeEmail`。按库的敏感会话校验执行，配置 `changeEmail.enabled=true`、`updateEmailWithoutVerification=false`，不增加逐操作 TOTP 证明。
- 按库原生流程向新邮箱发验证邮件；新邮箱验证前保留当前邮箱及其找回能力。默认不另发旧邮箱确认邮件，不提供匿名 `username + currentPassword` 改邮箱路径。
- 待验证新邮箱保存在库签名链接中，不另建永久预占表；不承诺排他预占、新申请撤销旧申请或后台列出所有待处理申请。多个申请可并存，第一个成功更换当前邮箱后，绑定旧邮箱的其余申请失效。
- 替换时以当前邮箱唯一约束处理冲突，不允许与他人当前邮箱重复。失败或发送失败不提前改变旧邮箱，不改变成员 ID、邀请链、角色或业务数据。
- 改邮箱验证链接必须在该成员有效登录会话内打开；无会话先正常登录后继续。外层门禁避免库在异设备无会话的验证分支自动建立会话而绕过本站第二因素策略，不能只依赖 `autoSignInAfterVerification=false`。
- 接受库的改邮箱/重置链接关系：改邮箱不承诺撤销此前已发出的密码重置链接；原生重置凭证绑定用户 ID，未过期旧链接仍可能有效。成员应妥善保护旧邮箱及已收到的重置邮件，最长残留期受 1 小时链接有效期限制。

### 6.1 总体架构

- 全站使用 React Router v7 框架模式，前后端作为一个 Worker 部署在 Cloudflare Workers 上。页面的登录校验在服务端的 loader 中完成。
- D1 存放所有结构化数据，包括 Better Auth 用户、凭证、会话、验证状态与插件表，以及邀请码、剧集资料、观看进度、片单和讨论。Better Auth 是运行在本站 Worker 内的开源认证库，不使用其托管身份服务，用户资料保存在站长自己的 D1；关闭库 telemetry。发件服务仅接收投递所需邮箱和邮件内容。
- R2 存放媒体文件和字幕文件。R2 存储桶不公开，只通过 Worker 访问。
- 海报和非播放页选集列表使用的小尺寸单集剧照留在仓库的 `public/` 目录下，作为 Workers 静态资源公开访问，不需要登录。站长知道这样会让外人看出这是一个星际迷航站，并接受这一点。
- 单集剧照以 `public/assets/stills/star-trek/manifest.json` 为准，按作品 TMDB ID、季号、集号匹配，可为空。默认输出 240×135 的 WebP（质量 55），保留原始画面比例并补边；列表按小尺寸 16:9 展示，懒加载，加载失败时保留同尺寸占位。播放页的选集列表不显示剧照，视频时间轴的预览缩略图仍在范围外。
- 界面以简体中文为主，不做 i18n；保留原型中的英文作品回退资料、字幕语言名称、星图标注、等宽辅助标签和评论时间格式。
- 全站返回 `X-Robots-Tag: noindex`，并配置 `robots.txt` 禁止所有爬虫。公开访客页同样不允许索引。
- 原型既是页面和交互基准，也是前端代码的迁移来源。正式应用使用 React Router 框架模式和真实的服务端权限校验，优先沿用经审查的页面、展示组件、样式和已定稿交互，不要求全面重写前端；原型保留、迁移边界和验收遵循 6.15。

#### 6.1.1 服务端边界与公共约定

- 路由模块负责 loader / action 的输入输出，认证、D1 查询、签名、R2 和备份逻辑放在 `*.server.ts` 或 Worker 服务端模块。浏览器构建不能引用 Secrets、数据库绑定或对象存储键。
- 每个受保护的 loader、action 和资源路由都单独校验会话、成员状态和权限，不能只依赖父布局 loader；框架的数据请求、预取和直接 HTTP 请求也受同一规则约束。`userId` 和角色取自服务端会话，不接受客户端指定当前身份。
- 会话 Cookie 按 Better Auth 的签名不透明 token 设置，生产命名 `__Host-session`，使用 `HttpOnly; Secure; SameSite=Lax; Path=/` 且无 `Domain`。D1 按原生 schema 保存 token 原值，Cookie 签名 Secret 独立保管；不再要求哈希会话表。库 Cookie 名映射和本地 HTTP 开发例外须实测，不能把本地属性当作生产验收。期限与改密行为见 6.3.3。
- 站点业务写入走 action 或非 GET 接口，校验 Origin 与 `APP_ORIGIN`、Fetch Metadata，并保留业务 CSRF token。Better Auth 入口使用库原生 Origin / Fetch Metadata / SameSite 防护，不再强制附加自定义 `csrfToken`；服务端 API 的包装入口同样先完成跨站检查，不能以内部调用跳过防护。验证邮件 GET 是 6.0.1 明确的例外。trustedOrigins 限于本环境，同源凭证，不开放跨域媒体；回跳限定本站。
- 站点业务 JSON action 成功结构为 `{ data, requestId }`，失败为 `{ error: { code, message, fieldErrors?, challenge? }, requestId }`。Better Auth API 保留原生 JSON、状态码、Cookie 与重定向，认证客户端消费 `code/message`、二步挑战及库客户端类型；中文文案由前端映射，不把全部库端点重写成业务 action。页面表单可 `303` 回跳，媒体返回字节流。
- `400` 表示格式或字段不合法；`401` 表示未认证或凭证无效；`403` 表示已认证但权限不足、CSRF 或挑战未满足；`404` 表示资源不存在或不可见；`409` 表示已消费、版本冲突或额度不足；`429` 表示限流；依赖暂不可用返回 `503`，意外错误返回脱敏 `500`。限流提供可重试信息，不能泄露内部 SQL、栈、R2 key 或上游原始错误。
- 稳定错误码至少区分 `AUTH_REQUIRED`、`AUTH_INVALID`、`CSRF_INVALID`、`TURNSTILE_REQUIRED`、`FRESH_SESSION_REQUIRED`、`INVITATION_INVALID`、`INVITATION_EXPIRED`、`INVITATION_USED`、`INVITATION_REVOKED`、`QUOTA_EXHAUSTED` 和 `REVISION_CONFLICT`；前端按 code 处理，不解析中文 message。邀请码无效使用 `400`，其已用/过期/作废及额度不足使用 `409`。
- 受保护 HTML 页面未登录时跳转登录页；6.5 列明的公开页无需登录，受保护 JSON 和媒体接口返回错误。登录、邮箱找回保留库脱敏语义；注册可返回库的用户名/邮箱冲突码，不能承诺注册入口完全隐藏账号存在性。邀请码失败仍明确区分状态，不返回邀请人的私人资料。
- 登录态 HTML、loader 数据、认证 action、邀请凭证和媒体响应使用 `Cache-Control: private, no-store`，禁止共享缓存绕过鉴权。公开静态资源可以按文件版本缓存；静态资源、重定向、错误和媒体响应同样带 `X-Robots-Tag: noindex`。Workers 静态资源头与 Worker 生成响应头分别配置，不能假定其中一处覆盖另一处。
- 动态响应设置 `Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`。浏览器不接收内部 R2 key/URL、Worker Secrets、密码哈希或 TOTP 密文；必要注册/绑定/签发流程只向有权接收者给出凭证材料，站长专用加密备份文件下载按 6.9.4 单独鉴权。Better Auth 自己的登录/会话端点可返回原生会话 token，按敏感凭证处理；本站会话列表仅给设备信息与 ID，撤销时在服务端映射 token。日志只记录请求 ID、路由模板、状态、错误码及必要资源 ID，不记录 Cookie、密码、邀请码、备用码、TOTP、完整 token/URL；平台 URL 日志也须验证脱敏。

### 6.2 数据模型（概念层）

- 作品分为电影和剧集两种。剧集下有季，季下有集。电影和集统一抽象为“可播放单元”，播放、进度、收藏和片单都只和可播放单元或作品打交道，不用区分电影和剧集。
- 作品、季、集都记录 TMDB ID，中英文标题和简介分开存储。展示时优先用中文，中文缺失就回退到英文。
- 一个可播放单元对应一个或多个媒体文件，媒体文件记录格式、码率等属性。v1 每个单元只有一个 MP4，以后加 HLS 或多档码率时只需要增加记录。
- 一个可播放单元可以挂多条字幕轨，每条记录语言、格式和显示名称。v1 只用 VTT，以后接入 ASS 时不需要改表结构。
- 片单里的条目既可以是作品，也可以是可播放单元，并且保留排序。
- 邀请码记录发出人、使用人、状态和有效期。成员表记录邀请人，邀请链由这两者串联出来。
- 评论绑定到可播放单元和作者；回复绑定到所属评论和作者，并可记录被回复的成员。电影和单集使用相同的讨论结构。
- 赞踩记录绑定成员和评论或回复，同一成员对同一对象最多有一个当前反馈；可切换赞或踩，也可取消。

#### 6.2.1 字段与关系草案

#### 6.2.2 D1 写入与幂等

- 0009 迁移不自动转换旧密码或设备凭证：旧成员必须先经审查关联到相同 ID、用户名、邮箱与验证状态的原生用户，credential 记录须保留已转换的相同密码哈希，旧待邮箱与自定义临时/设备凭证表须为空。否则 `legacy_auth_requires_review` 拒绝执行并回滚；不能直接把旧哈希或密文视作原生兼容，也不为通过迁移删除未审查的数据。符合前置条件后保留业务资料、角色、封禁、邀请关系和稳定 ID，退役旧自定义认证表。当前工程尚无正式成员，真实成员的旧认证转换不在本迁移中自动进行。
- 站点业务输入使用参数绑定、版本化迁移、单条条件写入及 D1 `batch()`；不使用跨网络调用的交互式事务。条件更新 0 行不会自动回滚 batch，后续写入必须受同一成功条件约束或由约束拒绝整批。
- Better Auth 原生 D1 adapter 的多次认证写入不保证整个流程原子提交；不要求用自定义 adapter 改写其事务模型。正式实现必须接受并测试 user/account 部分创建、重置凭证已消费但改密失败等状态，保留可重试或可修复的结果，不能把异常包装成成功。
- 邀请注册采用三步：**D1 条件预留邀请码 → 调用库创建待验证认证用户 → 在业务原子批次中消费邀请码、建立邀请关联并标记注册完成**。预留默认 15 分钟，在预留期间不能被另一个尝试抢占；完成提交重新检查期限、发出人状态和封禁竞态。完成后才发验证邮件。
- 预留和部分认证记录可持久存在；失败不烧掉邀请码、不转为已用码的永久占用，发码阶段的原占用仍按 6.5.2 计算。重试以服务端尝试 ID 和同一归属继续，不能凭客户端 userId 认领他人的账号；已存在用户名/邮箱冲突不消费码。过期/失败预留在后续请求或本机运维中安全释放，部分认证账号保持无成员权限，清理不得删除已完成成员及其业务数据。不引入跨产品事务、异步队列或新的自动清理服务。
- 当前注册服务在调用库前持久化目标用户 ID，使用原生 `user.create.before` 钩子指定该 ID；只按该 ID 读取真实用户，不把用户名/邮箱相同或库的模拟成功响应视为归属证明。同一尝试令牌持有者可在邀请码仍可用、且没有其他有效预留时续作或续订过期预留；已有 credential 必须按库验证密码，缺失时仅给该尝试自己的未完成用户补建原生 credential，不覆盖已有密码，每用户最多一条 credential。HTTP 接入时令牌只通过 HttpOnly Cookie 传递，不进 URL、业务响应或日志。
- `0010_registration_ownership.sql` 的触发器让成员资料插入、邀请码消费和尝试完成在同一 SQL 原子边界内提交，重新校验期限、发出人正常状态、邀请关联和原生 credential；任何一步失败都回滚业务激活。原生用户/credential 仍可保留为无成员权限的部分记录，重试不创建第二个账号；直接注册参数不能指定角色、邮箱验证状态或目标用户 ID。注册服务已通过内部 D1 验证，HTTP 防护和发信回调未接入前不开放注册入口。
- 所有成员 loader/action、媒体、认证会话建立与认证设备绑定门禁均检查注册完成、邮箱已验证及正常状态。直接调用库 signUp 不能绕过邀请流程；不需要的注册、邮箱密码直登、账号删除、任意资料更新和 OTP 路径关闭或受同一服务端门禁约束。
- 原生邮箱 JWT 验证、改邮箱、密码重置和备用码消费按库行为执行，不承诺与邀请、设备处理或所有旧凭证撤销同批完成。密码重置撤销会话失败时保持可观察失败并重试撤销；所有新请求仍读主库，不能依赖缓存延迟。
- 发码、作废、额度调整、封禁、业务成员激活、片单重排等本站业务继续使用 D1 原子边界。发码以发出人/操作类型内唯一 `operationId` 防重扣，响应丢失不重复生成；不提供事后查询邀请码原值的接口。
- 进度、收藏按组合主键写入；片单修改以 `expectedRevision` 条件提交，失败整体拒绝，不能部分重排。
- 鉴权与一次性凭证读取走 D1 主库，不启用读副本或认证 Cookie 缓存。若以后用 Sessions API，合并鉴权查询作为 `withSession('first-primary')` 首次查询；成员状态还纳入敏感业务条件写入，防止封禁与提交竞争。

### 6.3 身份认证

- **2026-10-06 已决定采用 Better Auth**，按库原生能力调整认证需求，不再以满足旧自研认证契约作为采用条件。基线为 POC 锁定的 `better-auth@1.7.7` 与 `@better-auth/passkey@1.7.7`；正式工程已锁定依赖、完成原生认证表与业务资料增量迁移并验证配置探针，必要 HTTP 流程已接通并经本地集成测试，真实设备及平台验收仍待完成；升级须单独核对行为。
- 使用自有 D1 的原生 adapter、username、twoFactor、passkey 和 captcha 插件；本站负责邀请注册、角色、封禁、业务额度及授权。OAuth、邮件 OTP/魔法链接登录、受信任设备免二步、账号删除等额外能力不因库支持而加入 v1。
- **用户名**沿用 username 插件默认规则：3–30 个字符，ASCII 字母、数字、下划线和点号 `[A-Za-z0-9_.]`，小写化唯一；展示保存 `displayUsername`。不沿用旧 3–12 位或连字符规则，不开放成员改用户名。
- **密码**沿用库默认 8–128 长度校验，不强制字符组合，允许空白、中文与 emoji；不自行 trim，哈希/校验接受库的 NFKC 规范化。长度计数采用锁定版本字符串语义，前端与服务端一致。
- 使用库原生 scrypt（锁定版本 `N=16384, r=16, p=1`）及其盐/哈希格式，不注入旧参数或自建版本化哈希协议；Workers 兼容性和 staging CPU/内存/并发成本仍须验证。密码不存明文。
- TOTP 和备用码按库原生认证加密存储，使用本环境 `BETTER_AUTH_SECRET`，不再要求独立 TOTP Secret、成员 AAD 或自定义密钥版本字段；它不得与播放/备份密钥共用。认证 Secret 和加密数据由站长控制，轮换按 6.9.1。

#### 6.3.1 凭证与挑战

- 密码登录使用 username 插件。开启 TOTP 的账号先通过密码，再用 TOTP 或一次性备用码完成第二因素；配置 `twoFactorCookieMaxAge=300`，登录挑战 5 分钟有效、每挑战最多 5 次 TOTP 尝试。接受库内部先创建再删除瞬时会话的过程，但第二因素完成前不得向客户端授予可用成员会话。
- 沿用库的账号级二步失败锁定（锁定版本 10 次失败后锁定 15 分钟）和挑战消费；重新发起密码阶段不解除账号锁。TOTP 6 位、30 秒、±1 步容差；不要求自建 `lastAcceptedStep` 时间步账本，同一有效码在不同挑战中可能被再次接受，不能把挑战一次消费写成跨挑战防重放。
- TOTP 绑定经当前密码确认并以有效验证码启用；取得绑定 URI、重新生成备用码、关闭二步等采用库对应的密码确认规则，不增加逐操作 TOTP 证明。v1 不使用 `trustDevice=true`，服务端拒绝此选项；不启用邮件/短信 OTP。
- 通行密钥注册/登录使用库与其 WebAuthn 实现校验 challenge、用途、成员、origin、RP ID、签名、期限及计数器。本站固定本环境 origin/RP；不信任客户端用户 ID，credential ID 唯一。同步密钥的合法零计数器不视为封禁理由。
- 通行密钥登录不再附加 TOTP。为保留验证器用户验证这一安全边界，配置请求 UV，并在库 `afterVerification` 钩子拒绝 `userVerified=false`；1.7.7 仅设置 `userVerification` 不能证明服务端强制 UV，选项和服务端门禁已接入必要 HTTP，真实设备验收仍待完成。不自研 WebAuthn 或替换库挑战流程。
- 账号敏感操作沿用库的当前密码确认或新鲜会话校验；站点配置 `freshAge=300`（5 分钟）。新鲜度按会话创建时间，单独在旧会话调用 verifyTOTP 不使其变成新鲜会话。需要时正常重新登录，不签发绑定 operation/target 的自定义一次性证明。
- 查看/撤销会话限本人，本站 UI 使用会话 ID，服务端查出本人 token 再调用库撤销接口；库原生端点本身返回的 token 是凭证，不能进日志或其他成员数据。

#### 6.3.2 限流与 Turnstile

| 入口 | 规则 |
| --- | --- |
| Better Auth API | 显式开启库 rateLimit，使用 D1 `database` storage 和可信 Cloudflare 客户端 IP；键为 IP + 路径。基线全局 100 次/10 秒，sign-in/sign-up/change-password/change-email 各 3 次/10 秒，two-factor 各 3 次/10 秒，request-password-reset/send-verification-email 各 3 次/60 秒；保留锁定版本特殊路由规则。接受共享 IP 共用预算，不承诺账号摘要滑动窗口或全局严格额度。 |
| 邀请注册、用户名密码登录、密码找回、验证邮件重发 | 每次要求 Turnstile；使用 captcha 插件配置实际入口，注册包装入口先验证再调用库。传递 `x-captcha-response`，核对 allowedHostnames 与 expectedAction；不再维护“失败 5 次才出现”的自定义计数。通行密钥与第二因素本身不加人机验证。 |
| 成员发信 | 保留 6.0.3 的目标邮箱摘要 + 用途精确 D1 配额，叠加库入口 IP 限流。 |
| 播放 token 签发/续期 | 每成员 30 次/分钟，站点 D1 精确计数。 |
| 管理员 ban/unban/quota/role | 每管理员 30 次/分钟，站点 D1 精确计数。 |
| 媒体/字幕 GET、HEAD、Range | 不消耗认证、签发或管理配额；每次仍鉴权。 |

- 不只使用 Workers isolate 内存存认证计数。库的持久化限流可减少重启绕过，但不宣称等同本站原来要求的精确滑动窗口；业务额度和邮件配额仍用条件写入。
- 库 `429` 保留原生结构及 `X-Retry-After`，客户端据此提示；站点业务限流返回 `Retry-After`。Turnstile 缺失、伪造、重用、错环境/操作或服务不可用时拒绝，不绕过验证。
- 包装入口显式完成跨站检查、IP 限流及 Turnstile，不假定内部 `auth.api` 调用会自动执行 HTTP onRequest 插件。匿名注册不能通过另一个未保护库端点绕过。

#### 6.3.3 会话与改密

- 配置 `session.expiresIn=30 天`、`updateAge=1 天`，采用原生滚动会话；会话被库读取并达到刷新阈值时续到读取时刻后的 30 天。取消绝对 180 天上限及仅 HTML/页面 loader 续期限制。
- 页面、业务 API、播放鉴权等调用库读取会话均可能触发刷新；已过期会话不能续回。Cookie 的期限和更新时点由库管理，达到阈值可重发 Cookie，不逐请求换标识。
- 关闭 `cookieCache`，不使用 secondaryStorage、JWT 无状态会话或鉴权结果缓存。每个受保护入口同时读主库成员状态，封禁与会话撤销影响下一请求；媒体流截止仍按 6.6。
- 本站 0011 D1 触发器在 credential 密码更新的同一语句中删除全部旧会话；密码写入失败则旧密码和旧会话均保留。此保证不扩展为整个原生认证流程的事务。
- 正常改密码调用库 `changePassword` 并传 `revokeOtherSessions=true`。接受库删除旧会话后创建全新当前会话，换标识并重置创建/到期时间；不保留旧绝对期限。改密的多次写入不承诺同一 D1 原子批次。
- 退出、撤销和邮箱密码重置使用库会话删除语义。封禁必须立即阻止新会话建立及业务访问；会话清理即使失败，成员状态门禁也不得放行（6.5）。

### 6.3.4 采用决定与核对依据

2026-10-06 站长明确同意调整需求以适配 Better Auth。采用的是库原生认证流程与配置/插件接口，邀请与权限仍是本站业务；保留 UV、即时封禁、跨站防护和业务配额门禁，不以重写库核心实现旧三路径恢复或自管会话协议。

### 6.4 密码找回与二步验证备用码

- **忘记密码只使用邮箱重置**（6.0.2），不再提供“恢复码重设密码”或“管理员生成重置链接”。后台不清除成员设备，不代发重置邮件；邮箱与所有有效认证方式均不可用时，没有 v1 网页恢复路径。
- **二步验证备用码**由 twoFactor 插件在开启二步时生成，默认 10 个，库认证加密保存，后台持认证 Secret 可解密；不要求仅存哈希。它只替代密码登录中的 TOTP，不能单独重设密码、关闭 TOTP 或清除通行密钥。
- 使用一个备用码完成第二因素后该码失效，其余码及 TOTP 保持可用；重新生成需要当前密码，替换旧组。账号页展示保存提示，不在注册时生成，也不增加管理员读取原码的入口。
- 邮箱重置后撤销全部旧会话，不自动签发备用码、不撤销未用备用码、不清除设备；不同未过期重置链接可并存，已消费链接不能复用。封禁状态不受任何找回或备用码登录影响。

#### 6.4.1 原生流程的失败边界

- 沿用库的重置/挑战/备用码存储与消费，不建立三路径恢复事务。故障可能发生在凭证消费后、密码或会话写入前；错误不表示自动回滚，旧密码是否仍可用以实际库结果为准。
- 新密码提交失败时保留清楚的重试提示，链接已消费则重新申请邮件；本站触发器保证密码更新时旧会话已经撤销；原生后续清理或新会话签发仍可能失败。此时不能报告“密码未变”，应重新登录；链接已消费且状态不明时重新申请邮件。故障注入覆盖这些分支，具体处置通过集成测试后才勾选完成。
- 重置表单 GET 不消费凭证；邮箱验证 GET 可改状态（6.0.1），两类链接行为不能混写。所有链接/表单 no-store、no-referrer、不加载泄露凭证的第三方资源，日志脱敏。

### 6.5 邀请与权限

- 角色只有两种：成员和管理员。
- 未登录时可访问访客首页 `/`、关于页 `/about`、登录 `/login`、邀请码注册 `/register`、邮箱验证结果 `/verify-email`、等待验证提示页、邮箱找回 `/forgot-password` 和邮箱重置表单 `/reset-password`。公开认证 API 仍须按库与站点门禁校验凭证；二步备用码输入属于待二步登录流程，不是独立密码恢复页。改邮箱验证需要当前成员会话（6.0.4），待验证账号不能匿名改邮箱。
- 访客首页和关于页不展示海报、作品列表、片库统计、成员数据或讨论，访客不能打开会列出作品的搜索。直接访问受保护页面时跳转 `/login?next=…`，登录后返回原页面；相关数据和媒体接口在服务端独立校验权限。
- “站内公开”的片单仅向已登录成员公开；仅片单所有者可以修改或删除该片单。评论、回复和赞踩只允许有效成员读取或操作，作者和管理员身份由服务端确定。
- 管理员生成邀请码不受数量限制。普通成员的邀请额度按 6.5.2 的定义计算。
- 封禁一名成员时，可以选择只封禁他本人，或者沿邀请链连带封禁他邀请的人。封禁后该成员的所有会话立即失效，后续成员接口操作（含评论、回复和赞踩）被拒绝，已经签发的播放 token 最多 30 分钟后自然失效。
- 解除封禁是 v1 提供的独立管理员操作（故事 74），规则见 6.5.3。
- 封禁生效后向被影响成员的注册邮箱发送安全提醒邮件（故事 70）。通知邮件里只说明账号状态变化，不含讨论内容、片库资料或其他成员的邮箱/身份信息。发信失败不影响封禁本身的原子提交，封禁结果以服务端状态为准，不因邮件问题回退或部分回滚。

#### 6.5.2 首个管理员、邀请额度与连带边界

- **首个管理员不通过网页注册产生**：站长用普通邀请码注册并完成邮箱验证后，在本机用运维命令把该账号提升为管理员。**不开放 first-admin 网页注册入口**，也不提供通过注册参数把自己设成管理员的路径。
- 首个邀请码由本机初始化准备，`issuer` 可以为空。空 issuer 只用于这类 bootstrap 码，**不得假冒任何业务成员**，也不会出现在成员列表或邀请链的“邀请人”列里。
- 管理员完成高影响操作前需要绑定 TOTP，并使用 5 分钟内新建的有效会话；可通过密码加 TOTP/备用码或强制 UV 的通行密钥完成登录（6.5.1）。

- **邀请额度定义**：每位普通成员有 `total`（默认 `2`）和派生的 `occupied`。`occupied = used + validUnused`，即已使用数加有效未使用数；`available = total - occupied`。**生成邀请码即占用**；使用后永久占用，不因使用后的到期或成员封禁返还；**仅未使用码**作废或过期时释放占用。**没有周期补额**。
- 管理员为成员调整 `total` 时，**不得低于当前 `occupied`**；低于则拒绝并返回当前占用数，不截断既有邀请码。
- 邀请码**默认有效期 30 天**，可在生成时显式指定其他期限。
- 邀请码的“已过期”由签发时记录的到期时间派生，**不需要为每个到期码跑定时任务**；读取和校验时按当前服务端时间计算即可。

- **邀请码发出人被封禁时，其名下的有效未使用邀请码全部作废并释放占用**。注册的业务完成步骤与封禁在 D1 原子提交边界内重新校验：注册先提交时，只有 `cascade=true` 才将新普通后代纳入本次连带封禁；只封本人时新成员保持正常。封禁先提交时，两种模式均拒绝消费已被作废的邀请码。不能留下漏封后代或孤立邀请链。
- **连带封禁覆盖全部普通后代**：沿邀请链向下，封禁所有普通成员后代；**遇到另一个管理员即为边界**——该管理员本人不被这次封禁波及，其后代也不再继续向下连带。自封禁、末位管理员保护按同一原则适用（6.5.3）。

#### 6.5.3 管理员边界与解除封禁

- **网页端禁止管理员封禁自己或取消自己的管理员身份**，也不能让系统中的正常管理员数量归零。这条用 D1 条件写入在并发下保护：请求与状态变更在同一个原子批次内重新校验，条件更新影响 0 行即失败，不先读后写。
- 站长在本机做紧急处理（例如需要恢复站点可用性）属于**本机运维操作**，不经过网页端，也不受上述网页规则约束；本机工具的具体设计随 6.8 的离线工具确定，不在此扩展。
- **解除封禁**（故事 74）是独立的管理员 action：
  - 只能对**当前处于封禁状态**的成员执行；目标不存在或未被封禁时按统一语义拒绝。
  - **不连带解封**，只恢复这一个人。
  - **不恢复旧会话**，也不恢复已作废的邀请码；被解封的成员自己重新登录。
  - 邀请总额度 `total` 保持原值，`occupied = used + validUnused`，`available = total - occupied`；已用码仍永久占用，不能因解封返还。
  - **解封不额外发送通知邮件**；除上述已列规则外，本条不新增其他通知、撤销或连带行为。

- 片单条目的可播放目标在 v1 按原文仅开放单集，电影通过作品条目加入；不因底层使用统一单元就扩展收藏或片单的产品粒度。同一目标重复条目按 6.7.1.1 拒绝，顺序仍必须稳定。

- 邀请额度按 6.5.2 的 `total` / `occupied` 定义，通过 D1 条件写入保证，不用 Rate Limiting 计数器；调整 `total` 不得低于当前 `occupied`。没有周期补额，过期状态按到期时间派生，不为每个到期码跑定时任务。
- 管理员 ban、unban、quota、role 使用库原生新鲜会话语义（`freshAge=300`），前置要求管理员已绑定 TOTP。新鲜会话可由密码加 TOTP/备用码或 UV 通行密钥登录产生；不再要求每操作再输 TOTP、绑定目标或一次消费。删评和发邀请码不额外要求新鲜会话，仍校验角色、成员状态和业务 CSRF。首管由本机提升，库 admin 插件的任意用户管理/模拟登录/重置入口不对外开放。
- 新鲜会话门槛仅覆盖上述四项高影响操作，不扩大到邀请码发放或删评；库敏感会话校验不等于新鲜度校验，管理 action 必须实际按 `createdAt/freshAge` 检查，不能只写一个配置值。

### 6.6 播放与媒体分发

- v1 直接播放 MP4 文件，要求视频为 H.264、音频为 AAC，并做 faststart 处理（元数据放在文件开头，这样不用下载完就能开始播放和拖动）。不做 HLS，也不做在线转码。
- 成员打开播放页时，Worker 签发一个播放 token：
  - 用 HMAC 签名，内容包括成员 ID、会话、可播放单元、媒体文件 ID 和过期时间；
  - 有效期 30 分钟，播放页在到期前 5 分钟自动续期；
  - 续期和每次媒体请求都检查成员与当前会话状态，所以被封禁、退出或会话被撤销后最迟在 30 分钟内无法继续播放。
- token 放在媒体地址的查询参数里，因为 `<video>` 标签无法自定义请求头。Worker 验证 token 后，把浏览器的 HTTP Range 请求原样转给 R2，并返回 `206 Partial Content`。
- 字幕文件用**同一个播放 token** 访问，范围限于该可播放单元下已挂接的 VTT 字幕轨（6.6.1）。
- 播放器使用 ArtPlayer，支持外挂 VTT 字幕及中文、英文、关闭三档切换；键盘操作包括空格播放或暂停、方向键快进快退和音量、`F` 全屏、`M` 静音、`C` 切换字幕。
- 播放页提供上一集、下一集、当前季选集、手动标记已看或未看和加入片单。播完后显示下一集提示和可取消的倒计时；倒计时结束或点击立即播放时进入下一集并尝试播放，浏览器阻止自动播放时保留手动播放入口。没有下一集时不显示无效操作。从片单进入的播放按 6.7.2 继续队列，不在队列结束后回退到剧集自然下一集。
- 切换可播放单元时，读取该成员对目标单元的进度；没有记录则从头播放，不得沿用上一集的起点或把上一集的进度写入新单元。
- v1 不限制每个账号的同时播放数。以后要加这个功能，入口放在 token 签发和续期这一步，限额由管理员在后台随时调整。

#### 6.6.1 token 载荷与撤销边界

- token 使用 HMAC-SHA-256，格式草案为 `base64url(payload).base64url(signature)`；签名覆盖带用途前缀的载荷原始字节，不重新序列化后验签。载荷包含 `v, kid, environment, purpose, userId, sessionId, playableUnitId, mediaFileId, iat, exp`，`purpose` 固定为 `playback`，`exp - iat` 不超过已定的 30 分钟。`kid` 只从服务端允许的密钥版本集合选取，不接受客户端指定算法或密钥来源。
- `environment` 和用途前缀防跨环境/跨协议重用；每个环境的签名密钥独立。载荷不包含 R2 bucket、key、URL 或明文会话 token；ID 可读，签名并不加密载荷。
- 严格限制 token 长度和解码结构，拒绝不认识的版本、错误用途、异常时间及多余的重复 query 参数；以固定长度的签名字节用常量时间校验，不用字符串 `===`。验签通过前不查 R2、不向响应泄露对象元数据。
- 成员绑定在资源入口核对请求者的服务端身份，不能用请求体/query 的成员 ID 代替；请求者未登录或 token 的成员与请求者不同均拒绝。
- **媒体与字幕共用同一个播放 token（已确认）**：视频和该单元下**所有已挂接的 VTT 字幕轨**都用同一个 token 访问，因此取消按资源分别签发专用 token 的方案，载荷不再要求 `resourceType` 区分媒体与字幕。签发时该单元只允许一个 v1 MP4，token 绑定 `playableUnitId` + `mediaFileId` + 当时的 `userId` / `sessionId` / `environment`。
- 授权边界：媒体只授权载荷指定的 `mediaFileId`；同一 `playableUnitId` 下已挂接的 VTT 字幕轨允许共用 token。替换为其他媒体文件或其他单元的字幕 ID 时拒绝，不限制同单元中英文字幕之间的切换。
- **每次 GET / HEAD / Range 都做即时鉴权**：同源请求带 Cookie，token 的 `sessionId` 对应 Better Auth 会话 ID，合并主库检查会话有效、成员注册已完成/邮箱已验证/未封禁、用户与会话匹配。不再依赖自定义 `credentialVersion`；外部播放密钥 `kid` 承担恢复后的 token 世代隔离。退出、撤销会话、邮箱密码重置、改密换会话或封禁后，下一个媒体请求拒绝。不缓存鉴权结果，复制 token 给其他成员无效。
- 一次已开始的流不会因数据库改动自动收回已发出的字节。实现必须在 token 到期时停止继续输出并取消 R2 读取，避免无 Range 的长响应越过“封禁后最多 30 分钟”的上限；到期前签发的续期不延长旧流的截止时间，新的签发/续期重新检查状态。即时鉴权只影响新请求，已开启的流最晚仍在旧 token 到期时停止，30 分钟上限不变。

#### 6.6.1.1 播放 token 续期策略

- 播放页在 token 到期前 **5 分钟**请求同一签发 action 续期，接口重新鉴权并返回新的 token 与 `expiresAt`。
- 网络错误或 `503` 按 **5 秒、15 秒、30 秒**退避自动重试，**最多 3 次**；`401` / `403` **立即停止**续期并转登录或提示，不再重试。
- 到期前始终没有续期成功时，播放器**暂停并提示手动重试**，不静默停播，也不无限重试。
- 续期成功换上新授权后，要**保留播放位置、暂停/播放状态和字幕选择**，不得因为换 URL 而从头播放。
- 开发时用两小时以上的连续播放验证拖动、字幕切换和续期换 URL 的实际表现；不能假定换 URL 一定无缝，不能用短片段可播代替（见第 7 节）。

#### 6.6.2 R2 与 HTTP Range 契约

鉴权先于 HEAD、Range 判断、条件响应和任何 R2 读取。Worker 使用私有 R2 binding，将资源 ID 映射到 D1 中的对象键，不重定向到 R2，也不返回可绕过 Worker 的预签名地址。

| 请求 | 外部行为 |
| --- | --- |
| `GET` 无 Range | `200 OK`，流式返回整文件，`Content-Length` 为对象总字节数，不带 `Content-Range`。到 token 截止时间取消尚未发送的流。 |
| `GET` 单个有效字节范围 | 支持 `bytes=start-end`、`bytes=start-`、`bytes=-suffix`，把原始 Range 头交给 R2 的 ranged read，不能先取全文件再切片；返回 `206`，以实际返回范围计算头和长度。end 超出尾部时截断到文件末尾。 |
| 范围无法满足 | start 超出文件、反向范围或零长度 suffix 返回 `416 Range Not Satisfiable`，`Content-Range: bytes */total`，无媒体 body；总大小仅在授权通过后可见。 |
| 非法 Range / 未支持的范围形式 | 格式不合法返回 `400`；非 bytes 单位和有效的多范围请求在 v1 忽略 Range，按无 Range 返回 `200`，不声称支持 multipart，也不拼成错误的单段 206。 |
| `HEAD` | 经过相同授权，忽略 Range，`200` 返回完整 GET 的元数据和总长度，没有 body；用 R2 `head()`，不为了 HEAD 拉取视频内容。 |
| `If-Range` | 不能直接假定 R2 支持；Worker 校验 ETag/时间条件，匹配才保留 Range，否则返回完整 `200`。v1 可不实现其他条件缓存响应；任何条件响应都不能绕过鉴权。 |
| 文件缺失 / 方法不支持 | 缺失返回脱敏 `404`，记录资源 ID 供排查；其他方法返回 `405` 及 `Allow: GET, HEAD`，不开放浏览器上传。 |

- 成功响应设 `Accept-Ranges: bytes`；206 的 `Content-Range` 为 `bytes start-end/total`，`Content-Length = end - start + 1`。R2 对象 `size` 是总大小，不当作部分 body 长度；依据返回的 `range` 核对实际范围，不仅依据请求的 end。
- MP4 使用 `video/mp4`，字幕使用 `text/vtt; charset=utf-8`；字幕接受同样的资源鉴权和 GET/HEAD 规则。只复制允许的 R2 HTTP 元数据，再覆盖安全/缓存头，不能让上传的 `cacheControl` 变成公开缓存。
- R2 `body` 以流交给响应；增加截止时间/取消处理时也不能整体 `arrayBuffer()` 或缓存进内存。媒体不压缩、不改写字节，不能让 Content-Length 与 Range 语义偏离；客户端断开时取消上游读取。
- v1 不将授权媒体响应放进共享 CDN/Cache API；query token 和 Cookie 不能成为“忽略查询参数缓存”的入口。签发结果、200、206、416 和错误均按私密缓存边界处理。日志/追踪必须剔除 query 的 `token`、恢复凭证和 R2 下载地址；按当前官方文档，默认 invocation log 会记录请求 URL，若不能脱敏则关闭该项并保留白名单应用日志，部署前验证实际日志。

### 6.7 观看进度与片单

- 播放页定期上报播放位置（默认 15 秒一次），暂停和离开页面时也上报一次。进度存在 D1，按“成员 + 可播放单元”保存，所以换设备也能接着看。
- 播放位置达到总时长的 90% 就标记为已看完（默认值，可调）。成员也可以手动标记。
- “继续观看”显示成员最近看过、还没看完的可播放单元。如果一集已经看完，就推荐同一部剧的下一集。首页与作品页采用一致的续播规则，手动标记和按作品去重不得让仍有未完成记录的作品消失。
- 收藏只针对作品。片单是有序列表，条目可以是作品或单集，成员可以设为私有或站内公开。
- 成员可以创建和删除自己的片单，添加、移除或调整条目顺序；桌面提供上移和下移，触屏支持滑动排序，移除入口保留给键盘和读屏用户。
- 片单提供“按顺序播放”入口，正式版须按 6.7.2 的展开规则构建播放队列，不能替换成剧集的自然下一集。

#### 6.7.1 写入与读取约束

- 上报位置必须是有限非负数，不能超出服务端已知总时长；手动已看/未看与自动上报明确区分，不能把缺省 `completed` 当作手动“未看”。看完阈值读取集中配置。
- 所有进度、收藏及片单写入以当前成员限定 ownership。站内公开片单只返回片单及作品/单集概要，不带所有者的私人进度；私有片单不能通过条目 ID 绕过权限。
- **进度采用 `expectedRevision`（已确认启用）**：请求携带 `expectedRevision`，服务端条件写入并返回新的 `revision`；版本不匹配返回 `409 / REVISION_CONFLICT` 和当前 `revision`。
- 冲突后的客户端行为**已定**：拿到 `409` 的旧上报**直接丢弃，不自动重放**。只有用户继续观看产生新的播放事件时才发下一次上报，客户端**不做无限补报队列**。同时不采用“取位置最大值”，因此**正常回看到更小的位置可以正常保存**。
- **手动“标记未看”已定**：`positionSeconds` 归 `0`、`completed = false`，并让 `revision` 递增。已落库后的旧上报因版本不符被拒绝；此后用户真实观看重新达到 `90%` 阈值即可再次标记完成，**不存在长期的手动覆盖状态**。
- “下一集”按同一作品的季号、集号排序查询；只有实际已导入可播媒体的单元才能返回播放地址。跨季、缺集时如何提示仍由前端按既有产品行为处理，不伪造不存在的片源。

#### 6.7.1.1 片单条目去重

- **同一目标在一个片单内只能有一条**（唯一键为 `playlist_id` 加目标类型与目标 ID）。重复添加同一目标时**返回已存在的那一条**，不新增条目、**不改变它的顺序**；接口返回的仍是成功结果，客户端据此刷新列表。
- 作品条目和它下属的单集条目**允许同时存在**，这是两个不同目标；播放队列仍按 6.7.2 在展开后按可播放单元 ID 去重。
- 去重要靠数据库唯一约束 + 条件写入实现，**并发重复添加必须幂等**：并发请求最终只留一条，另一条返回同一已有条目，不产生重复行或顺序抖动。

#### 6.7.2 “按顺序播放”的队列展开

- 队列按片单条目的存储顺序逐条展开：
  - 电影作品条目对应该电影的可播放单元；
  - 单集条目对应其自身；
  - 剧集作品条目展开为该作品下按季号、集号排序的、已导入且可播的集。
- 展开后按可播放单元 ID 去重，同一单元只保留第一次出现的位置，后续重复项丢弃。
- 展开结果中已看完的单元被跳过，不进入播放队列。
- 未看完的单元从该成员自己的保存进度开始；没有进度记录时从头播放，不沿用队列中上一单元的起点。
- 若全部可播单元均已看完，停留在片单页并提示“已全部看完”，不进入播放页、不自动重播。
- 队列播放时，队列内下一个单元优先于剧集的自然下一集；队列到达末尾后不再使用剧集的自然下一集。
- 队列播完后停止，不继续自然下一集，也不循环回队列开头；停留在当前播放页，显示“片单已播放完”和返回该片单的入口。
- 队列展开后的按单元去重，只作用于播放队列结果；**写入侧**按 6.7.1.1 禁止同一目标重复条目。

### 6.8 离线导入工具

这是一个在站长本机运行的命令行工具，可以指定导入到 staging 还是 prod。它负责：

- 读取 manifest，建立作品和季的记录；
- 按 TMDB ID 拉取作品、季和集的中英文资料；
- 检查 MP4 的编码和 faststart 是否符合要求，不符合就报错，提示站长先在本地转码；
- 把字幕统一转成 VTT，其中 ASS 字幕会丢失样式；
- 上传媒体文件和字幕文件到 R2，并在 D1 中写入对应记录。

导入可以重复执行而不产生副作用：记录以 TMDB ID 或季号、集号为唯一键，已经存在的文件会跳过。网站本身不提供内容管理后台，TMDB API Key 只放在站长本地。

#### 6.8.1 输入、预检与断点重试

- 输入契约由明确的 `environment`（仅 `staging` / `prod`）、仓库 manifest 和本机媒体映射组成。媒体映射声明 `kind, tmdbId`，集再声明 `seasonNumber, episodeNumber`，以及仅本地使用的 `videoPath`、字幕 `language, displayName, trackKey, sourcePath`；不靠文件名猜作品或集号，不把本机绝对路径存入 D1。工具启动时展示目标环境并校验资源归属，缺配置或身份歧义立即停止，不能默认写 prod。
- manifest 约束 v1 可导入作品和季；季条目的 `tmdb_id + season` 映射到所属剧和季号，再从 TMDB 获取季/集身份。电影和剧集分别使用其 TMDB 类型，不以标题匹配。manifest 的 `file` 是 `.jpg` 原图名，页面海报引用必须映射到仓库中存在的 `.webp` 静态资产；本项目海报留在 public，素材 README 中“生产导入 R2”的旧描述不改变 6.1 决策。
- 上传前完成本地预检：MP4 容器有效、视频 H.264、音频 AAC，解析容器确认 `moov` 位于媒体数据 `mdat` 前而非仅看扩展名；记录时长、字节数和 SHA-256。失败给出具体文件与原因并提示先转码，工具不在线转码，也不自动上传不合格文件。
- 字幕先按既有规则转为 VTT，再验证 UTF-8、`WEBVTT` 头、cue 时间语法、开始不晚于结束、时间可解析和标签/文本可安全渲染；ASS 转换明确提示样式丢失，不能把 ASS 原文件发布给 v1 播放器。语言限中文/英文，同一轨道用稳定 `trackKey` 识别。
- TMDB key 仅从站长本机环境变量 `TMDB_API_KEY` 读取，禁止写进输入文件、上传清单或 Worker Secrets。中文缺失保留为空并回退英文，不能把两种文本覆盖为同一列；上游超时/限流可重试，不把失败写成成功的空资料覆盖已有记录。
- 顺序为“预检及身份确认 → 上传并验证完整 R2 对象 → D1 原子挂接记录”。D1 和 R2 没有跨产品事务；上传过程中不修改现有可播记录，不能让 D1 引用未完成对象。大文件 multipart 的 upload ID、分片进度及校验值保存在本机断点记录，完成后才发布；失效上传重新开始并处理未完成分片。
- 使用稳定逻辑唯一键和服务端生成的私密对象键防重复。本机检查发现 D1 与 R2 的长度/校验均吻合时跳过；R2 完整但 D1 未提交时可校验后补挂接，D1 存在而 R2 缺失时只补缺文件。相同身份却不同校验值必须报冲突，不能以“幂等”名义覆盖旧可播内容；替换既有媒体不在本次导入规则内。
- D1 提交失败时，v1 只保留完整且可验证的对象供重试，不在失败路径自动删除对象。如需清理，必须暂停导入并排除并发挂接后另行操作，不能仅凭一次“无引用”检查删除对象。中断后从本机记录和 D1/R2 实际状态重建进度，不相信单一“已上传”标志。最终报告已导入/已跳过/冲突/失败的逻辑 ID 和数量，不输出凭证或远端私密路径；私密路径仅存在本地配置、内部 D1/R2 数据，不进公开仓库或浏览器。

### 6.9 环境与备份

- staging 和 prod 是两套完全独立的资源，各自有自己的 Worker、D1 和 R2。
- D1 利用 Time Travel 功能，可以恢复到最近 30 天内的任意时间点。
- 备份先调用 D1 导出 API 并存入私有 R2，再加密供直接下载或上传 WebDAV / S3。配置完整的 WebDAV 或 S3 目标后，站长可在网页设定自动备份频率和执行时间，由 Worker 定时入口执行；没有外部目标时仅支持手动备份，不启用定时备份。导出包含密码哈希和 TOTP 密钥，必须加密后才能离开 Cloudflare。备份默认保留 30 天。
- 网页数据库备份纳入 v1，提供直接下载、WebDAV 与 S3 三种目标，仅本环境 `OWNER_EMAIL` 指定的管理员可操作（6.9.4）；直接下载和外部存储均使用加密备份。
- WebDAV 地址必须能从公网通过 HTTPS 访问，最好用 443 端口。如果它在家里的 NAS 上，推荐用 Cloudflare Tunnel 暴露出来，不需要在路由器上开端口。
- Cloudflare API Token、WebDAV / S3 目标与凭证、备份加密密钥都存在 Worker Secrets 里；指定站长的 `OWNER_EMAIL` 使用 Worker 环境变量，不向浏览器公开。
- 视频原片只在站长本地冷备份，不存第二份云端副本。

#### 6.9.1 绑定、Secrets 与集中配置

每个环境分别配置下列逻辑名称，实际资源标识和值不写入公开仓库。本项目统一使用 `cf` CLI 创建项目、本地开发、部署和管理 Cloudflare 资源，不再使用 Wrangler，也不以 `npx wrangler` 替代。执行前先查 `cf --help` 或 `cf cli search <想做的事>`，确认命令、参数和目标环境；如引入已有 Wrangler 配置，按 `cf migrate` 的当前帮助迁移。`cf` 缺失、不支持所需能力或命令失败时记录原因并告知站长，不自行回退到 Wrangler，不在本文猜写 CLI 或配置方式。

#### 6.9.2 定时备份执行与失败行为

- **调度条件与设置**：只有本环境 WebDAV 或 S3 目标配置完整，站长才可以在网页设置并启用备份频率与执行时间。时间以**北京时间（Asia/Shanghai）**展示和保存，执行时换算为 UTC；不再固定每日 04:00。仅使用直接下载或只有私有 R2 暂存时不能开启定时备份；未设置启用时不自动运行。定时入口每次重新检查所选外部目标，目标配置失效时不继续导出或报告成功，网页展示不可执行状态。导出造成的维护/查询影响仍是已知代价，应随所设执行时间向站长说明。

1. 定时入口按本环境已启用的频率与时间发起全量 D1 SQL 导出，包括 schema 和全部业务数据；导出无法通过普通 D1 binding 替代。当前官方 API 是 `POST /accounts/{account_id}/d1/database/{database_id}/export`，首次使用 `output_format: 'polling'`，之后以返回的 bookmark 填入 `current_bookmark` 持续轮询同一任务，直至完成或失败；不能伪造同步 dump API。
2. 导出期间数据库可能无法服务查询，持续轮询中断时平台会取消导出。不得将仍在执行的导出留到下一次定时触发才继续。完成后及时读取返回的短期 `signed_url` 并流式存入私有 R2 备份对象；不能把下载 URL 返给浏览器、写日志或交给 WebDAV / S3 抓取。
3. R2 记录本次备份 ID、环境、备份时间、导出 bookmark、schema 版本、长度和 SHA-256；只有完整写入并校验后才标记 R2 完成。备份控制状态可放在私有 R2 元数据/伴随记录，不因此追加业务表；重试复用已验证的备份 ID，避免重复导出和混淆日期。
4. 从 R2 加密后上传所选 WebDAV / S3 目标：WebDAV 用 HTTPS `PUT`，S3 用 HTTPS S3 兼容 API。采用带版本的认证加密封装（建议 AES-GCM；若分块，每块独立唯一 nonce、认证序号/总块数，并验证最终完整性）；大小不得要求整个 SQL 常驻内存，采用有界缓冲/流处理。目标只能来自 Secret，不跟随把授权头带到其他主机的重定向。**只有 R2 完成、加密完整、所选外部目标上传成功并回读校验通过后，才记录该目标“备份完整成功”。**
5. **上传后回读校验（已确认）**：`PUT` 成功后再用 HTTPS `GET` 把对象**流式读回**，校验**长度和 SHA-256** 与本地记录一致。**ETag 不能代替内容哈希**校验。回读可能耗时，按实际耗时在 staging 实测并纳入 15 分钟时限评估（6.16）。
6. 导出/R2/WebDAV/S3 任一失败都不创建对应成功标记：保留完整 R2 副本和**脱敏失败记录**，由站长**人工触发重试**。**不设置自动重试调度，也不做主动失败告警。**
7. **保留策略**：默认保留 `30 天`，但**每一端（R2、WebDAV 与 S3）的最后一份完整可恢复副本受保护、可超过保留期不被删除**。清理绝不触碰媒体对象，备份与媒体清理前缀严格隔离；清理失败可重试，不把部分失败当作已删除。

Cron 当前最长执行时间为 15 分钟，导出轮询、加密、上传和回读校验的全流程都要在这 15 分钟内实测；必须整体由 scheduled 生命周期等待，不依赖 HTTP 返回后 30 秒的 `waitUntil`。必须在 staging 测量备份大小、耗时和内存，并验证按网页所设频率/时间正确触发；若全流程装不进单次时限，**报告站长**决定调度或恢复办法，**不擅自引入 Queues、Workflows 或其他新产品**。

#### 6.9.3 手动恢复顺序与完整性

1. 站长选择正确环境及恢复点，**先暂停该目标的写入和导入，并保留当前状态所在的旧库**（不先删、不先覆盖），再执行恢复。
2. **默认恢复目标是隔离的 D1 目标**：先恢复到隔离目标并完成校验，通过后才切换。**Time Travel 的隔离能力不作假定**——按官方现有能力核实后再决定；**若无法构建隔离目标，如实报告站长，不自行对生产库做原地覆盖恢复。**
3. 优先按事故选择 Time Travel 或完整备份。网页下载、WebDAV 或 S3 副本须验证密文认证、备份元数据、长度和校验，先在 Cloudflare 内解密到私有对象再导入；不在本机下载未加密 SQL，不让包含密码哈希/TOTP 数据的明文副本离开 Cloudflare。
4. SQL 恢复使用当时官方支持的导入流程。当前 D1 REST import 为 `init → 上传 SQL → ingest → poll`，参数和临时地址以官方响应为准；上传及轮询在 Cloudflare 内完成，不能把 SQL 文本交给站长本机 CLI 作为中间明文文件。在隔离目标确认 schema 兼容、外键完整、业务计数与摘要一致后，再执行目标切换。
5. 验证 `media_files` 和字幕关联的 R2 对象确实存在且长度/校验匹配；**恢复 D1 不会恢复 R2 媒体，也不会恢复 Worker Secrets**。缺媒体时需从站长本地冷备及字幕原件重新导入；尚未补齐的文件保持不可播，不先开放错误地址。
6. **重新开放前统一撤销**：删除旧 Better Auth 会话、临时 verification 记录并撤销未使用邀请码及全部二步备用码；切换外部播放签名密钥和认证签名 Secret，使恢复点带回的播放 token 与邮箱 JWT 失效。切换认证 Secret 前在 Cloudflare 内以旧 Secret 解密并重加密保留的 TOTP，备用码以库可识别的空组作废；验证完整后才切换，不靠已恢复的数据库版本计数拒绝旧凭证。密码哈希与通行密钥按恢复点保留，TOTP 设备保留；恢复可能带回后来解绑的设备，重开前由站长复核。此运维步骤尚待实现和演练。
7. **角色与封禁状态由站长逐条复核**；无法确认的账号保持**维护状态**而不是直接放行。
8. **邀请码**：恢复出的全部未使用码撤销后，`validUnused = 0`，`occupied = used`，`available = total - used`；已用记录仍占额度，不因恢复返还（6.5.2）。
9. **旧讨论（已确认做法）**：恢复点中的历史评论和回复**照原样恢复**，不做自动识别或自动清理。维护期间由管理员**人工 review 并重新手动删除**需要移除的内容。**不引入隐藏标记、软删除、删除 ID 台账，也不批量清空正常讨论**；**接受无法自动识别全部历史删除**这一事实，**不宣称历史备份或恢复点已被擦除**。

#### 6.9.4 站长专用网页备份

- **身份判定**：每个页面、状态接口、创建/重试、定时设置及下载请求都在服务端核对有效 Better Auth 会话与当前 D1 身份：邀请注册已完成、当前邮箱已验证、未封禁、角色为 `admin`，且当前邮箱按注册邮箱规范化规则与本环境 `OWNER_EMAIL` 完全匹配。不信任客户端传入的邮箱、角色或界面隐藏状态，不增加 `owner` 角色或首个登录者自动成为站长的规则。
- **即时失效**：管理员降权、封禁、退出、撤销会话、验证后更换邮箱或 `OWNER_EMAIL` 配置生效后，下一个请求重新判定权限。邮箱不再匹配的原站长不能继续访问备份；仍匹配邮箱的普通成员也无此权限。
- **页面与操作**：站长在站内备份页查看当前环境、备份列表与状态，手动创建备份，选择直接下载、WebDAV 或 S3，并对失败的任务手动重试。普通成员、其他管理员与访客不显示入口，直接调用接口仍被拒绝。写操作带业务 CSRF，页面及下载响应均 `noindex` / `no-store`。
- **共用流程**：网页与定时备份复用 6.9.2 的 D1 全量导出、私有 R2 完整性校验、版本化认证加密与脱敏失败记录。仅下载不要求同时上传 WebDAV / S3；已校验的完整 R2 副本可复用，外部上传失败不重新导出已完成的数据库。手动导出前明确提示成员查询可能受影响，不能暗示导出完全无维护影响。
- **直接下载**：Worker 仅返回本环境完整且经过校验的加密备份文件，不把未加密 SQL、R2 对象路径、D1 `signed_url` 或长期凭证交给浏览器。浏览器保存的是可恢复的加密文件，所需历史密钥由站长按 6.9.1 独立保管，不附在下载文件中。
- **WebDAV / S3**：目标及凭证只从本环境 Worker 配置/Secrets 读取，网页只选择目标类型，不接收任意远端 URL 或凭证。WebDAV 按 6.9.2 的 HTTPS PUT/GET 处理，S3 使用 HTTPS S3 兼容 API；上传后均流式回读并校验长度与 SHA-256，ETag 不代替内容校验。目标缺配置时明确不可用，不影响其他已配置目标；按所选目标分别展示完整/失败状态，不把部分成功报告为全部成功。
- **定时设置**：只有 WebDAV / S3 目标配置完整后才提供可用的频率与执行时间设置；仅下载时禁用并说明原因。服务端对启用请求执行相同校验，不能靠伪造表单绕过。设置只作用于本环境，可关闭定时备份；频率/时间与启用状态保存在私有备份控制记录，不因配置调度新增业务角色或公开凭证。
- **保留与失败**：私有 R2、WebDAV 和 S3 的各端保留策略均按 6.9.2 保护最后一份完整可恢复副本；站长自行下载的本地文件不由 Worker 清理。失败由网页展示脱敏结果并人工重试，不新增自动重试或主动告警。媒体冷备和 6.9.3 的隔离手动恢复流程继续适用，网页备份不包含一键覆盖生产库的恢复功能。
- **实现门槛**：先完成第三阶段真实认证与管理员门禁，再在第六阶段实现备份页与处理流程。网页触发任务的执行生命周期、中断和重试行为须在 staging 验证，不能依赖请求结束后短暂的 `waitUntil` 完成整次导出，也不未经确认引入新 Cloudflare 产品。

平台行为核对于 2026-10-04，开发时按实际兼容日期再核实：[D1 batch / Sessions](https://developers.cloudflare.com/d1/worker-api/d1-database/)、[外键](https://developers.cloudflare.com/d1/sql-api/foreign-keys/)、[R2 ranged read / If-Range 边界](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)、[Rate Limiting 一致性](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)、[node:crypto](https://developers.cloudflare.com/workers/runtime-apis/nodejs/crypto/)、[D1 export](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/export/)、[D1 import](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/import/)、[Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)、[Workers 执行时限](https://developers.cloudflare.com/workers/platform/limits/)、[URL invocation logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)。

### 6.11 页面与跨页面交互

- 视觉方向、基础 token、版式和响应式验收遵循 6.14；本节规定页面内容与跨页面交互。
- 访客首页在桌面展示星图和标题栏，在小于 768px 的视口展示登舰指南。星图属于装饰，不要求位置具备考据准确性；手机指南包括欢迎语、邀请码入口、加入三步、成员能力、守则和常见问题。首页的邀请码输入传递到注册页，成员登录提供通行密钥入口和密码登录链接。
- 关于页包括本站介绍、如何加入、成员守则、隐私与数据、找回账号、版权说明和技术说明；宽屏提供本页导航。版权说明保留《星际迷航》版权归 Paramount 所有的声明，并展示站长接收下架请求的公开联系邮箱 `contact@startrekchina.org`（这是站长自己的联系方式，不是 Paramount 官方渠道）。该邮箱只作展示，不引入邮件登录或站内发送系统。
- 成员首页以影院式舞台展示当前作品、单集、简介、海报、进度和继续播放入口；刻度尺展示其他继续观看条目及上次观看时间或“下一集”。点击未选中条目切换舞台，点击已选中条目播放；超宽条目可以横向滑动。新成员无观看记录时展示三个推荐起点，由站长通过配置文件维护，不增加网页管理功能；首版依次为 SNW、TNG、TOS 的第一季第一集，调整随部署生效。配置映射到正式片库的可播放单元，原型 ID 仅作参考。
- 剧集和电影页提供海报网格与按首映年份排列的时间轴两种视图，均可进入同一作品页。作品页保留资料、收藏、加入片单、季切换、逐集观看状态和单集剧照；中文资料缺失时回退英文。
- 成员搜索支持中文和英文作品名，并可用 `Ctrl+K`、`⌘K` 或 `/` 打开；`D` 切换深浅色。手机底部提供搜索和菜单胶囊、回到顶部按钮。访客菜单不展示受保护入口或作品搜索结果。
- 页脚提供跟随系统、浅色和深色三档主题选择；导航、页脚和页面内容在不同宽度下保持对齐。手机的固定导航、底部安全区、顶栏和播放器控件不得遮挡关键操作。
- 保留原型中账号页的宽屏分节导航、季选择和长列表的滚动提示、复制按钮、异步操作反馈及 404 页面。按钮、弹层、滑动条目和表单需要保留键盘和读屏可用性；文本输入时字母快捷键不触发站点操作。系统开启减少动态效果时，跳过平滑滚动、淡入和高亮动画。
- 原型中的数据刷新即重置、签发 token 文案和模拟加载不能作为正式行为；持久化、凭证校验、加载失败和重试应由正式前后端共同完成。

### 6.12 播放页讨论

#### 6.12.1 位置与对话

- 每个可播放单元有独立讨论区。单集放在选集列表下方，电影放在简介下方，标题分别为“本集讨论”和“本片讨论”，显示讨论总数；无内容时显示空状态。
- 1024px 及以上采用双栏：左栏为发评论输入框和评论列表，右栏为当前评论、回复及固定在对话底部的回复框。默认选择第一页第一条评论，点击评论空白处或回复数量可以切换对话，点击正文链接或选择文字不触发切换。
- 右栏按原型吸顶并内部滚动，标题和回复框保持可见；小于 1024px 时改为单栏，点击回复数量在评论下方展开或收起对话。
- 回复按时间正序排列。回复某位成员时显示“回复 @用户名”，可点关闭按钮取消；空回复框按 `Esc` 返回回复评论作者。点回复时聚焦输入框，并滚动到不被顶栏和底部导航遮挡的位置。
- 显示作者、当前成员和管理员等原型标签，长正文可以展开或收起。评论时间保留原型的等宽英文格式：7 天内用相对时间，更早用日期，跨年加年份；悬停显示完整时间。

#### 6.12.2 输入、发送和草稿

- 评论和回复正文上限默认 1000 字，提供工具栏、表情、Markdown 速查、预览和字数反馈。Markdown 支持粗体、斜体、删除线、代码、引用、列表、链接和分隔线，回车换行；不支持图片、表格和 HTML。
- 站外链接新窗口打开并带 `nofollow ugc`，同时防止新页面控制原窗口；`//host` 视为站外，`javascript:` 等危险协议不生成可点击链接。限制不能仅依赖前端编辑器，服务端须验证正文及长度，渲染须避免注入脚本。
- 发送按钮和 `Ctrl+Enter` / `⌘Enter` 使用相同行为。发送期间显示状态，锁定输入、工具栏、表情和预览以防重复提交；状态通过 `role=status` 向读屏播报。
- 发新评论后保持当前排序和正在看的对话，把新评论置顶并提示其位置；新回复展开到末尾并滚动到可见位置。系统启用减少动态效果时不闪烁或平滑滚动。
- 各对话的未发送草稿独立保存，切换对话或跨越宽窄屏断点不丢失。发送途中切换对话时，回复仍发送到原目标，返回时保持其发送状态；只有发送成功才清空对应草稿，失败时保留内容并允许重试。跨设备或刷新后的草稿同步不由本条要求。

#### 6.12.3 赞踩、排序与分页

- 评论和回复支持赞或踩，再点同一反馈取消，切换反馈替换原反馈。赞显示数量，踩不显示数量、仅参与智能排序；服务端保证一名成员对同一对象最多一个当前反馈。
- 评论提供智能、最新、最早三档排序；智能排序沿用原型按赞踩置信度与讨论参与度计算的规则，以原型为算法参考，不引入作品评分功能。选定排序时形成稳定列表，赞踩不会立即打乱当前阅读顺序。
- 评论默认每页 10 条，回复默认每批 10 条。评论和回复关联、数量、作者、时间及赞踩结果持久化到 D1；刷新或换设备后仍可读取。
- 管理员删除评论与回复已纳入 v1，规则见 6.12.4。成员自助编辑或删除、举报、其他审核与恢复工具、剧透遮罩和评论时间码跳转仍在范围外，不因删评纳入而自动加入。

#### 6.12.4 管理员删除评论与回复

- v1 只提供管理员删除评论和回复的入口，不提供成员自助编辑或删除、举报，以及审核/恢复后台。
- 删除顶层评论时，在同一次原子提交中从当前业务数据库移除该评论、其全部回复，以及评论和这些回复的赞踩记录。正文和记录一起删除，不保留软删除标记、删除占位或正文归档。
- 删除单条回复时移除该回复及其赞踩记录，不删除顶层评论或其余回复。回复仍是同一对话中的平铺列表，不另建嵌套回复树。
- 被删内容不再出现在列表、对话或直接读取接口中，也不计入讨论数量、回复数量、智能排序或分页。访问已删除目标，以及向其发送回复或赞踩，返回脱敏 `404`。
- 删除成功后，当前页面移除对应评论或回复；若当前选中的对话已被整段删除，清除其展示和回复入口，按剩余内容更新计数及分页，不留下删除占位。
- 删除与新增回复、赞踩并发时，不得留下孤立回复或反馈：删除前已经提交的关联记录一并移除，删除后提交的新回复或赞踩因目标不存在而失败。删除批次失败时不得留下部分删除的对话，也不得报告成功。
- 封禁成员默认保留其已有讨论记录，不因封禁自动删除评论或回复。
- 服务端按 6.5 的权限与归属校验执行删除，并沿用统一的 CSRF 校验；删除接口不能绕过认证、管理员权限或可播放单元归属检查。
- 上述删除范围是当前业务数据库和站点读取。删除前的备份及 D1 Time Travel 恢复点**仍可能含有旧数据**，不能把业务记录删除宣称为历史备份已被擦除。**恢复点中的历史讨论照原样恢复**（6.9.3），这类情况由管理员在维护期间**人工 review 并重新手动删除**；不引入隐藏标记、软删除或删除 ID 台账，也不清空正常讨论。

## 7. 测试决策

- 只测试从外部能观察到的行为：请求发进去，看返回的结果和数据库、存储里的变化。不测内部函数的调用方式和实现细节。
- 已有正式工程的 Workers Vitest runner、D1 约束与 HTTP 测试，以及前端基础浏览器验收；覆盖进展见 PLAN.md，不表示全部业务已实现。测试边界包括 Worker HTTP 接口、离线导入工具和浏览器中的用户流程；正式开发应将原型行为与本文规则转为可观察的验收，模拟身份或内存数据通过不代表后端已验证。
- 测试边界一：Worker 的 HTTP 接口。用 Cloudflare 的 Workers Vitest 集成在本地运行真实的 Worker，D1 和 R2 使用本地模拟。覆盖以下场景：
  - 注册：原生 username 3–30 位 `[A-Za-z0-9_.]`，大小写冲突、点号可用/连字符拒绝；密码 7/129 位拒绝，空白/中文/emoji 可用，NFKC 行为与长度语义一致。邮箱必填且唯一。并发邀请码仅一个完成成员，预留过期/库部分创建/冲突/业务提交失败可重试且不烧码，未完成记录无权限；无注册会话或备用码。
  - 邮箱验证：原生签名、1 小时有效、GET 完成、普通注册验证幂等重复、重发旧链接可并存；过期/签名错拒绝，注册验证后不自动登录。待验证/注册未完成账号无成员访问。发信失败保留完成注册，计数和结果不泄露凭证。
  - 登录：用户名密码、通行密钥、TOTP/备用码第二因素；密码阶段未授予成员会话，拒绝 trustDevice 与未纳入 v1 的 OTP/邮箱密码/公开 sign-up 绕过路径。通行密钥验证 origin/RP/用途/签名/UV/计数器；锁定版本 request UV 不代替服务端钩子。TOTP 按原生挑战/锁定规则验收，记录不同挑战复用同一码的边界，不假称全局时间步防重放。
  - 会话与改密：30 天滚动到期、每日刷新阈值，页面与 API 读取均可能续期且 Cookie 同步，持续使用可超过旧绝对上限；过期不能续回。Cookie 属性、禁用缓存、即时撤销/封禁有效。普通改密删除旧会话并建立全新当前会话，其他会话失效；注入各写入失败验证实际状态及重试。
  - 密码找回与备用码：邮箱重置 1 小时、POST 一次消费、GET 不消费、成功不自动登录/撤销全部旧会话/保留 TOTP、通行密钥和未用备用码；多个有效链接可并存，已消费不可重用。备用码需正确密码，只完成二步，消费一枚不清设备、重生成旧组失效；旧恢复码重设与管理员重置接口不存在。封禁不能借找回解除。
  - 认证失败：注入重置消费后密码写入失败、密码已改但会话删除失败、二步消费后会话创建失败等情况；不得宣称自动回滚，链接/备用码已消费则走重新申请或剩余认证方式，撤销失败须重试清理。
  - 修改邮箱：本人库敏感会话申请，新邮箱验证前旧邮箱/找回可用；同一成员会话内确认后替换，其他账号或无会话拒绝，失败不提前改旧邮箱。当前邮箱唯一，待邮箱不预占；多申请第一个完成后其余绑定旧邮箱的链接失效。旧密码重置链接未必失效，按 1 小时边界验收。匿名改邮箱入口不存在。
  - 封禁：只封本人/连带普通后代、遇其他管理员停止；注册业务完成与封禁竞态重新检查，不漏封/孤立。管理员 ban/unban/quota/role 必须已绑定 TOTP且会话创建不超过 5 分钟，新鲜会话可连续操作，缺绑定或过期拒绝；旧会话单独验证 TOTP 不刷新新鲜度。删评只需管理员会话及业务 CSRF。
  - 解除封禁：只恢复单个被封禁成员，旧会话/已作废邀请码不恢复、额度按业务公式计算、无额外发信；缺管理员绑定或新鲜会话拒绝。
  - 管理员边界：网页端自封禁、自降权和使管理员数归零的请求一律被拒；两个并发请求不能把管理员数降到 0。本机提升首管的流程不被网页端注册参数绕过。
  - 播放 token：签名被篡改、已过期、拿去访问别的文件、属于别的成员，这些情况都应该被拒绝。按 6.6.1 验证同一 token 可访问该单元的媒体与全部 VTT 字幕轨，但换成其他可播放单元的媒体或字幕即被拒；退出、撤销会话、邮箱密码重置、封禁后，下一个 GET/HEAD/Range 请求即被拒绝；已开始的流最晚在旧 token 到期时停止，30 分钟上限不变。续期按 6.6.1.1：到期前 5 分钟发起，网络错误或 503 按 5/15/30 秒重试且最多 3 次，401/403 立即停止，到期仍未成功则暂停并提示手动重试。
  - Range 请求：返回 206 状态码，内容范围和字节数正确。
  - 观看进度和片单：增删改查、跨成员隔离、私有与站内公开权限、条目排序，以及“已看完”的判定逻辑；切集不得串用起点，手动标记后继续观看不得漏掉仍未完成的作品。按 6.7.1 验证 `expectedRevision`：版本不符返回 409 且旧上报被丢弃、不自动重放，只有继续观看产生的新事件才再上报；回看到更小的位置能正常保存；手动“未看”后位置归零、`completed = false`、版本递增，此后重新观看达到 90% 仍能自动完成。按 6.7.1.1 验证同一目标重复添加返回已有条目、不新增也不改顺序，并发重复添加幂等，作品与其单集条目可同时存在。另按 6.7.2 验证队列展开（作品与单集混合、去重保留首次出现、跳过已看、无进度从头）、全部已看时的“已全部看完”提示，以及队列播完停在当前播放页并显示“片单已播放完”和返回入口。
  - 评论、回复和赞踩：正文与长度校验、所属可播放单元和对话正确、持久化、每成员单一赞踩及取消、数量、分页和稳定排序；访客与被封禁成员不能读取受保护讨论或发送内容，危险 Markdown 和链接不能造成脚本执行。管理员删除顶层评论后，该评论、全部回复和相关赞踩在数据库及读取结果中均不存在；删除单条回复只移除该回复和其赞踩，不影响其余讨论。被删内容不留占位、不计入数量、排序或分页，直接读取、回复或赞踩已删目标返回 `404`，普通成员调用删除被拒绝。并发写入和删除失败不得留下孤立记录或部分删除。
  - 访问控制：访客可以查看 6.5 列明的公开页面和公开静态素材；访问成员页面时跳转登录并保留返回目标，访问受保护数据或媒体接口时被拒绝。公开页不展示片库、成员记录、搜索结果或讨论，所有页面均禁止索引。
- 测试边界二：离线导入工具。用一份精简的样例 manifest、几个很小的样例视频和字幕文件，导入到本地的 D1 和 R2。验证数据是否正确写入、连续导入两次结果是否一致，以及格式不对的视频是否被拒绝。
- 测试边界三：邮件发信。把已购发件服务的 HTTPS API 换成本地模拟服务，验证发信请求的收件人、正文来源和一次性凭证是否符合 6.0，投递失败、超时和返回错误码时注册、找回和改邮箱流程的行为，以及同一邮箱的限流计数。每次操作最多向模拟服务发出一次请求，失败或超时后无自动补发；超时不报告确定未送达。注册验证、重发验证与改邮箱验证共用验证用途配额、邮箱找回单独计数，各自至少间隔 60 秒、滚动 60 分钟最多 5 次，首次及失败/超时尝试均计入，换 IP 不绕过，窗口边界和并发请求不得超额；管理员通知不受站内发信频率限制，上游拒绝仍记录且不回滚管理操作。手动重发仍遵守相应限流与一次性凭证约束。测试不向真实服务商发信，不使用真实邮箱地址。
- 浏览器验收：覆盖当前原型的全部产品页面，以 1440×1000 桌面和 360×800 手机为基础，检查浅色/深色、成员/访客/管理员、空数据、加载、失败和成功状态；手机视口模拟之外，实际手机的键盘、触控和播放能力也需验证。
  - 访客入口：星图和登舰指南切换、邀请码带入注册、受保护页面登录返回、关于页版权声明与 `contact@startrekchina.org` 下架联系方式展示、无索引规则。
  - 浏览与首页：影院舞台与刻度尺、无记录时按配置展示三个推荐起点（首版 SNW/TNG/TOS 第一季第一集，调整随部署生效）、网格和时间轴、中文/英文搜索、切季、剧照缺失和加载失败占位、观看状态、收藏和加入片单。
  - 播放：真实自生成测试媒体的拖动、字幕、键盘、暂停和离开上报、逐单元续播、跨设备读取、下一集倒计时取消与自动播放受限回退；长时播放按 6.6.1.1 验证续期换 URL 后仍保留播放位置、暂停/播放状态和字幕选择，不能用短片段可播代替。
  - 片单：创建和删除、混合条目增删、桌面按钮和手机滑动排序、可见范围、按 6.7.2 的队列规则播放（含跳过已看、去重、全部已看提示、队列播完停留并提供返回片单入口）。
  - 讨论：宽屏双栏吸顶与窄屏内联展开、空状态、三档排序、评论分页和回复分批、赞踩、Markdown 和预览、键盘发送、回复目标取消、分对话草稿、发送锁定与失败重试、发送途中切换对话、减少动态效果；另验证顶层评论及全部回复整段消失、单条回复删除不影响其余讨论、当前对话关闭和计数分页更新；列表和对话不留删除占位，已删目标不能继续读取、回复或赞踩。
  - 跨页面与账号管理：主题、导航、复制、快捷键、键盘/读屏、备用码保存、邀请码、邀请链、封禁及管理员新鲜会话引导。关于页和账号页使用邮箱找回/二步备用码新文案，不出现旧三路径恢复或管理员重置入口；改邮箱只有已登录成员流程。
- 限流（测试边界四）：按 6.3.2 验证库原生 IP+路径规则、D1 storage、可信 IP、共享 IP 预算及 `X-Retry-After`；包装入口不绕过限流/Turnstile。验证原生二步挑战 5 分钟/5 次及账号锁定，服务端配置 hostname/action 并拒绝验证码重用或依赖失败。发信/播放签发/管理业务配额分别验精确条件计数与响应头，正常媒体不耗这些配额。
- 数据库备份：模拟 WebDAV / S3，验证网页创建、失败后人工重试、加密文件直接下载及定时入口共用完整导出流程；仅配置完整的外部目标可设置并启用频率/时间，直接下载/缺配置/伪造启用均拒绝，验证北京时间换算、修改/关闭设置与目标失效后的执行拒绝。上传后流式回读长度与 SHA-256 一致，构造 ETag 相同但内容不同的对象确认不会误判成功。仅 `OWNER_EMAIL` 匹配的正常管理员可访问页面、状态、设置与文件，校验 CSRF、无匹配/缺配置、伪造邮箱/角色、降权/封禁/改邮箱/会话撤销及环境隔离。下载文件可认证解密还原，不含明文密钥，响应与日志不泄露 SQL、上游地址或外部凭证；各端最后一份完整可恢复副本可超过 30 天，清理绝不触碰媒体或站长本地文件。

### 7.1 后端补充验收条件

沿用外部可观察行为的边界，HTTP 集成使用 `@cloudflare/vitest-pool-workers` 的真实 Workers 运行时和本地 D1/R2；只观察请求、响应、数据及对象状态，不断言内部函数调用。涉及 6.16 验证门槛的用例在门槛完成前不宣称通过，本地模拟不宣称验证了线上复制延迟、Rate Limiting 全局精度或实际导出耗时。

| 数据关系 | 保留目录、媒体、片单、讨论的关系与唯一约束；认证表对齐锁定库 schema、用户 ID 与业务资料一对一、当前邮箱/用户名/会话 token/credential ID 唯一。验证 Date 序列化、历史数据迁移及孤立注册记录无权限；不再验收旧待邮箱占用、单一 JWT 或单一重置链接约束。 |
