## 3. 术语

| 术语 | 含义 |
| --- | --- |
| 作品 | 一部电影或一部剧集（系列），和 manifest 中的一条主海报一一对应 |
| 季 | 剧集下的一季，有自己的季海报 |
| 集 | 某一季下的一集 |
| 可播放单元 | 可以直接播放的东西：一集，或一部电影 |
| 媒体文件 | 存在 R2 中、属于某个可播放单元的视频文件（v1 为单文件 WebM 或 MP4） |
| 字幕轨 | 挂在可播放单元上的一条外挂字幕（v1 为 VTT）；内容分中文和中英双语，文字分简体和繁体 |
| 成员 | 邀请注册已完成、通过邮箱验证且未被封禁的用户 |
| 管理员 | 能管理成员和邀请码的用户 |
| 站长 | 本环境 `OWNER_EMAIL` 指定邮箱的正常管理员；网页备份权限只授予该账号，不增加第三种业务角色 |
| 邀请码 | 一次性的注册凭证，记录是谁发出的 |
| 邀请链 | 成员之间“谁邀请了谁”的关系，出问题时用来追溯和连带处理 |
| 邮箱验证 token | Better Auth 签名的限时邮箱归属证明；注册验证可在到期前重复确认，不承诺一次性消费 |
| 改邮箱待验证 | 已验证成员已提交新邮箱、但新邮箱尚未验证通过的状态；此时旧邮箱及旧邮箱找回仍然可用 |
| 待验证账号 | 已提交注册、但尚未通过邮箱验证的账号，不能登录成员功能 |
| 通知邮件 | 系统主动发出的封禁等安全提醒；不含管理员签发的账号重置链接 |
| 播放授权 | 视频和字幕的每次请求由 Worker 按成员当前登录会话实时判定；不另行签发播放凭证，媒体地址本身不含权限 |
| 二步验证备用码 | Better Auth 的一次性第二因素备用码，需先通过密码阶段；不能用于重设密码，本文不再把它称为密码恢复码 |
| 重置链接 | Better Auth 发往成员邮箱的限时密码重置入口；提交新密码时一次消费，多个未过期链接可并存 |
| 片单 | 成员自己整理的有序作品或剧集清单 |
| 评论 | 成员在一个可播放单元下发表的讨论内容 |
| 对话 | 一条评论及其按时间排列的回复 |
| 赞踩 | 成员对评论或回复的赞同或反对反馈，与作品评分无关 |

## 4. 范围与规模

### 4.1 片库

片库以 `public/assets/posters/star-trek/manifest.json` 为准，v1 不开发收录新内容功能；结构设计见 catalog 计划。

- 电影 14 部：1979 年到 2025 年，包括《Section 31》。
- 剧集 13 部，共 52 季，约 950 集（集数为估算）：TOS、TAS、TNG、DS9、VOY、ENT、DIS、Short Treks、LD、PIC、PRO、SNW、Starfleet Academy。

### 4.3 前端原型对应的 v1 范围

当前原型提供 v1 的展示与交互参考；认证相关页面按 2026-10-06 确认的 Better Auth 方案调整。恢复码重设密码、管理员签发重置链接和匿名改邮箱不再纳入 v1。下表用于检查覆盖情况，原型旧流程不作为正式规则。

| 页面或能力 | v1 范围 |
| --- | --- |
| 访客首页 `/`、关于 `/about` | 桌面星图、手机登舰证、邀请码入口、通行密钥和密码登录入口、站点说明与守则 |
| `/login`、`/register`、`/reset-password` | 用户名密码、通行密钥、TOTP 与备用码登录、邀请码注册和邮箱验证；旧 `/recover` 密码恢复页不迁移 |
| 邮箱验证 `GET /verify-email`、待验证提示页 | 验证邮件链接落地页、验证结果反馈、重新发送验证邮件入口；原型的同名页面从正式工程回填，只作展示参考 |
| 邮箱找回密码 `GET /forgot-password` | 提交邮箱、统一成功提示、邮件中的重置落地页；原型的同名页面从正式工程回填，只作展示参考 |
| 成员修改邮箱 `/account` | **原型没有**：已登录成员通过库原生改邮箱流程验证新邮箱，完成后替换旧邮箱；不提供匿名密码改邮箱 |
| 成员首页 `/` | 影院式推荐或续播舞台、继续观看刻度尺、收藏、剧集和电影分区 |
| `/series`、`/movies`、全站搜索 | 剧集和电影浏览、网格与首映年份时间轴、中文或英文作品名搜索 |
| 作品页 `/series/<简称>[/s<季号>]`、`/movies/<slug>` | 作品资料、收藏和加入片单、季切换、带单集剧照和观看状态的选集列表；地址规则见 6.11 |
| 播放页 `/series/<简称>/s<季号>/e<集号>`、`/movies/<slug>/watch` | 播放、拖动、字幕、清晰度、弹幕、键盘控制、续播和观看状态、下一集提示、加入片单、评论与回复 |
| `/library`、`/playlists`、`/playlists/<片单 ID>` | 收藏、片单创建和删除、条目增删排序、私有或站内公开、按顺序播放入口 |
| `/invites`、`/account`、`/admin` | 邀请、账号安全和会话、成员及邀请链管理、封禁与解封、额度与管理员身份；无管理员账号重置入口 |
| 跨页面交互 | 默认跟随系统、可一键切换的深浅色主题、响应式布局、手机搜索与菜单、回到顶部、快捷键、复制和操作反馈、404 页面 |

原型中的 PROTO 控制台、身份切换、虚构用户、模拟接口、固定密码和验证码、人为等待时间、自生成测试片段，以及已删除的设计比较方案，不属于正式产品功能。原型已有的加载、空数据、失败和成功反馈需要接入真实数据；已知缺陷不能作为正式版的预期行为。此前已确认但尚未在原型中实现的后端、导入和运维需求仍然保留。

## 5. 用户故事

### 5.1 访客与注册

1. 作为访客，我希望能查看不展示片库的首页、关于页，以及登录、注册和账号恢复页，了解如何加入；作品资料、搜索、媒体、观看记录、片单和讨论只对成员开放。
2. 作为访客，我希望用邀请码注册账号，这样只有受邀的人才能加入。
3. 作为访客，我希望邀请码无效、过期或已被使用时能看到明确的提示，这样我知道该去找邀请人重新要一个。
4. 作为访客，我希望注册时自己设置用户名、密码和邮箱，注册后收到验证邮件，验证通过才能使用成员功能，这样账号一定对应一个真实可联系的人。
5. 作为成员，我希望开启二步验证时取得一组备用码并妥善保存，这样遗失验证器后仍能在输入正确密码后登录。注册时不发放密码恢复码。
6. 作为搜索引擎的爬虫，我不应该收录本站的任何页面。

### 5.2 登录与账号安全

7. 作为成员，我希望用用户名和密码登录。
8. 作为成员，我希望绑定通行密钥，这样可以不输密码直接登录。
9. 作为成员，我希望开启 TOTP 二步验证，这样即使密码泄露，账号也不会被盗。
10. 作为成员，我希望认证入口有限流和人机验证，减少自动化注册、密码猜测和邮件滥用。
11. 作为成员，我希望能查看自己有哪些登录会话，并退出不认识的会话。
12. 作为成员，我希望能修改密码、重新生成二步验证备用码、解绑通行密钥或关闭二步验证，按 Better Auth 的密码确认和新鲜会话规则完成。
13. 作为成员，我希望在忘记密码时通过邮箱重设密码；遗失 TOTP 验证器时可用密码加二步验证备用码登录。
14. 原“管理员生成账号重置链接”故事移出 v1；邮箱、密码、验证器和备用码均不可用时，不承诺网页自助或管理员一键恢复。

### 5.3 浏览片库

15. 作为成员，我希望在首页看到“继续观看”，以及按剧集和电影分类的全部作品。
16. 作为成员，我希望在作品页看到中文标题、简介、年份和海报；中文资料缺失时显示英文。
17. 作为成员，我希望在剧集页按季浏览，每一集都显示标题、简介、时长、我的观看状态和一张小尺寸单集剧照；剧照仅用于非播放页的选集列表，缺失时显示同尺寸占位，不用作品或季海报替代。
18. 作为成员，我希望按作品名（中文或英文）搜索作品。
19. 作为成员，我希望在一部作品的季和集之间顺畅地切换。

### 5.4 播放

20. 作为成员，我希望点击一集或一部电影就能在网页里直接开始播放。
21. 作为成员，我希望可以随意拖动进度条，播放能马上从新位置开始。
22. 作为成员，我希望在简中、简英、繁中、繁英字幕和关闭字幕之间切换。
23. 作为成员，我希望看完两小时的电影都不会中途被要求重新登录或刷新页面。
24. 作为成员，我希望用键盘控制播放器（播放、暂停、快进、快退、调节音量、全屏）。
25. 作为成员，我希望一集播完后看到下一集提示，可以立即播放、取消倒计时，或等倒计时结束后继续播放；浏览器不允许自动播放时，应给我明确的手动播放入口。
26. 作为站长，我希望复制出去的视频地址对非成员无效，转发出去也拿不到内容，这样链接外流的影响有限。

### 5.5 观看进度与片单

27. 作为成员，我希望系统自动记住每一集和每部电影看到了哪里，下次打开时从那里继续。
28. 作为成员，我希望看到接近结尾时自动标记为“已看完”，也可以手动标记为已看或未看。
29. 作为成员，我希望在剧集页一眼看出哪几集已经看过。
30. 作为成员，我希望在不同设备上看到同样的观看进度。
31. 作为成员，我希望收藏作品。
32. 作为成员，我希望建立有序的片单（比如“TNG 必看 20 集”），片单里可以放作品，也可以放单集。
33. 作为成员，我希望把片单设为站内公开，让其他成员也能看到。

### 5.6 邀请

34. 作为成员，我希望看到自己还剩多少个邀请码，并能生成邀请码发给朋友。
35. 作为成员，我希望看到自己发出的邀请码是否已被使用，以及是谁用的。
36. 作为成员，我希望能作废还没被使用的邀请码。

### 5.7 管理员

37. 作为管理员，我希望生成邀请码不受数量限制。
38. 作为管理员，我希望调整每位成员的邀请额度。
39. 作为管理员，我希望查看成员列表，以及每个人的邀请人和被邀请人。
40. 作为管理员，我希望封禁一名成员，并可以选择连带封禁他邀请的人。
41. 作为管理员，我希望被封禁的成员立即无法登录，也无法开始新的播放、拖动、换集或刷新；已经在传输中的视频不保证立即中断。
42. 原“管理员重置成员账号”故事移出 v1；后台不签发重置链接，也不清除成员的认证设备。
43. 作为管理员，我希望把其他成员设为管理员，或取消管理员身份。

### 5.8 站长与运维

44. 作为站长，我希望在本地用一个命令行工具把视频、字幕和剧集资料导入 staging 或 prod 环境。
45. 作为站长，我希望导入工具能重复运行而不出问题：再跑一次只会补上缺少的部分，不会产生重复数据。
46. 作为站长，我希望导入工具在上传前检查视频格式，格式不对时明确提示我去重新转码。
47. 作为站长，我希望剧集标题和简介由导入工具从 TMDB 自动拉取中文和英文版本，不用我手动整理。
48. 作为站长，我希望 staging 和 prod 完全隔离，这样在 staging 上试错不会影响成员。
49. 作为站长，我希望在网页内备份数据库、查看结果，可以直接下载加密备份，或保存到 WebDAV / S3；其他管理员和成员不能使用这项功能。配置完整的 WebDAV 或 S3 目标后，我才可以设置自动备份的频率与执行时间；仅使用直接下载时不启用定时备份。
50. 作为站长，我希望每月的开销都在预算以内，不用盯着账单。

### 5.9 原型新增与细化的用户故事

以下编号接续原有 1–50，保留已有编号便于追踪。

51. 作为访客，我希望桌面首页展示星图、手机首页展示登舰证，并能从首页使用通行密钥登录、进入密码登录或填写邀请码注册。
52. 作为访客或成员，我希望在关于页了解本站、加入方式、成员守则、隐私与数据、账号找回、版权说明和技术说明。
53. 作为成员，我希望首页用影院式舞台展示当前续播作品，并通过带进度的刻度尺切换或播放其他继续观看条目；没有记录时能看到推荐起点。
54. 作为成员，我希望在剧集和电影浏览页切换海报网格与首映年份时间轴，并从两种视图进入作品页。
55. 作为成员，我希望在单集或电影的播放页发表评论，用受限的 Markdown、表情和预览表达内容。
56. 作为成员，我希望展开评论的对话、回复评论或其中某位成员，并在切换对话时保留各自未发送的草稿。
57. 作为成员，我希望对评论和回复赞同或反对，再次点击可以取消；赞显示数量，踩仅参与排序、不显示数量。
58. 作为成员，我希望按智能、最新或最早排序查看评论，分页浏览评论和分批展开回复；点赞时列表不应突然重新排列。
59. 作为成员，我希望评论发送时有明确反馈且不能重复提交，发送成功后容易找到新内容，过长正文可以展开或收起。
60. 作为成员或访客，我希望页面适配桌面与手机，主题默认跟随系统，也可以一键切换深浅色；手机上能方便地打开搜索、菜单和回到顶部。
61. 作为成员，我希望通过键盘快捷键打开搜索、切换主题、控制播放，以及发送评论；输入文字时普通字母快捷键不应干扰输入。
62. 作为成员或管理员，我希望复制邀请码、邀请链接和二步验证备用码时得到明确反馈，异步操作也有加载、成功或失败状态。
63. 作为成员，我希望创建和删除自己的片单、添加或移除条目，在桌面通过按钮排序、手机通过滑动排序，并通过“按顺序播放”入口观看片单内容。

### 5.10 邮箱与通知

以下编号接续 1–63。

64. 作为访客，我希望注册时填写邮箱，注册后收到一封验证邮件，点击其中的链接完成验证，这样我的账号绑定了一个真实邮箱。
65. 作为待验证账号，我希望在验证前看到明确说明，被告知成员功能要验证后才能使用，并且能重新发送验证邮件。
66. 作为待验证账号，我希望重新发送验证邮件时受到限流和频率限制，这样别人不能拿我的邮箱反复触发发信。

## 6. 业务规则与行为规格

本节规定可观察的行为与安全边界；工程实现见各节链接的计划。已确认规则索引见 6.13，实现状态和验证门槛见 6.16。

### 6.0 邮箱验证与发信

#### 6.0.1 注册与邮箱验证

- 邀请注册必须填写邮箱，由 Better Auth 校验格式并按其小写化规则保证当前邮箱唯一。账号注册完成且 `emailVerified=true` 后，才能访问成员功能；待验证或注册未完成的账号没有片库、媒体或讨论权限。
- 注册按 6.2.2 预留并完成，注册时不自动登录、不生成备用码，邀请码完成消费后才发信。完成的待验证账号保留用户名、邮箱和邀请码消费记录，不因长期未验证自动返还邀请码。
- 使用 Better Auth 原生签名验证链接，有效期默认 **1 小时**。原生 `GET /api/auth/verify-email?token=...` 可完成验证并跳转结果页，接受邮件预览器可能提前完成验证的行为；验证不承担密码重置或授予成员身份的作用。链接无效、已过期或对应账号不可用，以及改邮箱链接已使用或不属于当前登录账号时，同样跳转结果页说明原因和下一步，不向浏览器返回 JSON 错误。
- 普通注册验证后由成员正常登录，不自动建立会话。未过期且邮箱仍匹配时重复点击可幂等成功；新旧未过期链接可并存，重发不立即撤销旧链接，过期或签名不合法则失败。
- 邮件发送失败保留注册结果，提示可重发，按 6.0.3 记录发送结果；不得宣称服务商接受请求就代表已经送达。

#### 6.0.2 邮箱作为密码找回通道

- 邮箱找回对存在和不存在邮箱均给出同一成功提示。链接默认 **1 小时**有效，多个未过期链接可并存，不承诺申请新链接撤销全部旧链接。
- 密码重置成功后只更新密码并撤销全部旧会话，保留 TOTP、通行密钥及未用二步备用码，不自动登录；仍开启 TOTP 的密码登录仍须第二因素。
- 重置 POST 成功后，替换当前浏览器历史条目进入无凭证参数的 `/reset-password/complete` 完成页；显示“密码已重设”、所有设备已退出登录及二步验证保留说明，提供“前往登录”主按钮。完成页不保留密码表单，不创建会话；失败时保留原表单和重试提示，不显示完成状态。
- GET 检查链接并跳转 `/reset-password?token=...`，不消费重置凭证；POST 设置新密码时消费。链接无效或已过期时跳转 `/reset-password?error=...`，页面直接说明并提供重新申请入口，不显示密码表单。D1 故障可能已消费链接但未改密，界面应允许重新申请邮件，不把多次库写入描述为原子事务（6.4.1）。
- 邮箱找回不能关闭二步验证或解除封禁。仅邮箱可用但验证器与备用码均遗失时，不能借密码重置绕过第二因素；已绑定通行密钥仍可用于登录。

#### 6.0.3 发信通道与限流

- 沿用站长已购买的 Postal 发件服务，不重新选型；具体 HTTPS 接入与字段/配置见[认证计划](plan/authentication.md#原生配置与发信接入)。服务商接受不代表已送达，必须区分失败、未确认与已接受。

- 每次操作最多一次发信请求，传输层单次等待默认 **10 秒**；失败或超时不自动重试，超时/连接中断记录为发送结果未确认。回调捕获并记录脱敏失败，避免注册结果随邮件失败回滚；成员可按配额手动重发。传输层不自动跟随重定向，避免 API key 发往其他地址。
- 验证（注册、重发、改邮箱）共用目标邮箱摘要的配额，找回单独计数：至少间隔 **60 秒**，滚动 **60 分钟最多 5 次**。首次、失败和超时均计入，不存在邮箱的找回同样计数；并发或换 IP 不得绕过精确用途配额，入口 IP 限流不能代替它。
- 改邮箱另按发起成员计数：至少间隔 **60 秒**，滚动 **60 分钟最多 30 次**，切换目标地址、邮箱别名或客户端 IP 不重置额度；预留成功后的失败、未发送和超时仍计入。成员与目标邮箱配额须在同一原子写入中同时满足。
- 封禁通知不受站内发信频率上限限制；服务商套餐和 API 限额仍适用。发信失败不回滚封禁，不增加自动排队、主动失败告警或投递 webhook。
- 2026-10-07 站长确认已购服务额度为**每小时 3,000 封、每日 24,000 封**；这是上游套餐额度，不改变上述站内邮箱用途配额。月额度和 API 请求频率未提供，不推断为无限；实际追加费用仍按服务商套餐核对。
- 发件地址使用站长确认的统一子域，staging 与 production 标识区分，Reply-To 指向同一收信地址；域名与收信配置由站长维护。真实地址和凭证不入公开仓库，实际配置与投递验证见认证/运维计划。
- 仅邮件正文包含必要限时链接；日志只含邮箱不可逆摘要、用途、请求 ID、结果与脱敏错误，不含正文、完整 URL 或 token。发送结果必须可观察，不把未完成发送报告为成功。

#### 6.0.4 修改注册邮箱

- 仅已验证、注册完成且正常的成员可申请改邮箱，发起时须在 **5 分钟**内登录过；使用原生新鲜会话校验，不增加逐操作 TOTP 证明。过期拒绝不占发信额度，重新登录后可继续；具体库配置见认证计划。
- 按库原生流程向新邮箱发验证邮件；新邮箱验证前保留当前邮箱及其找回能力。默认不另发旧邮箱确认邮件，不提供匿名 `username + currentPassword` 改邮箱路径。
- 待验证新邮箱不排他预占，不承诺新申请撤销旧申请或列出所有待处理申请。多个申请可并存，第一个成功更换后，绑定旧邮箱的其他申请失效。
- 替换时以当前邮箱唯一约束处理冲突，不允许与他人当前邮箱重复。失败或发送失败不提前改变旧邮箱，不改变成员 ID、邀请链、角色或业务数据。
- 改邮箱验证链接必须在该成员有效登录会话内打开，无会话先正常登录后继续；不得因无会话验证自动登录而绕过第二因素。
- 接受库的改邮箱/重置链接关系：改邮箱不承诺撤销此前已发出的密码重置链接；原生重置凭证绑定用户 ID，未过期旧链接仍可能有效。成员应妥善保护旧邮箱及已收到的重置邮件，最长残留期受 1 小时链接有效期限制。

### 6.1 访问、隐私与公共行为

- 站点、自有数据库及私有媒体存储运行在 Cloudflare；成员资料由站长控制，不使用托管身份服务。发件服务仅接收投递所需邮箱和正文。已确认的 React Router、D1、R2 等选型见[架构方案](plan/foundation.md#61-总体架构)，搬移不表示重新选型。
- 片库、播放及成员数据要求登录、注册完成、邮箱验证及正常状态；每个页面、数据和媒体入口独立校验，直接请求或预取不能绕过。当前身份及角色由服务端确定。
- 海报及作品页小尺寸单集剧照为公开素材，站长接受其暴露站点主题。剧照按作品/季/集匹配，缺失或加载失败保持同尺寸占位，不用海报替代；播放页选集不显示剧照。视觉见 6.14，生成方式见架构方案。
- 界面以简体中文为源文字，首次生产发布后可整体切换为繁体中文（6.1.2），不做中英双语界面；保留英文资料回退、星图标注、辅助标签和评论时间格式。所有页面、素材、错误、重定向及媒体均不允许搜索引擎收录。

#### 6.1.1 权限、响应与安全边界

- 业务写入统一校验来源、要求 JSON 请求、拒绝跨站请求，不使用页面凭证；认证用库原生防护，包装入口不能绕过。验证邮件 GET 是 6.0.1 的明确例外；回跳在 URL 规范化后仍只限本站，不开放跨域媒体。站点页面禁止被其他页面嵌入。
- 受保护页面未登录时跳转登录并保留返回目标；JSON/媒体返回错误。登录和找回保持脱敏；注册可提示用户名/邮箱冲突，邀请码区分无效、过期、已用、作废，不泄露邀请人私密资料。
- 错误区分输入不合法、未认证、权限不足、不可见/不存在、冲突、额度不足、限流及依赖暂不可用，提供可重试信息；不能泄露内部 SQL、栈、存储路径或上游凭证。HTTP 状态、错误码及响应封装见[接口约定](plan/foundation.md#611-服务端边界与公共约定)。
- 登录态 HTML、数据、认证、邀请凭证、媒体及备份响应私密且不可共享缓存；公开素材可按版本缓存。浏览器不接收原始媒体地址、对象键、Secrets、密码哈希或认证密文。必要凭证只给有权者，本站会话列表只显示本人设备信息与 ID。
- 会话 Cookie 不可被脚本读取，生产使用安全传输及同站限制。页面避免泄露来源；应用和平台日志不记录密码、Cookie、邀请码、备用码、TOTP、完整 token/URL 或私密地址。安全头及 Cookie 的技术配置见接口约定，必须实测平台行为。

#### 6.1.2 简繁切换

- 首次生产发布后开发，技术方案见[工程基础计划 ZH1](plan/foundation.md#zh1-简繁切换)。发布前不加界面 i18n 层，只按 6.8 为字幕标明简繁和双语，生产数据日后无需重新标注。
- 访客和成员都可以在简体中文（zh-CN）与繁体中文（zh-TW）之间切换。一个偏好同时决定界面文字、作品标题与简介和字幕的简繁；入口在页脚底栏。
- 简体是唯一的源文字：界面文案和作品资料只维护简体，繁体由 OpenCC 按台湾用词转换，不另行维护繁体文案，也不从 TMDB 拉取繁体资料。英文资料、邀请码、用户名、邮箱和代码类信息不转换；成员发表的评论、回复、弹幕和片单名称等内容按原文显示，不转换。

### 6.2 业务对象与一致性

- 作品分电影和剧集，剧集含季和集；电影和单集均为可播放单元。作品、季、集保留 TMDB 身份与双语资料，中文缺失回退英文。

- 邀请记录发出人、使用人、状态和期限；成员邀请关系完成后不可改，不允许自邀请。初始化码可无发出人，不冒充成员。
- 评论属于单元和作者，回复属于同一对话并可指向其中成员；每名成员对一个对象最多一个当前赞踩，可切换或取消。
- 对象身份稳定；迁移、补资料或重试不产生第二套成员身份，不破坏进度、邀请链、片单及讨论。

#### 6.2.1 存储映射入口

表、字段、外键、唯一键和索引只在[数据结构方案](plan/foundation.md#621-数据结构共用约定)维护；业务关系和可观察结果按本节、6.5、6.7、6.12 及第 7 节验收。

#### 6.2.2 并发、重试与部分失败

- 邀请注册先预留、创建待验证账号、再完成成员注册；预留默认 15 分钟，期间不被其他尝试抢占。完成时重检期限、邀请人状态和封禁竞态，完成消费后才发信。
- 同一码只能完成一个成员注册；用户名/邮箱冲突及失败尝试不烧码。未完成账号无成员权限，同一归属可安全续作或续订过期预留，不能认领他人账号；清理不删除已完成成员及数据。
- 原生账号已创建、成员注册尚未完成时，若原邀请过期、撤销或邀请人失去资格，可用原用户名、邮箱和密码更换有效邀请继续注册。丢失注册 Cookie 时必须验证原密码；仅匹配邮箱或用户名不能认领。恢复保留原账号与密码，仍须完成邀请消费和邮箱验证，不自动登录。
- 原生认证可能部分成功（账号/凭证部分创建、重置凭证消费后改密失败等）；错误不等于全流程回滚，按 6.4.1 提供可重试或修复结果。
- 发码重试不重复生成或扣额，响应丢失也不提供事后查询原码；额度、封禁、注册业务完成和片单重排不能部分成功。进度及片单冲突行为见 6.7。
- 认证密钥变化导致原发码操作无法重放时，明确拒绝并提示刷新后重新生成，不返回与原记录不符的邀请码、不重复占额；原邀请码及记录保留，仍可按既有规则使用或作废。
- 新请求即时检查当前权限，封禁/撤销不能因缓存或延迟读取放行；封禁与注册先后结果见 6.5.2。旧认证迁移不自动转换或删除未审查凭证。
- 管理员删除讨论或弹幕时，在实际删除处校验当前会话、成员资格及角色；检查后降权或撤销会话也不得删除目标及其关联数据。
- 表、触发器、SQL 条件、批次、主库读取及续作方式见[D1 写入方案](plan/authentication.md#622-d1-写入与幂等)。

### 6.3 身份认证

- 已确认采用 Better Auth 原生认证行为；版本、插件及迁移在[认证计划](plan/authentication.md)维护。当前业务行为以本节为准，版本升级须单独核对，不因库新增能力扩大 v1。
- 认证资料保存在站长自己的数据库；本站控制邀请、角色、封禁、额度与授权。OAuth、邮件 OTP/魔法链接、受信任设备免二步及账号删除不因库支持而加入 v1。
- **用户名**沿用 username 插件默认规则：3–30 个字符，ASCII 字母、数字、下划线和点号 `[A-Za-z0-9_.]`，小写化唯一；展示保存 `displayUsername`。不沿用旧 3–12 位或连字符规则，不开放成员改用户名。
- **密码**沿用库默认 8–128 长度校验，不强制字符组合，允许空白、中文与 emoji；不自行 trim，哈希/校验接受库的 NFKC 规范化。长度计数采用锁定版本字符串语义，前端与服务端一致。
- 密码不得存明文，沿用已采用库的密码哈希行为；算法参数及 Workers 成本验证见认证计划。
- TOTP 和备用码加密保存在站长控制的环境，管理界面不开放读取原码；不与播放/备份复用密钥，轮换和历史备份保管见 6.9.1。

#### 6.3.1 凭证与挑战

- 密码登录用用户名；开启 TOTP 时先通过密码再用 TOTP/一次性备用码，挑战 **5 分钟**有效、最多 **5 次** TOTP 尝试。接受库内部瞬时会话过程，但第二因素完成前客户端不能获得可用成员会话。
- 沿用库的账号级二步失败锁定（锁定版本 10 次失败后锁定 15 分钟）和挑战消费；重新发起密码阶段不解除账号锁。TOTP 6 位、30 秒、±1 步容差；不要求自建 `lastAcceptedStep` 时间步账本，同一有效码在不同挑战中可能被再次接受，不能把挑战一次消费写成跨挑战防重放。
- TOTP 绑定经当前密码确认并以有效验证码启用；取得绑定 URI、重新生成备用码、关闭二步等采用库对应的密码确认规则，不增加逐操作 TOTP 证明。v1 不使用 `trustDevice=true`，服务端拒绝此选项；不启用邮件/短信 OTP。
- 每个成员仅有一份 TOTP 配置；未完成绑定时，经当前密码确认重新打开同一配置和备用码。并发首次绑定不得覆盖已返回的配置；冲突提示重新打开，不返回无法使用的另一份密钥。
- 通行密钥注册/登录使用库与其 WebAuthn 实现校验 challenge、用途、成员、origin、RP ID、签名、期限及计数器。本站固定本环境 origin/RP；不信任客户端用户 ID，credential ID 唯一。同步密钥的合法零计数器不视为封禁理由。
- 通行密钥登录不再附加 TOTP，但必须由验证器完成用户验证（UV），服务端拒绝未验证结果；仅浏览器请求 UV 不算保障。具体钩子及真实验证证据见认证计划。
- 账号敏感操作使用原生当前密码确认或新鲜会话校验；新鲜度为创建后 **5 分钟**。旧会话单独验证 TOTP 不刷新新鲜度，需要时正常重新登录，不新增逐操作绑定目标的一次性证明。
- 删除本人通行密钥须使用 **5 分钟**内创建的会话；过期拒绝保留密钥，重新登录后可删除。
- 查看/撤销会话限本人，本站 UI 使用会话 ID，服务端查出本人 token 再调用库撤销接口；库原生端点本身返回的 token 是凭证，不能进日志或其他成员数据。

#### 6.3.2 限流与 Turnstile

| 入口 | 规则 |
| --- | --- |
| Better Auth API | 按可信客户端 IP + 路径限流；全局 100 次/10 秒，登录/注册/改密/改邮箱及二步各 3 次/10 秒，找回/重发各 3 次/60 秒，并保留锁定版本特殊路由规则。共享 IP 共用预算，不承诺精确账号滑动窗口或全局严格额度。 |
| 邀请注册、用户名密码登录、密码找回、验证邮件重发 | 每次要求 Turnstile，检查本环境及操作，缺失/伪造/重用/服务不可用拒绝；不等失败 5 次才出现。通行密钥及第二因素不附加人机验证。 |
| 成员发信 | 保留 6.0.3 的目标邮箱摘要 + 用途精确配额，叠加库入口 IP 限流。 |
| 管理员 ban/unban/quota/role | 每管理员 30 次/分钟，站点精确计数。 |
| 媒体/字幕 GET、HEAD、Range | 不消耗认证或管理配额；每次仍鉴权。 |

- 重启不能简单清空认证限流；原生持久化限流不等于精确滑动窗口。发信与管理额度仍按本站精确规则，配置及存储方式见认证计划。
- 库 `429` 保留原生结构及 `X-Retry-After`，客户端据此提示；站点业务限流返回 `Retry-After`。Turnstile 缺失、伪造、重用、错环境/操作或服务不可用时拒绝，不绕过验证。
- 包装入口同样执行跨站检查、IP 限流及 Turnstile；匿名注册不能通过另一个未保护端点绕过，内部调用方式不免除这些校验。

#### 6.3.3 会话与改密

- 原生会话滚动有效 **30 天**，刷新阈值 **1 天**；会话读取达到阈值后续到读取时刻的 30 天后，不设旧绝对 180 天上限，不限于页面读取。
- 页面、业务 API、播放鉴权等调用库读取会话均可能触发刷新；已过期会话不能续回。Cookie 的期限和更新时点由库管理，达到阈值可重发 Cookie，不逐请求换标识。
- 每个受保护入口即时核对当前会话与成员状态，缓存不得延迟封禁或会话撤销对下一请求的影响；具体缓存配置见认证计划，媒体流截止按 6.6。
- 密码一旦更新，全部旧会话必须已撤销；密码写入失败保留旧密码和旧会话。此保证不等于原生整个认证流程原子回滚，技术保证见认证计划。
- 正常改密撤销旧会话后建立全新当前会话，更换标识并重新计算期限，其他会话失效；后续建立会话仍可能失败，不承诺整个改密流程原子提交。
- 退出、撤销和邮箱密码重置使用库会话删除语义。封禁必须立即阻止新会话建立及业务访问；会话清理即使失败，成员状态门禁也不得放行（6.5）。

### 6.3.4 认证基线与变更依据

2026-10-06 确认采用 Better Auth 原生认证并保留本站邀请、权限、UV、即时封禁、跨站防护及业务配额。产品规则以 6.0、6.3–6.5 为准，不恢复旧三路径找回或自管会话。版本、插件、配置与变更映射见[认证采用方案](plan/authentication.md#634-采用决定与核对依据)，验收状态见[第三阶段](plan/authentication.md)。

### 6.4 密码找回与二步验证备用码

- **忘记密码只使用邮箱重置**（6.0.2），不再提供“恢复码重设密码”或“管理员生成重置链接”。后台不清除成员设备，不代发重置邮件；邮箱与所有有效认证方式均不可用时，没有 v1 网页恢复路径。
- **二步验证备用码**由 twoFactor 插件在开启二步时生成，默认 10 个，库认证加密保存，后台持认证 Secret 可解密；不要求仅存哈希。它只替代密码登录中的 TOTP，不能单独重设密码、关闭 TOTP 或清除通行密钥。
- 使用一个备用码完成第二因素后该码失效，其余码及 TOTP 保持可用；重新生成需要当前密码，替换旧组。账号页展示保存提示，不在注册时生成，也不增加管理员读取原码的入口。
- 邮箱重置后撤销全部旧会话，不自动签发备用码、不撤销未用备用码、不清除设备；不同未过期重置链接可并存，已消费链接不能复用。封禁状态不受任何找回或备用码登录影响。

#### 6.4.1 原生流程的失败边界

- 沿用库的重置/挑战/备用码存储与消费，不建立三路径恢复事务。故障可能发生在凭证消费后、密码或会话写入前；错误不表示自动回滚，旧密码是否仍可用以实际库结果为准。
- 新密码提交失败时保留清楚的重试提示，链接已消费则重新申请邮件；密码更新时旧会话必须已撤销；原生后续清理或新会话签发仍可能失败。此时不能报告“密码未变”，应重新登录；链接已消费且状态不明时重新申请邮件。故障注入覆盖这些分支，具体处置通过集成测试后才勾选完成。
- 重置表单 GET 不消费凭证；邮箱验证 GET 可改状态（6.0.1），两类链接行为不能混写。所有链接/表单 no-store、no-referrer、不加载泄露凭证的第三方资源，日志脱敏。

### 6.5 邀请与权限

- 角色只有两种：成员和管理员。
- 未登录时可访问访客首页 `/`、关于页 `/about`、登录 `/login`、邀请码注册 `/register`、邮箱验证结果 `/verify-email`、等待验证提示页、邮箱找回 `/forgot-password`、邮箱重置表单 `/reset-password` 和重置完成提示 `/reset-password/complete`。公开认证 API 仍须按库与站点门禁校验凭证；二步备用码输入属于待二步登录流程，不是独立密码恢复页。改邮箱验证需要当前成员会话（6.0.4），待验证账号不能匿名改邮箱。
- 访客首页和关于页不展示海报、作品列表、片库统计、成员数据或讨论，访客不能打开会列出作品的搜索。直接访问受保护页面时跳转 `/login?next=…`，登录后返回原页面；没有回跳目标或目标不在本站时，登录后进入首页。相关数据和媒体接口在服务端独立校验权限。
- “站内公开”的片单仅向已登录成员公开；仅片单所有者可以修改或删除该片单。评论、回复和赞踩只允许有效成员读取或操作，作者和管理员身份由服务端确定。
- 管理员生成邀请码不受数量限制。普通成员的邀请额度按 6.5.2 的定义计算。
- 封禁一名成员时，可以选择只封禁他本人，或者沿邀请链连带封禁他邀请的人。封禁后该成员的所有会话立即失效，后续成员接口操作（含评论、回复和赞踩）被拒绝，新的播放请求立即被拒绝，已在传输中的视频不保证立即中断（6.6.1）。
- 解除封禁是 v1 提供的独立管理员操作（故事 74），规则见 6.5.3。
- 封禁生效后向被影响成员的注册邮箱发送安全提醒邮件（故事 70）。通知邮件里只说明账号状态变化，不含讨论内容、片库资料或其他成员的邮箱/身份信息。发信失败不影响封禁本身的原子提交，封禁结果以服务端状态为准，不因邮件问题回退或部分回滚。

#### 6.5.2 首个管理员、邀请额度与连带边界

- **首个管理员不通过网页注册产生**：站长用普通邀请码注册并完成邮箱验证后，在本机用运维命令把该账号提升为管理员。**不开放 first-admin 网页注册入口**，也不提供通过注册参数把自己设成管理员的路径。
- 首个邀请码由本机初始化准备，`issuer` 可以为空。空 issuer 只用于这类 bootstrap 码，**不得假冒任何业务成员**，也不会出现在成员列表或邀请链的“邀请人”列里。
- 管理员完成高影响操作前需要绑定 TOTP，并使用 5 分钟内新建的有效会话；可通过密码加 TOTP/备用码或强制 UV 的通行密钥完成登录（6.5.1）。

- **邀请额度定义**：每位普通成员有 `total`（默认 `2`）和派生的 `occupied`。`occupied = used + validUnused`，即已使用数加有效未使用数；`available = total - occupied`。**生成邀请码即占用**；使用后永久占用，不因使用后的到期或成员封禁返还；**仅未使用码**作废或过期时释放占用。**没有周期补额**。
- 管理员为成员调整 `total` 时，**不得低于当前 `occupied`**；低于则拒绝并返回当前占用数，不截断既有邀请码。
- 邀请码**默认有效期 30 天**，可在生成时显式指定其他期限。
- 邀请码是否过期以服务端当前时间与签发期限判断，不因清理任务延迟继续有效。

- **发出人封禁时，全部有效未用码作废并释放占用**。注册先完成且选择连带时，新普通后代纳入封禁；仅封本人时新成员正常。封禁先完成时，两种模式均拒绝消费已作废码，不漏封或留下孤立邀请链。
- **连带封禁覆盖全部普通后代**：沿邀请链向下，封禁所有普通成员后代；**遇到另一个管理员即为边界**——该管理员本人不被这次封禁波及，其后代也不再继续向下连带。自封禁、末位管理员保护按同一原则适用（6.5.3）。

#### 6.5.3 管理员边界与解除封禁

- **网页端禁止管理员封禁自己或取消自己的管理员身份**，也不能让正常管理员数量归零，并发请求也必须保持此保护；失败不得部分改变状态。具体条件写入见认证计划。
- 站长在本机做紧急处理（例如需要恢复站点可用性）属于**本机运维操作**，不经过网页端，也不受上述网页规则约束；本机工具的具体设计随 6.8 的离线工具确定，不在此扩展。
- **解除封禁**（故事 74）是独立的管理员 action：
  - 只能对**当前处于封禁状态**的成员执行；目标不存在或未被封禁时按统一语义拒绝。
  - **不连带解封**，只恢复这一个人。
  - **不恢复旧会话**，也不恢复已作废的邀请码；被解封的成员自己重新登录。
  - 邀请总额度 `total` 保持原值，`occupied = used + validUnused`，`available = total - occupied`；已用码仍永久占用，不能因解封返还。
  - **解封不额外发送通知邮件**；除上述已列规则外，本条不新增其他通知、撤销或连带行为。

### 6.6 播放与媒体分发

- v1 直接播放单个视频文件，视频编码按清晰度档位固定：VP9 用 WebM 封装、Opus 音频，H.264 用 MP4 封装、AAC 音频；索引和元数据放在文件开头（WebM 前置 Cues，MP4 做 faststart），这样不用下载完就能开始播放和拖动。不做 HLS，也不做在线转码。VP9 用 WebM 是因为 iOS Safari 不播放 MP4 封装的 VP9，WebM 封装从 iOS 17.4 起可以播放；iOS 上 Safari 以外的浏览器及更低版本仍不能解码 VP9，只能播放 H.264 档位。
- 播放权限直接取自成员当前的登录会话，不另行签发播放凭证：视频与字幕的每次请求都由 Worker 实时确认会话有效、成员已完成注册与邮箱验证且未被封禁。所有有效成员都可观看全部片库，不按单集或文件另设权限。
- 浏览器通过本站固定的媒体地址访问，并支持拖动所需的部分内容读取；地址本身不含凭证，未登录或其他网站嵌入的请求拿不到任何内容。传输及 Range 方案见[播放计划](plan/playback.md)。
- 字幕与视频使用同样的会话授权，可在该可播放单元已挂接的 VTT 字幕轨之间切换（6.6.1）。
- 播放器支持外挂 VTT 字幕，选项依次为简中、简英、繁中、繁英和关闭，只列出该单元已有的轨道；默认选第一条已有的轨道（默认），简繁切换上线后改为优先与全站偏好相同文字的轨道（6.1.2）；字幕在播放器的设置菜单中选择，播放页不另设字幕控件。不提供纯英文字幕。键盘操作包括空格播放或暂停、方向键快进快退和音量、`F` 全屏、`M` 静音、`C` 切换字幕。已采用的 ArtPlayer 版本与接入见播放计划。
- 清晰度是站长离线准备的多个独立文件，不做按网速自动切换。所有媒体的视频均重新编码以节省 R2 空间，不直接复制源视频流。每个单元必须有不带档位后缀的原生主档，如 `E03.webm` 或 `movie.webm`，使用 VP9（profile 0，8 位 4:2:0）、Opus 和前置 Cues。“原画”表示保留所提供片源的原始分辨率与画面比例，不论分辨率多少；不表示无损、保留源码率或未经处理的拍摄母版。
- 其他档位从同一源文件直接向下编码，不向上放大，不从压好的低清档再次转压，也不生成与原画同分辨率的重复档位。已确认的制作组合如下；960p 不生成 720p，不按“低于原画的所有标准档位”自动补齐。其他片源分辨率的组合待开发者确认。

  | 片源分辨率 | 原画主档 | 向下档位 | 文件总数 |
  | --- | --- | --- | --- |
  | 960p | 保留源尺寸，VP9 | 480p，AVC / H.264 | 2 |
  | 1080p | 保留源尺寸，VP9 | 720p、480p，均为 AVC / H.264 | 3 |

- 档位后缀白名单为 `.2160p`、`.1080p`、`.720p`、`.480p`，白名单不代表每个单元都要制作这些档位。可选 `2160p`、`1080p` 用 VP9（profile 0，8 位 4:2:0）的 WebM，如 `E03.1080p.webm`；`720p`、`480p` 用 H.264（8 位 4:2:0）的 MP4，如 `E03.720p.mp4`；编码或封装与身份不符时不关联。每个文件只有一条视频轨和一条音轨（WebM 为 Opus，MP4 为 AAC），音轨最多两个声道，多于两个声道时不关联：多声道片源统一混缩为立体声，单声道片源保持单声道。网页播放以双声道输出为主，且 iOS Safari 播放 5.1 Opus 无声，因此不保留 5.1。压制与制作侧检查见[导入说明](import-media.md#压制规格)。
- 主档与各档位单独验证、单独按会话授权，只有已验证的原生主档使单元可播并决定单元时长；可选档位不能代替缺失或未验证的主档。档位与主档时长相差超过 1 秒（默认）时不关联也不列出；主档被同名替换（6.8）后，时长不再相符的档位不再列出，同名重传相符的档位并通过扫描后恢复。
- 播放器先列“原画”，再按后缀从高到低列出该单元已验证且与主档时长相符的档位，不按浏览器的解码能力隐藏；只有原画时不显示清晰度选择。成员选过的档位记在本浏览器，之后打开的单元有该档位时沿用；没有记忆或单元没有该档位时默认播放原画。VP9 档位（原画、2160p、1080p）在本设备无法解码时，自动切到该单元最高的 H.264 档并提示，不改动成员的选档记忆；本浏览器同时记住不能解码 VP9，之后打开的单元若默认档位是 VP9，直接改用最高的 H.264 档。成员手动改选 VP9 档位时重新尝试，失败后再次切回。单元没有 H.264 档时提示本设备无法播放该片源，不提供重新连接。其他档位无法播放时按 6.6.2 提示。切换保留播放位置、播放或暂停状态和倍速，各档共用同一组字幕轨。
- 播放页提供上一集、下一集、当前季选集、手动标记已看或未看和加入片单。上一集、下一集和播完提示取同一作品按季号、集号排序后相邻的可播单元，跳过片源暂缺的集。播完后显示下一集提示和可取消的倒计时（默认 10 秒）；倒计时结束或点击立即播放时进入下一集并尝试播放，浏览器阻止自动播放时保留手动播放入口。只有从提示进入的这一次尝试自动播放，刷新或前进后退回到该页不自动播放。没有下一集时不显示无效操作。从片单进入的播放按 6.7.2 继续队列，不在队列结束后回退到剧集自然下一集。
- 播放页工具行下的资料行：剧集为英文原名（仅标题显示中文译名时）、`YYYY-MM-DD 首播` 与片长，日期按 TMDB 单集文本原样显示，缺失时省略该项；电影为英文原名、`YYYY 年` 与片长。首播日期只在播放页显示。
- 切换可播放单元时，读取该成员对目标单元的进度；没有记录则从头播放，不得沿用上一集的起点或把上一集的进度写入新单元。
- v1 不限制每个账号的同时播放数，未来是否增加须另行确认。

#### 6.6.1 授权与撤销边界

- 每次 GET/HEAD/Range 即时鉴权，未授权返回 `401` 且不返回大小、类型等元数据。退出、撤销会话、重置、改密换会话或封禁后，下一个媒体请求即被拒绝。
- 已在传输中的响应不保证立即中断：被封禁或退出的成员最多继续接收当前这一次已建立的传输，任何新的打开、拖动、换集或刷新都会被拒绝；已发出的字节无法收回。
- 防盗链依靠会话 Cookie（`SameSite=Lax`）与逐请求鉴权：其他网站嵌入或把地址转给非成员都无法获取内容。能播放即能被成员保存，访问控制不是 DRM，v1 不另设防下载措施。

#### 6.6.2 媒体请求行为

- 视频与字幕始终经本站授权入口，不跳转到原始存储或返回绕过权限的地址。支持 GET/HEAD 和单个字节范围，拖动无需先下载全文件；未授权不返回元数据。
- 仅提供已验证且版本一致的视频和字幕；历史未验证、已被替换、长度不符或已删除的对象返回脱敏 `404`，不能仅凭长度相同放行。版本核对与内容读取在同一次存储操作中完成，读取时对象已被替换同样返回 `404`。
- 播放页只依据数据库中已验证的片源和字幕给出播放器与字幕选项，打开页面时不访问存储。对象缺失由媒体请求返回 `404`；媒体同步完整检查存储后清除已删除对象的已验证版本，片库最晚在下一个同步周期显示片源暂缺。
- 播放器读不到视频请求的 HTTP 状态，出错后向同一地址再发一次 HEAD，区分登录失效（`401`/`403`）、片源暂时无法播放（`404`）、VP9 无法解码（HEAD 正常而浏览器报格式不支持或解码失败，按 6.6 自动换档）与连接或服务故障。登录失效提供“重新登录”并在登录后回到当前播放页；其他故障提供原地重新连接，回到故障前位置并恢复原来的播放或暂停状态；播放器不自动重试，重连再失败时重新提示。提示以页面顶部的 toast 显示，不受播放器高度和页面滚动位置影响：带“重新登录”或“重新连接”的视频故障提示一直保留且不能手动关闭，恢复、换集或离开页面时收起；其他提示按默认时长自动消失。全屏或网页全屏时出现需要按钮的视频故障会先退出全屏，其他提示同时在播放器内显示。字幕加载返回 `404` 时从选项中移除并切到关闭，其他失败保留选项并提示重新选择字幕，不提供视频重连。
- 视频或字幕请求的存储元数据、文件内容读取在响应开始前抛出异常时返回脱敏 `503`；确定缺失或版本、长度不符仍返回 `404`。
- 首页推荐、续播和选集入口不将缺少已验证版本的记录标为可播放。片库展示依据数据库挂接状态，当前对象可用性在每次媒体请求确认；展示状态不能代替实时校验。
- 完整 GET 为 200，合法单范围为 206，HEAD 无正文；尾部/后缀、无效范围、If-Range、缺失、方法及响应头的验收见第 7 节与[HTTP 契约](plan/playback.md#662-r2-与-http-range-契约)。
- 保持原始字节、正确类型/长度和私密缓存边界；内存、私有存储读取和日志方式见方案。
- **长时验收**：视频与字幕逐请求按登录会话鉴权，没有随播放时长到期的凭证或截止，会话有效期远长于单次观看，长时间播放不另设验收；拖动与字幕切换按常规播放验收覆盖整片范围。涉及媒体传输（包括 R2 读取、Range 处理）、缓冲、解码或长期状态管理的行为变化时，用两小时以上的真实连续播放重新验证拖动和字幕切换，不能用短片段可播代替。其他播放器局部改动按实际影响执行定向回归，覆盖相关操作、失败恢复和数据结果，不因改动播放器代码而一律重跑长播。

### 6.7 观看进度与片单

- 播放页定期上报播放位置（默认 15 秒一次），暂停和离开页面时也上报一次。进度持久保存，按“成员 + 可播放单元”保存，所以换设备也能接着看。
- 播放位置达到总时长的 90% 就标记为已看完（默认值，可调）。成员也可以手动标记。
- “继续观看”显示成员最近看过、还没看完的可播放单元。首页每部作品只保留最近更新的可播、未完成且有进度单元，再按更新时间倒序排列；较新的已完成、不可播或零进度记录不得挤掉较早的有效记录。一部剧没有这样的单元但有看完的集时，推荐最近看完那一集之后第一个未看完的集（已看完的集跳过），按那次看完的时间参与排序；该集片源暂缺时不越过它推荐更后面的集，这部剧暂不出现在继续观看中。首页与作品页采用一致的续播规则，手动标记和按作品去重不得让仍有未完成记录的作品消失。
- 收藏只针对作品。片单是有序列表，条目可以是作品或单集，成员可以设为私有或站内公开。
- 成员可以创建和删除自己的片单，添加、移除或调整条目顺序；桌面提供上移和下移，触屏支持滑动排序，移除入口保留给键盘和读屏用户。
- 片单提供“按顺序播放”入口，正式版须按 6.7.2 的展开规则构建播放队列，不能替换成剧集的自然下一集。
- 片单名称去掉首尾空白后为 1–60 个字符（默认），须包含可见内容，拒绝控制字符及文字方向控制符；合法 emoji 的连接符、变体选择符及正常双向文字保留。每个片单最多 200 个条目（默认）；从“加入片单”菜单新建的片单为私有，在片库新建时可选私有或站内公开。

#### 6.7.1 写入与读取约束

- 上报位置必须是有限非负数，不能超出服务端已知总时长；手动已看/未看与自动上报明确区分，不能把缺省 `completed` 当作手动“未看”。看完阈值读取集中配置。
- 所有进度、收藏及片单写入以当前成员限定 ownership。站内公开片单只返回片单及作品/单集概要，不带所有者的私人进度；私有片单不能通过条目 ID 绕过权限。
- **进度采用 `expectedRevision`（已确认启用）**：请求携带 `expectedRevision`，服务端条件写入并返回新的 `revision`；版本不匹配返回 `409 / REVISION_CONFLICT` 和当前 `revision`。
- 冲突后的客户端行为**已定**：拿到 `409` 的旧上报**直接丢弃，不自动重放**。只有用户继续观看产生新的播放事件时才发下一次上报，客户端**不做无限补报队列**。同时不采用“取位置最大值”，因此**正常回看到更小的位置可以正常保存**。
- **手动“标记未看”已定**：`positionSeconds` 归 `0`、`completed = false`，并让 `revision` 递增。已落库后的旧上报因版本不符被拒绝；此后用户真实观看重新达到 `90%` 阈值即可再次标记完成，**不存在长期的手动覆盖状态**。
- 自动上报不清除“已看完”：已看完的单元回看时照常保存位置，只有手动“未看”才清除完成状态；手动“已看”把位置记为全片时长。手动标记也适用于尚无片源的单元（成员可能在别处看过），自动上报只接受有可播媒体的单元。
- “下一集”按同一作品的季号、集号排序查询；只有实际已导入可播媒体的单元才能返回播放地址。跨季、缺集时如何提示仍由前端按既有产品行为处理，不伪造不存在的片源。

#### 6.7.1.1 片单条目去重

- **同一目标在一个片单内只能有一条**，目标由类型与身份区分。重复添加返回已存在条目、不新增、不改顺序，仍返回成功并刷新列表。
- 作品条目和它下属的单集条目**允许同时存在**，这是两个不同目标；播放队列仍按 6.7.2 在展开后按可播放单元 ID 去重。
- **并发重复添加必须幂等**，最终只留一条，各请求返回同一条目，不产生重复或顺序抖动；约束与写入方案见 community 计划。

#### 6.7.2 “按顺序播放”的队列展开

- 队列按片单条目的存储顺序逐条展开：
  - 电影作品条目对应该电影的可播放单元；
  - 单集条目对应其自身；
  - 剧集作品条目展开为该作品下按季号、集号排序的、已导入且可播的集；片源暂缺的单集或电影条目不进入队列。
- 展开后按可播放单元 ID 去重，同一单元只保留第一次出现的位置，后续重复项丢弃。
- 展开结果中已看完的单元被跳过，不进入播放队列。
- 队列播放时，播放器下方的队列条按展开结果（含已看完的单元）显示当前单元的序号、总数和逐项看完状态，右侧下一项与播完提示的目标相同；之后没有未看完的单元时不显示下一项，并标注“最后一项”。队列条只展示位置，播放仍跳过已看完的单元。
- 未看完的单元从该成员自己的保存进度开始；没有进度记录时从头播放，不沿用队列中上一单元的起点。
- 若全部可播单元均已看完，停留在片单页并提示“已全部看完”，不进入播放页、不自动重播。
- 队列播放时，队列内下一个单元优先于剧集的自然下一集；队列到达末尾后不再使用剧集的自然下一集。
- 队列播完后停止，不继续自然下一集，也不循环回队列开头；停留在当前播放页，显示“片单已播放完”和返回该片单的入口。
- 队列播放时，标题栏上一集/下一集仍按剧集顺序跳转，并保留片单参数；目标单元不在队列内时按普通播放页处理。
- 队列展开后的按单元去重，只作用于播放队列结果；**写入侧**按 6.7.1.1 禁止同一目标重复条目。

### 6.8 资料初始化与媒体导入

2026-10-07 确认资料占位与上传分开：站长用本机项目 CLI 初始化资料，用支持大文件的工具独立上传，服务器定时发现并验证关联；网站不提供上传或内容编辑后台。

- 明确选择 staging/prod，展示目标并校验归属，不默认写 prod。manifest 限定作品和季，从 TMDB 取双语资料及身份；中文缺失回退英文，上游失败不覆盖已有资料。
- 先建全部作品、季、集占位；缺媒体显示“片源暂缺”且不授权，未知时长显示“时长暂缺”，关联后用媒体实际时长。单集首播日期取 TMDB 原值，缺失保存为空；格式不是 `YYYY-MM-DD` 时整次初始化停止、不写入。
- 本机预检各档位的封装、编码、音轨、前置索引和档位间时长，与服务器扫描共用同一套 WebM/MP4 检查，不合规提示先转码；字幕转为安全的 VTT，并按简中、简英、繁中、繁英标明文字与内容（命名约定见[片库计划 SUB1](plan/catalog.md#sub1-字幕四类标记)），纯英文字幕不导入。简繁切换上线后，只提供简体或繁体之一的字幕用 OpenCC 转出另一种（繁体按台湾用词），站长提供的原生版本优先、不被转换结果覆盖。ASS 明确提示样式丢失，不渲染 ASS。
- 默认每 5 分钟扫描，只关联完整且通过格式、时长、完整性及版本校验的对象，不以扩展名当验证；超出验证能力报告失败并保持不可播。
- 重复执行不重复建数据、不重建身份、不丢进度或讨论；未变对象跳过，失败对象后续可重试且不阻塞其他对象。
- 站长用同一固定名称上传不同文件即为替换：扫描对新文件做与首次关联相同的完整验证，通过后改写原记录的校验值、长度、版本、时长和码率，主档同时更新单元时长；记录 ID、播放地址及进度、弹幕、讨论不变。字节相同的重传只更新版本，计为跳过。扫描验证前播放拒绝新版本；发现版本变化即不再沿用旧验证结果，新文件未通过时报告失败并保持不可播（该档位和字幕从选项中移除，主档未验证时单元显示片源暂缺）。被覆盖的旧文件本站不保留。
- 关联失败保留完整对象供重试，不自动删除；缺媒体保持不可播并可补回。
- 主档与可选档位按 6.6 命名，走同一扫描、验证和替换规则；某一可选档位验证失败、编码与档位不符或时长与主档不符，只让该档位不可选，不影响主档和其他档位。替换主档并改变时长时，须同名重传时长相符的档位。
- TMDB key 仅在站长本机；真实路径/凭证不入公开仓库、浏览器或报告。报告导入/替换/跳过/失败数量及对应逻辑身份。

### 6.9 环境、备份与恢复

- staging/prod 完全隔离，可各建全量资料占位；staging 仅少量生成测试媒体，prod 保存正式片源。staging 即预览环境，合并为同一个 Worker 时统一改称 preview（6.9.5）。媒体与字幕原件的冷备由站长在项目之外自行完成，项目不提供冷备功能或配合，也不加第二份云端媒体副本。
- 数据库可选最近 30 天内 Time Travel 恢复点或完整备份恢复；数据库恢复不等于媒体/密钥恢复，平台能力和隔离性须实测。
- 站内提供手动备份、加密下载、WebDAV/S3 保存、结果查看和人工重试，仅 6.9.4 的站长可用。敏感备份离开 Cloudflare 前必须加密。
- 默认保留 30 天，各端最后一份完整可恢复副本可超期保留；缺密钥不算可恢复。清理不触碰媒体或站长本地文件。
- 外部保存位置变更或不再配置时，旧位置副本和记录保留，页面标为“旧位置待处理”，当前位置继续独立清理。只有站长明确确认旧副本已迁移到可恢复的位置或已完成清理，才结束该副本的站内追踪；确认不删除远端文件，站内副本继续按保留规则处理。
- production 正式发布在主要功能完成后按[第六阶段](plan/operations.md)且经站长授权执行；资源准备/dry-run 不等于上线。

#### 6.9.1 配置与密钥保管

- 真实资源、地址、凭证只在本机/平台，每环境/用途密钥独立。备份目标服务端预配，网页不能提交任意 URL 或凭证。
- 手动轮换，不设定期自动轮换；线上、密码管理器、离线副本三处保管。旧密钥保留至全部引用备份被删除或重加密，包括超期保护副本。
- 轮换不能使保留的验证器不可用，认证及备份历史密钥都须保管。绑定、Secret 名称、集中配置与重加密顺序见[配置方案](plan/operations.md#691-绑定secrets-与集中配置)。

#### 6.9.2 定时、完整性与失败

- 仅 WebDAV/S3 配置完整时站长可设置并启用频率和北京时间（Asia/Shanghai），未启用不执行，不固定每日 04:00；仅下载或私有暂存不支持定时。
- 每次执行重检目标，失效拒绝并显示不可执行。导出可能影响查询，手动开始前和设置时间时说明维护影响。
- 完整导出、存储、加密、目标上传及回读校验全部成功才报告该目标成功；回读核对长度和 SHA-256，ETag 不能代替。备份结果与过期清理结果分别记录，清理失败或超时不改变已完整成功的备份结果，可单独人工重试清理。
- 密文验证通过并可靠记录后回收暂存明文 SQL，不等待外部上传成功；密文及必要元数据按既有保留规则保存。明文删除失败须可见并可重试，最后密文副本保护不延长明文保留。加密失败仍保留完整源用于重试，上传失败复用已验证密文。
- 失败保留完整副本与脱敏结果，由站长人工重试，可复用完成的导出；不自动重试调度或主动告警，不把部分成功报告为全部成功。
- 各端保留按 6.9；平台时限、内存、网页中断及定时能力须实测。API、加密/传输与生命周期见[备份方案](plan/operations.md#692-定时备份执行与失败行为)。

#### 6.9.3 恢复与重新开放

- 恢复前暂停目标写入/导入并保留旧库；默认先恢复到隔离目标，完整验证后切换。无法隔离报告站长，不自行覆盖生产库，网页无一键恢复。
- 核对备份认证、元数据、长度/校验、关系、媒体和历史密钥；明文敏感备份不离开 Cloudflare。缺媒体不中止恢复，单独计数并清除该记录的已验证版本，站长从本地按原名补回后由扫描按 6.8 重新验证，补齐前不可播。媒体版本和长度与恢复点相同才沿用其验证结果；不同时（恢复点之后同名替换或重新上传）清除该记录的已验证版本，切换后由扫描按 6.8 重新验证，完成前该片源不可播。
- 重开前撤销旧会话、临时凭证、未用邀请码、二步备用码，以及恢复点带回的邮箱验证凭证（播放随会话撤销一并失效）；密码和设备按恢复点保留，TOTP 保持可用。恢复可能带回后来解绑设备，站长须复核。
- 角色、封禁和设备逐条复核，不明确的账号保持维护状态。邀请只保留已用数占额度，不返还已用码。
- 历史讨论照原样恢复，管理员维护期间人工复核重删；不加软删除、隐藏标记、删除台账或清空正常讨论，不声称历史备份已擦除。
- 导入、校验、重加密和切换顺序见[恢复方案](plan/operations.md#693-手动恢复顺序与完整性)，完整演练前不算完成。

#### 6.9.4 站长专用网页备份

- 站长是本环境 OWNER_EMAIL 完全匹配的正常管理员，已完成注册、邮箱验证且未封禁，不加第三种角色。缺失/无效配置或无匹配账号时拒绝，不回退任意管理员。
- 各页面、状态、创建、重试、设置和下载独立判断；降权、封禁、退出、会话撤销、验证后改邮箱或配置生效后，下次请求即时重判。
- 页面显示环境、列表、状态、可用目标及脱敏失败；其他身份不显示入口且直接请求也拒绝，写入统一校验来源并要求 JSON 请求，页面和下载不可索引/缓存。
- 下载仅本环境已完成并校验的加密文件，不附密钥，不给明文 SQL、对象路径、上游地址或长期凭证；仅下载不要求外部目标。
- WebDAV/S3 按目标显示结果，缺配置不影响其他目标。定时设置只对本环境有效，伪造启用同样拒绝。
- 网页及定时共用完整性、保留、失败和人工重试；实现及平台门槛见[网页备份方案](plan/operations.md#694-站长专用网页备份)和第六阶段。

#### 6.9.5 GitHub 分支构建与发布

常规发布使用 Cloudflare Workers Builds 的 GitHub 集成，由 Cloudflare 获取远程仓库代码并在云端构建、验证和部署，使发布版本可追溯到提交且不依赖本机工作目录或构建产物。

| 环境 | 唯一常规发布分支 | 发布目标 |
| --- | --- | --- |
| 预览（preview） | GitHub `dev` | 与正式环境同一个 Worker 的 `dev` 预览，绑定预览专用的 D1、R2、Secrets 与域名 |
| 正式（production） | GitHub `main` | 该 Worker 的正式版本及正式资源 |

合并完成前，预览环境由现有独立的 staging Worker 及其资源承担，现行文档和代码中的 `staging` 即预览环境；合并的时机、步骤和待确认事项见[运维计划 ENV1](plan/operations.md#env1-预览环境并入同一个-worker)。

- **触发与来源**：启用对应链路后，目标分支的新推送触发本环境构建；预览环境对只改文档或原型的推送不构建，排除规则见[运维计划](plan/operations.md)。本地工作树修改、提交或合入本地 `dev` 不触发。`main` 仅通过经批准的 PR 合并更新，PR 来源分支不限于 `dev`；禁止直接推送或绕过分支保护。在生产发布授权范围内合入 `main` 后自动触发部署；PR 来源分支自身的推送或未合并 PR 不触发 production 部署。只有 `dev` 生成预览，其他分支和 PR 不构建预览。
- **发布门槛**：每次发布前运行项目测试、类型检查和目标环境构建，使用锁文件与明确的工具版本；前置检查失败不得发布新版本，保留当前服务版本。production 部署须遵守 [AGENTS 生产发布授权规则](../AGENTS.md#git-流程)，站长明确确认前不启用或触发生产自动部署。首次 production 发布还须主要功能完成、相关测试与 staging 验收通过；连接仓库不等于发布授权。
- **环境与配置**：正式与预览分别绑定自己的 D1、R2、域名和 Secrets，预览设置单独配置、不继承正式设置；构建配置同样按环境隔离。两个环境的代码与构建步骤相同，差异只来自配置中的绑定与变量（数据库、媒体桶、站点地址、登录信任来源、通行密钥域名、人机验证、发件标识等）。登录与通行密钥只信任本环境的固定地址，不信任整个 `workers.dev` 子域。构建变量/Secrets 与 Worker 运行时变量/Secrets 分开配置，不假定两者自动互通；内部资源标识和服务端凭证不进入公开仓库、客户端产物或构建日志。
- **预览环境限制**：Cloudflare 只对正式版本触发定时任务，预览环境的媒体扫描与定时备份不会自动执行；处理方式待站长确认（运维计划 ENV1）。
- **数据库迁移**：Git 集成不自动完成 D1 迁移。发布前明确迁移与应用发布顺序、现有数据处理和失败恢复方式，版本兼容要求按 [AGENTS 开发期兼容策略](../AGENTS.md#开发期兼容策略)执行，先在 staging 验证；迁移失败不得继续部署新代码。代码回滚不代表数据库回滚，不自动执行破坏性逆向迁移或覆盖生产数据。
- **可追溯与失败**：构建/部署记录应能对应环境、分支、提交 SHA 和 Worker 版本，区分构建、迁移与部署结果；构建成功不等于发布成功，失败不得记为完成，也不得擅自改用本机上传绕过失败。
- **工具与授权边界**：云端流程可以调用项目约定的 CLI，要求是代码来源和执行位置，而非禁止 CLI。本机保留开发、验证及授权资源管理能力，直接部署仅限站长明确授权的例外；推送 `dev`、合并 `main` 的授权须包含其自动发布后果，授权规则见 [AGENTS](../AGENTS.md#git-流程)。具体构建命令、迁移步骤、工具兼容性和实施状态见[运维计划](plan/operations.md)。

### 6.11 页面与跨页面交互

- 视觉方向、基础 token、版式和响应式验收遵循 6.14；本节规定页面内容与跨页面交互。
- 访客首页的第一屏在桌面是星图和标题栏，在小于 768px 的视口是登舰证（欢迎语、登舰证样式的邀请码表单和成员登录入口）；两者下方都接加入三步、成员能力、守则和常见问题。星图属于装饰，不要求位置具备考据准确性。首页的邀请码输入传递到注册页，成员登录提供通行密钥入口和密码登录链接。
- 关于页包括本站介绍、如何加入、成员守则、隐私与数据、找回账号、版权说明和技术说明；宽屏提供本页导航。版权说明保留《星际迷航》版权归 Paramount 所有的声明，并展示站长接收下架请求的公开联系邮箱 `contact@startrekchina.org`（这是站长自己的联系方式，不是 Paramount 官方渠道）。该邮箱只作展示，不引入邮件登录或站内发送系统。
- 成员首页以影院式舞台展示当前作品、单集、简介、海报、进度和继续播放入口；刻度尺展示其他继续观看条目及上次观看时间或“下一集”。点击未选中条目切换舞台，点击已选中条目播放；超宽条目可以横向滑动。新成员无观看记录时展示三个推荐起点，由站长通过配置文件维护，不增加网页管理功能；首版依次为 SNW、TNG、TOS 的第一季第一集，调整随部署生效。配置映射到正式片库的可播放单元，原型 ID 仅作参考。
- 剧集和电影页提供海报网格与按首映年份排列的时间轴两种视图，均可进入同一作品页。作品页保留资料、收藏、加入片单、季切换、逐集观看状态和单集剧照；中文资料缺失时回退英文。
- 页面地址按作品分层，不出现内部 ID：剧集 `/series/<简称>` 显示第一季（季号最小的一季），`/series/<简称>/s<季号>` 显示该季，`/series/<简称>/s<季号>/e<集号>` 播放单集；电影 `/movies/<slug>` 为详情，`/movies/<slug>/watch` 播放。简称取番号小写（tos、tas、tng、ds9、voy、ent、dis、st、ld、pic、pro、snw、sfa），电影 slug 为固定英文短名（如 `wrath-of-khan`、`star-trek-2009`），片库每部作品都有一个。季号、集号写不带前导零的十进制数；未知简称或 slug、不存在的季或集、大写或带前导零的写法返回 404，旧 `/title/…`、`/watch/…` 地址不跳转。切季时地址同步变为 `/s<季号>`，页面停在原位；作品页和播放页的主导航高亮“剧集”或“电影”。片单地址为 `/playlists/<8 位字母数字 ID>`，`?playlist=<ID>` 在剧集和电影播放地址上都按 6.7.2 续接队列。
- 成员搜索支持中文和英文作品名，并可用 `Ctrl+K`、`⌘K` 或 `/` 打开；`D` 切换深浅色。手机底部提供搜索和菜单胶囊、回到顶部按钮。访客菜单不展示受保护入口或作品搜索结果。
- 主题默认跟随系统且不记录；顶栏按钮或 `D` 切换到与系统相反的深浅色时记在本机，切回与系统一致或系统深浅色变化时清除记录、重新跟随系统。导航、页脚和页面内容在不同宽度下保持对齐。手机的固定导航、底部安全区、顶栏和播放器控件不得遮挡关键操作。
- 保留原型中账号页的宽屏分节导航、季选择和长列表的滚动提示、复制按钮、异步操作反馈及 404 页面。页面级操作的结果与失败用 toast 提示，不在页面中插入会挤动内容的提示；表单和对话框内的校验与失败留在该表单内。按钮、弹层、滑动条目和表单需要保留键盘和读屏可用性；文本输入时字母快捷键不触发站点操作。系统开启减少动态效果时，跳过平滑滚动、淡入和高亮动画。
- 原型中的数据刷新即重置、签发 token 文案和模拟加载不能作为正式行为；持久化、凭证校验、加载失败和重试应由正式前后端共同完成。

### 6.12 播放页讨论

#### 6.12.1 位置与对话

- 每个可播放单元有独立讨论区。单集放在选集列表下方，电影放在简介下方，标题分别为“本集讨论”和“本片讨论”，显示讨论总数；无内容时显示空状态。
- 1024px 及以上采用双栏：左栏为发评论输入框和评论列表，右栏为当前评论、回复及固定在对话底部的回复框。默认选择第一页第一条评论，点击评论空白处或回复数量可以切换对话，点击正文链接或选择文字不触发切换。
- 右栏按原型吸顶并内部滚动，标题和回复框保持可见；小于 1024px 时改为单栏，点击回复数量在评论下方展开或收起对话。
- 回复按时间正序排列。回复某位成员时显示“回复 @用户名”，可点关闭按钮取消；空回复框按 `Esc` 返回回复评论作者。点回复时聚焦输入框，并滚动到不被顶栏和底部导航遮挡的位置。
- 显示作者、当前成员和管理员等原型标签，长正文可以展开或收起。评论时间保留原型的等宽英文格式：7 天内用相对时间，更早用日期，跨年加年份；悬停显示完整时间。

#### 6.12.2 输入、发送和草稿

- 评论和回复正文上限默认 1000 字，提供工具栏、表情、Markdown 速查、预览和字数反馈。Markdown 支持粗体、斜体、删除线、代码、引用、列表、链接和分隔线，回车换行；不支持图片、表格和 HTML。
- 站外链接新窗口打开并带 `nofollow ugc`，同时防止新页面控制原窗口；`//host` 视为站外，`javascript:` 等危险协议不生成可点击链接。限制不能仅依赖前端编辑器，服务端须验证正文及长度，渲染须避免注入脚本。
- 发送按钮和 `Ctrl+Enter` / `⌘Enter` 使用相同行为。发送期间显示状态，锁定输入、工具栏、表情和预览以防重复提交；状态通过 `role=status` 向读屏播报。
- 发新评论后保持当前排序和正在看的对话，把新评论置顶并提示其位置；新回复展开到末尾并滚动到可见位置。系统启用减少动态效果时不闪烁或平滑滚动。
- 各对话的未发送草稿独立保存，切换对话或跨越宽窄屏断点不丢失。发送途中切换对话时，回复仍发送到原目标，返回时保持其发送状态；只有发送成功才清空对应草稿，失败时保留内容并允许重试。跨设备或刷新后的草稿同步不由本条要求。

#### 6.12.3 赞踩、排序与分页

- 评论和回复支持赞或踩，再点同一反馈取消，切换反馈替换原反馈。赞显示数量，踩不显示数量、仅参与智能排序；服务端保证一名成员对同一对象最多一个当前反馈。
- 评论提供智能、最新、最早三档排序；智能排序沿用原型按赞踩置信度与讨论参与度计算的规则，以原型为算法参考，不引入作品评分功能。选定排序时形成稳定列表，赞踩不会立即打乱当前阅读顺序。
- 评论默认每页 10 条，回复默认每批 10 条。评论和回复关联、数量、作者、时间及赞踩结果持久化保存；刷新或换设备后仍可读取。
- 管理员删除评论与回复已纳入 v1，规则见 6.12.4。成员自助编辑或删除、举报、其他审核与恢复工具、剧透遮罩和评论时间码跳转仍在范围外，不因删评纳入而自动加入。

#### 6.12.4 管理员删除评论与回复

- v1 只提供管理员删除评论和回复的入口，不提供成员自助编辑或删除、举报，以及审核/恢复后台。
- 删除顶层评论时，在同一次原子提交中从当前业务数据库移除该评论、其全部回复，以及评论和这些回复的赞踩记录。正文和记录一起删除，不保留软删除标记、删除占位或正文归档。
- 删除单条回复时移除该回复及其赞踩记录，不删除顶层评论或其余回复。回复仍是同一对话中的平铺列表，不另建嵌套回复树。
- 被删内容不再出现在列表、对话或直接读取接口中，也不计入讨论数量、回复数量、智能排序或分页。访问已删除目标，以及向其发送回复或赞踩，返回脱敏 `404`。
- 删除成功后，当前页面移除对应评论或回复；若当前选中的对话已被整段删除，清除其展示和回复入口，按剩余内容更新计数及分页，不留下删除占位。
- 删除与新增回复、赞踩并发时，不得留下孤立回复或反馈：删除前已经提交的关联记录一并移除，删除后提交的新回复或赞踩因目标不存在而失败。删除批次失败时不得留下部分删除的对话，也不得报告成功。
- 封禁成员默认保留其已有讨论记录，不因封禁自动删除评论或回复。
- 服务端按 6.5 的权限与归属校验执行删除，并沿用统一的业务写入来源与 JSON 校验；删除接口不能绕过认证、管理员权限或可播放单元归属检查。
- 上述删除范围是当前业务数据库和站点读取。删除前的备份及 D1 Time Travel 恢复点**仍可能含有旧数据**，不能把业务记录删除宣称为历史备份已被擦除。**恢复点中的历史讨论照原样恢复**（6.9.3），这类情况由管理员在维护期间**人工 review 并重新手动删除**；不引入隐藏标记、软删除或删除 ID 台账，也不清空正常讨论。

### 6.14 视觉方向与界面风格

整体是克制的“私人档案馆／线稿图纸”，以资料秩序服务观看，不做全站彩色舰桥面板。沿用当前原型已成熟的视觉语言；chanhdai.com 是此前的参考来源，不要求跟随该网站未来改动。正式工程按 6.15 审查并迁移已有前端实现，不全面重写页面；间距、色彩、圆角和阴影沿用原型现有 token，不另起刻度，也不把已知遮挡或触控缺陷固化为设计。

| 基础项 | 约束 |
| --- | --- |
| 站名与标题 | 界面、验证器与通行密钥显示的站名统一为“星际舰队档案馆”；浏览器标题为“页面名 · 星际舰队档案馆”，首页与出错页只显示站名；系统邮件标题以“【星际舰队档案馆】”开头 |
| 中性色与状态 | zinc 黑白灰为基底；页面、文字、表面、弱化信息使用 `background`、`foreground`、`card`、`surface`、`muted` 等现有 token；边界和焦点用 `border`、`line`、`input`、`ring`，状态沿用现有语义色 |
| 内容列 | 宽列 72rem（1152px），窄列 48rem（768px）；顶栏、页面和页脚同宽，切换共享 `--content-width` 的 320ms 过渡；手机两档都占满可用宽度 |
| 字体 | Noto Sans SC：正文 400，标题、导航和标签 500；Geist Mono 用于集号、时长、年份、邀请码等辅助信息，中文回退到 Noto Sans SC；大标题字距 `-0.0125em` |
| 控件与标签 | 按钮、输入框、菜单项 8px 圆角；分段选择是带边框、以 1px 竖线分格的方框，选中项灰底；季格贴着横线；进度条直角，小状态 Tag 为胶囊 |
| 海报 | 2:3 比例，圆角取宽度的 7%，最小 4px、最大 12px；大小海报及其遮罩统一使用 `rounded-poster` 规则，不在单页另设圆角 |

**版式与视觉层级**

- 居中内容列保留左右边框；1px hairline 横线可贯穿屏幕，斜纹分隔带组织章节，页脚采用分格“图纸标题栏”。宽列服务首页、片库浏览、作品、播放和片单；窄列服务登录、账号、邀请、管理和 404，文字与表单不为填满空间而拉宽。
- 成员页面（登录类页面除外）的页脚图签依次列出维护者、构建提交（7 位，链接到公开仓库的该提交）、边缘节点、请求 ID、部署平台、源代码、许可证、数据库、主要依赖版本（读自 `package.json`）、字体、资料来源与版权说明（含 TMDB API 声明），不显示片库统计；宽屏 4 列、手机 2 列。访客页面和登录类页面只保留底栏。构建提交在 staging 为云端构建的源提交，本地为当前检出的 HEAD。边缘节点是处理请求的 Cloudflare 机房代码，平台未提供时显示“—”；请求 ID 是 Cloudflare 为该请求分配的 Ray ID（取自请求头 `cf-ray`），用于在 Cloudflare 的请求记录中检索，平台未提供时显示“—”。两者取自最近一次加载站点框架数据的请求：整页载入或刷新、提交操作后的自动刷新、改变查询参数的跳转（片库只切换视图或排序除外）会更新，普通站内切页不更新、也不为此多发请求；整页载入或刷新得到的 404、403、500 出错页显示出错那次请求的值，站内跳转进入的出错页同普通切页。图签不显示 D1/R2 名称、资源 ID 或账号 ID。
- 列表页用小标签与大标题建立层级；作品和播放页沿用返回、前后切换与标题的资料页结构。正文、辅助信息、状态和主操作清楚分级；细线是装饰，不能替代控件边界或焦点提示。
- 海报及影院背景光承担主要彩色信息。片库海报在桌面精细指针下默认灰度，悬停或键盘焦点时恢复彩色；触屏保持彩色，不依赖悬停才能辨认或操作。LCARS 彩色与 Antonio 窄体标注仅限访客星图内部，沿用星图已有配色，不扩散到全站控件。

**核心页面构图**

- 成员首页确定为影院式 hero：深色全宽舞台、上方透明顶栏、当前海报模糊成背景光；海报置于四角加亮的线框内，配作品、单集、简介、直角进度与播放入口。手机缩小海报并与标题并排，不隐藏海报。继续观看以列内刻度尺呈现，每 12px 一短刻度，段首长刻度、序号与集号形成秩序；当前项更亮，溢出可横滑并有渐隐提示，单条记录也保留整体结构。
- 访客桌面是一张仿剧集 Alpha/Beta 象限星图的图纸：字母与数字编号的正方扇区网格、按格填色的势力疆域、象限标签、联邦名称下的 UFP 徽章（Wikimedia Commons 的公有领域矢量重绘，设计属 Paramount）和锁定的 Sol，下接薄标题栏与文字分格面板；手机改为登舰证样式的邀请码表单，下接同样的面板，避免压缩不可读的图示。桌面星图固定 9:5、扇区保持正方，矮屏上标题栏可落到首屏以下；功能与权限仍按 6.11，不以装饰泄露片库。
- 海报网格保留细线行列，手机起 2 列，随空间扩展到 3／4／5／6 列；首映年份时间轴桌面横向、手机纵向，沿用等宽年份与线轨。作品页以海报、资料、季格和选集行组织信息；剧照手机 80×45、`sm` 起 112×63，缺图仍保留同尺寸中性占位，观看状态和操作不被挤掉。
- 播放器占满列宽，以 16:9 为默认高度并随视口高度封顶，确保正常首屏可见控制条；封顶时视频在播放器内按原比例居中显示，不在播放器外另留空白。短屏、手机横屏或浏览器工具栏变化时控制条仍须可达。播放器、选集和讨论延续站点字体、分隔与信息层级。

**响应式与状态验收**

- 手机搜索／菜单浮层与主 CTA 易发现、触控命中可靠；安全区、固定顶栏、底部导航、渐隐层和软键盘不得遮挡操作或输入。不设仅键盘走通全流程的专项设计或验收门槛，保留已有快捷键和原生基本能力；电视遥控器能走通主流程，焦点可见、可滚入视野，不仅靠颜色区分状态。
- 浅色／深色保持同一层级，弱化文字、边界与状态可见可读；加载、空数据、错误和成功反馈使用一致样式，缺图和等待不造成布局跳动，失败有明确说明与可用后续操作。启用 reduced-motion 时豁免列宽过渡，并跳过淡入、平滑滚动和高亮动画。
- 正式版验收桌面与 375px 手机的注册、浏览、播放等主流程，保留已有 1440×1000 和 360×800 基线，并用真实手机验证键盘、触控与播放。此前布局评估不代替正式数据和设备验收；业务待定项仍按 6.13。

### 6.17 弹幕

弹幕的显示、发送框和设置面板直接采用 ArtPlayer 官方弹幕插件（开发者确认），版本与接入见[社区计划](plan/community.md#t54-弹幕)。

- **范围与权限**：每个可播放单元有独立弹幕，按视频时间显示在画面上。只有正常成员能读取和发送；访客、未完成注册或邮箱验证、被封禁的账号都不能读取或发送。
- **内容与样式**：纯文本，去掉首尾空白后 1–50 字（默认，与评论相同按 Unicode 字符计数），不能换行。拒绝控制字符、Unicode 行/段分隔符，以及仅含空白或默认不可见字符的正文；合法 emoji 连接符保留。位置为滚动、顶部、底部三种；颜色只能从白、黄、红、蓝、绿、紫 6 个预设色中选。服务端校验长度、位置和颜色白名单，不接受任意颜色或 HTML，页面按纯文本渲染。弹幕与字幕都使用站点正文字体，各设备显示一致。
- **发送**：弹幕记录发送时的视频时间（秒，保留一位小数），成功后立即出现在本人画面。同一成员两次发送至少间隔 5 秒（换集、刷新也不重置），滚动 60 分钟内最多 60 条（默认，按发送次数计，被删除的弹幕不退还次数）；超出或校验失败时提示原因，不显示该弹幕。
- **读取**：打开播放页时一次读取该单元的弹幕，超过 3000 条（默认）时只取最新的 3000 条。不实时推送其他成员新发或被删除的弹幕，重新打开或刷新后更新。读取失败时本页不显示弹幕、播放照常，提示一次“弹幕加载失败，刷新页面可重试。”，不自动重试（开发者确认）。
- **发送者**：成员读取的弹幕不含发送者或其他可识别信息，接口也不返回。管理员在播放页的“弹幕管理”中按视频时间查看本单元弹幕的内容、发送者和发送时间，每页 50 条（默认）。
- **管理员删除**：确认后直接删除，不留占位、不能恢复；被删弹幕不再出现在任何读取结果中，已打开播放页的成员在刷新前仍可能看到。v1 没有成员自助删除、举报或审核后台；封禁成员不自动删除其弹幕。删除前的备份及恢复点仍含旧弹幕，恢复时照原样恢复并由管理员人工重删，与 6.12.4 相同。
- **本机设置**：弹幕开关、不透明度、速度、字号、显示区域、显示类型、防重叠、同步倍速，以及发送位置和颜色，只保存在本浏览器，不同步到服务器或其他设备。
- **屏蔽词**：每台设备最多 20 个、每个 1–20 字（默认），不区分大小写、按包含匹配；重复的词不再添加。添加或移除后立即生效，画面上已有的弹幕也按新规则重新显示。屏蔽词只保存在本浏览器，不发送到服务器。
- **布局**：播放器宽度放不下控制栏里的发送框时，发送框移到播放器下方；进入全屏或网页全屏时回到控制栏。弹幕不设键盘快捷键，`D` 保留给 6.11 的深浅色切换。

## 7. 验收条件

- 只测试从外部能观察到的行为：请求发进去，看返回的结果和数据库、存储里的变化。不测内部函数的调用方式和实现细节。
- 验收覆盖 HTTP、导入、发信和浏览器流程，观察请求/响应和持久化结果。原型模拟身份/内存数据通过不代表正式能力通过；测试工具及状态只在模块计划和报告维护。
- 测试边界一：HTTP 接口，覆盖以下外部可观察场景：
  - 注册：原生 username 3–30 位 `[A-Za-z0-9_.]`，大小写冲突、点号可用/连字符拒绝；密码 7/129 位拒绝，空白/中文/emoji 可用，NFKC 行为与长度语义一致。邮箱必填且唯一。并发邀请码仅一个完成成员，预留过期/库部分创建/冲突/业务提交失败可重试且不烧码，未完成记录无权限；无注册会话或备用码。
  - 邮箱验证：原生签名、1 小时有效、GET 完成、普通注册验证幂等重复、重发旧链接可并存；过期/签名错拒绝，注册验证后不自动登录。待验证/注册未完成账号无成员访问。发信失败保留完成注册，计数和结果不泄露凭证。
  - 登录：用户名密码、通行密钥、TOTP/备用码第二因素；密码阶段未授予成员会话，拒绝 trustDevice 与未纳入 v1 的 OTP/邮箱密码/公开 sign-up 绕过路径。通行密钥验证 origin/RP/用途/签名/UV/计数器；锁定版本 request UV 不代替服务端钩子。TOTP 按原生挑战/锁定规则验收，记录不同挑战复用同一码的边界，不假称全局时间步防重放。
  - 会话与改密：30 天滚动到期、每日刷新阈值，页面与 API 读取均可能续期且 Cookie 同步，持续使用可超过旧绝对上限；过期不能续回。Cookie 属性、禁用缓存、即时撤销/封禁有效。普通改密删除旧会话并建立全新当前会话，其他会话失效；注入各写入失败验证实际状态及重试。
  - 密码找回与备用码：邮箱重置 1 小时、POST 一次消费、GET 不消费、成功不自动登录/撤销全部旧会话/保留 TOTP、通行密钥和未用备用码；多个有效链接可并存，已消费不可重用。备用码需正确密码，只完成二步，消费一枚不清设备、重生成旧组失效；旧恢复码重设与管理员重置接口不存在。封禁不能借找回解除。
  - 认证失败：注入重置消费后密码写入失败、密码已改但会话删除失败、二步消费后会话创建失败等情况；不得宣称自动回滚，链接/备用码已消费则走重新申请或剩余认证方式，撤销失败须重试清理。
  - 修改邮箱：本人库敏感会话申请，新邮箱验证前旧邮箱/找回可用；同一成员会话内确认后替换，其他账号或无会话拒绝，失败不提前改旧邮箱。当前邮箱唯一，待邮箱不预占；多申请第一个完成后其余绑定旧邮箱的链接失效。旧密码重置链接未必失效，按 1 小时边界验收。匿名改邮箱入口不存在。
  - 封禁：只封本人/连带普通后代、遇其他管理员停止；注册业务完成与封禁竞态重新检查，不漏封/孤立。管理员 ban/unban/quota/role 必须已绑定 TOTP且会话创建不超过 5 分钟，新鲜会话可连续操作，缺绑定或过期拒绝；旧会话单独验证 TOTP 不刷新新鲜度。删评只需管理员会话及业务写入来源与 JSON 校验。
  - 解除封禁：只恢复单个被封禁成员，旧会话/已作废邀请码不恢复、额度按业务公式计算、无额外发信；缺管理员绑定或新鲜会话拒绝。

  - 观看进度和片单：增删改查、跨成员隔离、私有与站内公开权限、条目排序，以及“已看完”的判定逻辑；切集不得串用起点，手动标记后继续观看不得漏掉仍未完成的作品。按 6.7.1 验证 `expectedRevision`：版本不符返回 409 且旧上报被丢弃、不自动重放，只有继续观看产生的新事件才再上报；回看到更小的位置能正常保存；手动“未看”后位置归零、`completed = false`、版本递增，此后重新观看达到 90% 仍能自动完成。按 6.7.1.1 验证同一目标重复添加返回已有条目、不新增也不改顺序，并发重复添加幂等，作品与其单集条目可同时存在。另按 6.7.2 验证队列展开（作品与单集混合、去重保留首次出现、跳过已看、无进度从头）、全部已看时的“已全部看完”提示，以及队列播完停在当前播放页并显示“片单已播放完”和返回入口。
  - 评论、回复和赞踩：正文与长度校验、所属可播放单元和对话正确、持久化、每成员单一赞踩及取消、数量、分页和稳定排序；访客与被封禁成员不能读取受保护讨论或发送内容，危险 Markdown 和链接不能造成脚本执行。管理员删除顶层评论后，该评论、全部回复和相关赞踩在数据库及读取结果中均不存在；删除单条回复只移除该回复和其赞踩，不影响其余讨论。被删内容不留占位、不计入数量、排序或分页，直接读取、回复或赞踩已删目标返回 `404`，普通成员调用删除被拒绝。并发写入和删除失败不得留下孤立记录或部分删除。

## 8. 范围外（后续版本）

- HLS 切片和按网速自动切换清晰度。计划用远程服务器自动处理上传后的视频；v1 只提供 6.6 的多档文件手动切换。
- ASS 字幕渲染（JASSUB）。前期评估结论：
  - 内嵌字体需要做子集化；
  - iPhone 上全屏播放时字幕叠加层不可见，需要用 VTT 兜底；
  - 低端设备上复杂特效可能掉帧。
- 作品评分。播放页评论、回复、赞踩和弹幕已进入 v1，赞踩不等于作品评分。
- 弹幕的实时推送、成员自助删除或举报、自定义颜色及高级弹幕；弹幕按 6.17 进入 v1。
- 评论的剧透遮罩、时间码跳转，以及成员自助编辑或删除、举报和完整的审核/恢复工具；管理员删除评论与回复已进入 v1，采用 6.12.4 的直接删除规则。如站长确认上述其余能力是上线前必需配套，再补入本文。
- 限制每个账号的同时播放数。
- OAuth 登录，后续按 Better Auth 对应插件接入，v1 不提前实现。邮箱验证、邮件发信和成员自助修改注册邮箱已按 6.0 纳入 v1，不再属于范围外。
- 收录新内容，以及网页端的内容管理后台。
- 非选集列表用途的剧照，以及视频时间轴的预览缩略图。播放页选集列表不增加剧照；作品浏览页的首映年份时间轴已进入 v1。
- 中英双语界面。
- 观看热力图；此前原型探索已决定不做。

- 密码恢复码、管理员签发/代发账号重置链接、匿名改邮箱、受信任设备免二步、邮件/短信 OTP 与魔法链接登录、成员改用户名或删除账号；旧原型相关演示不纳入正式 v1。
