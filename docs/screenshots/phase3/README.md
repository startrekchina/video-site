## 对照结果与必要适配

- 账号页沿用原型的标题、资料行、三个分区、图标行、分隔条及桌面侧栏；操作使用原型对话框。邀请页恢复双栏统计、居中生成按钮、邀请码状态行和空态；管理页恢复三栏统计、成员表格、行菜单及成员／邀请码／邀请关系三个标签页。登录与注册恢复窄列、居中卡片、表单间距和简洁页脚。
- 保留现有字体、色彩、线条、圆角和响应式 token。状态按钮用 CSS 和现有图标实现加载／完成反馈，没有新增动画依赖。对话框限制最大高度并支持内部滚动；手机表格在自身容器中横向滚动，页面没有横向溢出。
- 按当前需求保留注册邮箱、邮箱验证及本人修改邮箱；用户名 3–30 位、密码 8–128 位、邀请码默认 30 天，以需求文档为准。注册第一步只进入资料填写，邀请码有效性由最终服务端提交确认，界面不伪装为已通过验证。
- 原型的假 Turnstile 替换为官方组件；小于 300 px 的容器使用 compact 尺寸并预留高度，其余使用 normal。本机仅使用官方测试配置；测试 token 不证明实际站点的防机器人效果。
- 账号资料、密码更新时间、通行密钥、会话和备用码余量来自本人数据，不沿用假设备、假地理位置或模拟身份。TOTP 采用真实手动密钥设置，原型的假二维码未迁移；新备用码仍使用原型网格、复制、下载和保存确认。既有邀请码读取不返回原文；仅本次创建结果可以复制原文或链接。
- 管理操作遵循已确认的 TOTP 与新鲜会话要求，禁用自封禁／自降权；不保留旧管理员重置密码入口。列表不返回其他成员邮箱、凭证、邀请码摘要或会话 token。

## staging 原生 scrypt 小样本

2026-10-07 北京时间 00:10:32–00:10:33，在本次已有 staging 官方 API 例外内，通过临时受随机请求凭证与 10 分钟期限保护的入口调用当前构建实际使用的原生 scrypt；参数为 N=16384、r=16、p=1、dkLen=64，只使用虚构密码。8 次 HTTP 检查覆盖哈希、正确密码校验、错误密码拒绝与最多 2 路并发，全部 HTTP 200 且结果符合预期，客户端耗时 120–981 ms。

对应 UTC 窄时间窗 `2026-10-06T16:10:32.095Z`–`2026-10-06T16:10:33.800Z` 的平台指标返回 6 条成功样本：

| 指标 | 结果 |
| --- | --- |
| CPU P50 / P99 | 77.246 ms / 83.573 ms（平台微秒值换算） |
| 墙钟 P99 | 84.320 ms |
| V8 isolate memory P50 / P99 | 19,952,184 / 19,952,700 bytes（P99 约 19.0 MiB） |
| 执行错误 | 0 |

HTTP 检查为 8 次，平台指标为 6 条样本，不宣称逐请求 CPU 都已采集。Worker 内部时钟读数均为 0，不能作为零耗时证据；客户端耗时含网络，平台 V8 内存指标也不等于进程总峰值。本结果只证明本次小样本和最多 2 路并发，不代表完整容量。

已核对 Workers Paid；当前未显式设置 `cpu_ms`，按[官方 Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)的 HTTP 默认 CPU 上限 30 秒、isolate 内存上限 128 MB 判读。初次传播检查出现非 JSON 响应后已恢复正常入口；增加就绪检查后取得上述成功结果。最终正常主模块和服务端 chunk 校验和一致、诊断路径返回 404、临时凭证文件删除，正式源代码及绑定没有改动。正常版本的公开页面、权限门禁、UV、安全头和 4 个客户端 JS 资源随后重新通过 HTTPS 冒烟，query 脱敏及 invocation/traces 关闭配置保持。
