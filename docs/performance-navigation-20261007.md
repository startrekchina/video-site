# 页面导航性能修复（2026-10-07）

站长报告 staging 多个页面点击后需要等待。使用指定的 Kimi 浏览器会话复现并修复；测试站保留真实目录与成员门禁，测试播放只使用自生成视频。

## 原因与修复

- Better Auth 1.7.7 每次新建认证实例都执行数据库结构检查。临时 HTML 响应计时显示鉴权约 380–480 ms；只关闭运行环境的重复 schema 检查后降到约 180–215 ms。结构继续通过版本化迁移和测试环境的原生检查验证，原生会话读取、滚动续期与主库成员校验仍逐请求执行。参见[库的 schema 检查说明](https://www.better-auth.com/docs/concepts/database#runtime-schema-validation)。
- 片库原先串行读取作品、全部季、全部单集，再单独统计分类；片库查询约 400 ms、额外统计约 80 ms。现在列表在一次 D1 batch 中返回作品卡片、本人已看统计及分类总数；详情和播放页限定到当前作品。批量调用依据见 [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。
- 剧集列表原先携带约 51.3 万字符的解压后文本，包含整库单集标题/简介；现在卡片直接携带完整季数、集数与本人已看数，不返回单集数组。首页的作品卡片也使用同一契约。
- 首页第一轮只精简了浏览器响应，服务端仍读取整库单集，预热后测到 816 ms。最终仅读取继续观看、配置推荐所需的剧集单元以及电影时长行；季数、集数和已看总数保持完整，既有推荐/续播排序保持。
- 海报墙/时间轴与年份排序只改变已有数据的展示。仅这些 URL 参数变化时由 root 和片库路由跳过 loader；搜索、跨页面、表单/action、手动刷新仍按框架规则请求服务端。

受保护响应继续使用 `private, no-store`，每个实际 loader 请求独立检查权限。未增加鉴权结果缓存、预取数据缓存或依赖；正式工程继续沿用原型布局。

## 测量方法与结果

复用本任务 Chrome staging 标签，1440×1000、正常成员会话。依次真实点击关于/剧集/电影链接，使用 `performance.now()` 记录点击到 URL 提交，Resource Timing 记录 `.data` 请求。修复前重复两轮，预热后仍复现；修复后重新加载客户端再测。下表来自最后部署后的同一完成点，均为本机网络样本。

| 操作 | 修复前 | 最终版本 |
| --- | --- | --- |
| 关于导航 | 558 ms | 366 ms |
| 剧集导航 | 1303 ms | 407 ms |
| 电影导航 | 928 ms | 368 ms |
| 视图/排序 | 每次 637–2477 ms，1 个 `.data` 请求 | 12–40 ms，0 个 `.data` 请求 |
| 剧集 `.data` 传输体 | 约 222 KB | 约 10.7 KB |
| 剧集 `.data` 解压后文本 | 513232 字符 | 13878 字符 |
| 首页 `.data`（第一轮修复后仍有残余查询） | 816 ms，25435 字符 | 404 ms，25435 字符 |

最后部署后，独立采样到关于/剧集/电影 `h1` 更新分别为 409/388/414 ms，无长任务。双 `requestAnimationFrame` 曾把关于样本拉长到约 2 秒；分段采样显示 DOM 在 409 ms 已更新，其后帧等待 1464 ms。相同标签的空闲电影页也测到 943/1000 ms 的帧间隔，发生展示动画后的间隔为 17–33 ms，因此单独帧等待另列为浏览器调度的测量边界。未把这种变化计入请求优化收益或承诺所有绘制始终低于 0.5 秒。完整真实手机验收仍按 PLAN T4.4 待反馈。

## 验证与复现

`pnpm test -- test/catalog.test.ts` 可复核紧凑 HTTP payload、统计和当前作品范围。新增 payload 断言在修复前因列表包含 `A Fictional First Episode` 失败，修复后通过；详情仍保留此单集资料。真实 D1 检查覆盖中文/英文及字面搜索、本人收藏/已看隔离、电影时长、完整计数、推荐起点与继续观看。

最终 178 项应用测试通过；首页最后调整后另复跑全部 6 项片库测试通过。类型检查、staging 构建及 cf dry-run 通过。安全回归使用关闭重复 schema 检查的实际认证配置，验证 Cookie 滚动更新、立即拒绝封禁/撤销，以及解封不会恢复旧会话。

Kimi 实际验证英文筛选只返回 TNG、筛选后的视图/排序保持条件且无数据请求、TNG 第二季 22 个条目与相邻作品入口；375 px 本机虚构成员片库无横向溢出，搜索/菜单可用。staging 自生成 7260 秒视频 `readyState=4`、无解码错误，检查后暂停。匿名独立请求 `/series.data?_routes=series` 和 `/movies.data?_routes=movies` 返回 202 登录重定向数据，无片库泄漏；非法媒体凭证返回 401。公开页面与这些响应的私密缓存、noindex、no-referrer、nosniff 均通过。

临时 `DEBUG-nav-802b`/`Server-Timing` 诊断代码已移除；线上公开响应未保留诊断头。63 个客户端文本产物及改动文件的已知敏感值检查通过，官方公开 Turnstile 测试值按样例识别。按本次 T4 官方 API 例外更新 staging，最终启动 44 ms；D1/R2/既有 Secrets、五分钟 Cron 和私密日志配置保留。没有新建云端资源、重新导入资料或修改 production/Git 远端。

部署涉及 loader 数据契约更新，已有测试站标签页应刷新一次。开发服务继续保留在 `0.0.0.0:6120`。此前[原型布局修复证据](screenshots/design-fixes-20261007/README.md)和[自然长时播放基线](screenshots/phase4/README.md)仍保留；本轮性能检查未重新跑两小时播放。
